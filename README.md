# CoDraw

**CoDraw** — веб-редактор диаграмм, аналог [draw.io](https://www.drawio.com), созданный для совместной работы.

Несколько человек одновременно редактируют одну диаграмму и в реальном времени видят изменения,
курсоры и выделения друг друга. Совместная работа здесь — основной сценарий, а не надстройка
над однопользовательским редактором.

## Возможности (план)

- **Редактор диаграмм** — фигуры, коннекторы, текст, группы, страницы, стили, сетка и привязка.
- **Совместное редактирование в реальном времени** — без блокировок и конфликтов (CRDT).
- **Присутствие** — курсоры, выделения и аватары участников, следование за участником.
- **Undo/redo для каждого участника** — отменяются только свои действия, а не чужие.
- **Офлайн-режим** — правки сохраняются локально и синхронизируются при восстановлении связи.
- **Доступ и роли** — приглашения и ссылки с ролями: владелец, редактор, комментатор, читатель.
- **Комментарии** к элементам диаграммы.
- **История версий** — просмотр и откат к предыдущим состояниям.
- **Импорт/экспорт** — `.drawio`, PNG, SVG, PDF.

## Запуск

Нужны JDK 25, Node.js 22.12+, pnpm 10 (`corepack enable`) и Docker.

```bash
pnpm install
docker compose up -d postgres

# каждый сервис — в отдельном терминале
cd backend && ./gradlew bootRun    # API: http://localhost:8080
pnpm dev:collab                    # синхронизация: ws://localhost:1234
pnpm dev:frontend                  # приложение: http://localhost:5173
```

Подробная инструкция — проверки на каждом шаге, порты, запуск собранной версии, тесты и частые
проблемы — в [docs/running.md](docs/running.md).

Развёртывание на сервере — Docker-образы, nginx, TLS-прокси, обновление и резервные копии — в
[docs/deploy.md](docs/deploy.md).

## Вход через GitHub и Google

В CoDraw входят через GitHub или Google. В списке каждый видит только свои доски, а чужую доску открывает
по ссылке на неё — с правами, которые владелец дал ссылке (см. «Доступ по ссылке»). Для входа нужны
OAuth-приложения у провайдеров: создайте их один раз и передайте backend их client id и secret.
Без них backend запускается, но работает только режим гостя.

**Без входа.** На странице входа можно нажать «Продолжить без входа»: CoDraw создаст гостя «Гость N»,
который работает с досками так же, как вошедший пользователь. Гостевой сеанс хранится в cookie браузера 30 дней
с последнего обращения. Если гость затем войдёт через GitHub или Google, его доски перейдут к аккаунту;
если очистит cookie, не войдя, доски станут ему недоступны. Когда сеанс гостя истёк, вернуться он уже не может:
его доски удаляются, если с ними 30 дней никто не работал (не менял и не открывал по ссылке), а затем удаляется
и сам гость.

Адрес возврата (callback URL) — адрес приложения, к которому добавлен путь
`/api/login/oauth2/code/<провайдер>`. Для локальной разработки это
`http://localhost:5173/api/login/oauth2/code/github` и `http://localhost:5173/api/login/oauth2/code/google`,
в продакшене — `https://<домен>/api/login/oauth2/code/github` и `…/google`. Порт 5173 — порт фронтенда:
вход идёт через него, как и остальные запросы к API.

### GitHub

1. Откройте [Settings → Developer settings → OAuth Apps](https://github.com/settings/developers)
   и нажмите **New OAuth App**.
2. **Application name** — любое, например `CoDraw local`; **Homepage URL** — `http://localhost:5173`;
   **Authorization callback URL** — `http://localhost:5173/api/login/oauth2/code/github`.
3. Нажмите **Register application**, скопируйте **Client ID**, затем нажмите **Generate a new client secret**
   и скопируйте секрет: GitHub показывает его один раз.

Для каждого адреса приложения (локально, продакшен) нужно отдельное OAuth-приложение: у приложения GitHub
один callback URL.

### Google

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект или выберите существующий.
2. **APIs & Services → OAuth consent screen**: тип пользователей **External**, заполните название
   и контактный email. Дополнительные scopes не нужны: CoDraw запрашивает только `profile`. Пока приложение
   в статусе **Testing**, добавьте в **Test users** аккаунты, которыми будете входить.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**: тип **Web application**,
   в **Authorized redirect URIs** добавьте `http://localhost:5173/api/login/oauth2/code/google`
   (и адрес продакшена, если нужен).
4. Скопируйте **Client ID** и **Client secret**.

### Переменные окружения

| Переменная | Сервис | Что |
|---|---|---|
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | backend | OAuth-приложение GitHub |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | backend | OAuth-приложение Google |
| `CODRAW_COLLAB_TOKEN_SIGNING_KEY` | backend | RSA-ключ подписи токенов синхронизации (PEM, PKCS#8) |
| `CODRAW_COLLAB_TOKEN_PREVIOUS_SIGNING_KEY` | backend | предыдущий ключ подписи на время смены ключа |
| `BACKEND_JWKS_URL` | collab | открытые ключи backend: `<адрес backend>/.well-known/jwks.json` |

Локально достаточно задать переменные провайдеров при запуске backend; если нужен только один провайдер,
переменные другого можно не задавать. Вместо переменных можно положить значения в
`backend/config/application-dev.yaml` — backend читает его в профиле `dev`, а файл в `.gitignore`:

```bash
cd backend
GITHUB_CLIENT_ID=… GITHUB_CLIENT_SECRET=… GOOGLE_CLIENT_ID=… GOOGLE_CLIENT_SECRET=… ./gradlew bootRun
```

Затем откройте http://localhost:5173 и нажмите «Войти через GitHub» — после подтверждения доступа
у провайдера откроется список ваших досок, а в шапке появятся ваши имя и аватар.

В продакшене обязательны все переменные backend, кроме предыдущего ключа подписи. Ключ подписи — один
и тот же у всех экземпляров backend; без него backend генерирует ключ при каждом старте, и выданные токены
перестают действовать после перезапуска. Создать ключ:

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out collab-signing-key.pem
```

и передать его содержимое: `CODRAW_COLLAB_TOKEN_SIGNING_KEY="$(cat collab-signing-key.pem)"`. При смене
ключа прежний перенесите в `CODRAW_COLLAB_TOKEN_PREVIOUS_SIGNING_KEY` хотя бы на 5 минут — срок жизни
токена.

## Доски

На главной странице — свои доски, недавно изменённые сверху, раздел «Начать с шаблона» (ER-диаграмма, C4, микросервисы, деплой в Kubernetes) и раздел «Открытые по ссылке»: доски других
пользователей, которые вы открывали по ссылке, с именем владельца. Владелец переименовывает доску щелчком по её
названию на странице доски или пунктом «Переименовать» в меню доски в списке, а удаляет — пунктом «Удалить» того же
меню или «Удалить доску» на странице доски. Удаление необратимо: доска удаляется вместе с документом, а участники,
которые на ней работают, видят «Доска не найдена». Новое название сразу видят все, кто открыл доску.

### Доступ по ссылке

Кнопка «Поделиться» на странице доски показывает ссылку на доску с текущей страницей и копирует её. Владелец там же
выбирает, что ссылка даёт остальным:

| Режим | Что видит открывший ссылку |
|---|---|
| «Редактирование» | правит доску вместе с владельцем; так создаётся каждая новая доска |
| «Просмотр» | доску с отметкой «Только просмотр»: прокрутка, масштаб, выделение, копирование, экспорт в `.drawio` и в изображение, без панели фигур, инструментов правки, правки страниц и импорта |
| «Только я» | «Нет доступа»; доска пропадает из его раздела «Открытые по ссылке» и вернётся, когда владелец снова откроет доступ |

Новый режим действует сразу, в том числе у тех, кто уже работает на доске: их соединение переподключается с новыми
правами. Право правки проверяет сервис синхронизации — правки участника с режимом «Просмотр» не применяются, даже если
отправить их в обход интерфейса. Владелец всегда правит свою доску.

### Живая картинка

Владелец включает в окне «Поделиться» «Живую картинку» и выбирает страницу: появляется постоянная ссылка
`/api/embeds/….svg` и кнопки «Копировать ссылку» и «Копировать Markdown» для README, вики и задач. Картинку рисуют
браузеры участников, которые правят доску: после их правок страницы (через 3 секунды тишины, не чаще раза в 10 секунд)
страница рисуется в SVG, как при экспорте, и уходит в `backend`; сервер очищает SVG по белому списку и отдаёт его без
входа с `Cache-Control: max-age=60` и политикой `sandbox`. Картинку видит любой, у кого есть ссылка, даже если доступ
к доске закрыт; выключение удаляет её, а новое включение даёт новую ссылку.

### История версий

CoDraw сам сохраняет прежнее состояние доски как версию — перед первой правкой после паузы и не реже чем раз в 10 минут
работы; у доски хранятся 100 последних версий, вместе не больше 64 МБ. Владелец открывает «История версий» в меню доски: там список версий
(«Автоматически», «Вручную», «Перед восстановлением») и кнопка «Сохранить версию». Выбранная версия показывается вместо
доски только для просмотра, со своими страницами. «Восстановить эту версию» сначала сохраняет текущее состояние как
версию «Перед восстановлением», а затем возвращает доске содержимое версии — у всех участников сразу. Остальным
участникам история недоступна.

### Следование за участником

Щелчок по участнику в списке включает следование: ваш холст открывает его страницу, ставит середину вида туда же,
где у него, берёт его масштаб и повторяет каждое его движение — удобно на созвоне, когда один ведёт по схеме. Над
холстом — плашка его цвета «Вы следуете за …» с «Остановить». Следование заканчивается, когда вы сами двигаете холст,
открываете другую страницу или нажимаете Escape, и когда ведущий уходит с доски. Вид участника (середина и масштаб)
идёт через присутствие, как курсоры, и не сохраняется.

### Комментарии

Кнопка «Комментарии» в шапке доски показывает число открытых веток и открывает панель справа: ветки сгруппированы по
страницам, текущая — первой, с фильтрами «Открытые», «Решённые» и «Упоминают меня». Ветку к фигуре, таблице, полю,
связи или группе начинает пункт «Комментировать» меню правого щелчка, ко всей странице — «Комментарий к странице» в
панели. В ветке отвечают, свои комментарии правят и удаляют, владелец доски удаляет любые; удаление первого
комментария удаляет ветку. «Решено» убирает ветку из открытых, «Открыть снова» возвращает. `@` и первые буквы имени
предлагают участников доски — владельца и открывавших её по ссылке; упомянутые выделяются в тексте. У элемента
с открытыми ветками на холсте значок с их числом; щелчок по значку открывает его ветки, а щелчок по ветке переходит
на её страницу и выделяет элемент. Комментарии пишут и участники в режиме «Просмотр»: схему они не меняют. Ветка
удалённого элемента остаётся с пометкой «Элемент удалён»; комментарии хранятся в PostgreSQL, не в документе доски,
поэтому восстановление версии их не трогает. Изменения видны остальным участникам сразу.

### Маршруты связей

Ортогональная связь — форма новой связи — прокладывается сама: обходит таблицы и фигуры страницы с отступом, к полю
таблицы подходит слева или справа на его высоте, к другой фигуре — к середине стороны или к точке, к которой привязан
конец, выбирает путь с меньшим числом изломов, а связи, которые шли бы по одной линии или приходят в одно поле,
разводит. Рамки и группы не мешают: связь идёт внутри них и обходит их фигуры. Маршрут пересчитывается после каждой
правки страницы, своей или чужой, и у всех участников одинаков; в документе и в `.drawio` его нет. Считает его
libavoid в Web Worker ([ADR-0004](docs/adr/0004-edge-routing.md)); пока маршрут не готов, связь идёт ортогонально,
как раньше. Если перетащить отрезок связи, она пойдёт через поставленные изломы и перестанет прокладываться сама;
«Прямая» и «Кривая» в «Стиле линии» тоже рисуются как раньше.

### Автораскладка

Кнопка «Автораскладка» на панели инструментов расставляет фигуры слоями по связям — «Слева направо» или «Сверху вниз»,
`Ctrl+Shift+L` (на macOS — `Cmd+Shift+L`) — «Слева направо». С двумя выделенными фигурами и больше раскладывается
выделенное, иначе вся страница; разложенное остаётся на месте своего левого верхнего угла. Таблицы и группы
переставляются целиком (связь полей — связь таблиц), фигуры внутри рамки — границы, границы C4 или кластера
Kubernetes — раскладываются внутри неё, и рамка подстраивает размер. Раскладка — один шаг отмены, её видят все
участники. Алгоритм — ELK Layered ([ADR-0003](docs/adr/0003-auto-layout.md)); библиотека загружается при первой
раскладке.

### Таблицы базы данных

Поле таблицы показывается колонками, выровненными по всей таблице: ключ у первичного ключа, звено у внешнего, ромб у
уникального (`UNIQUE`), имя,
тип, `NULL` или `NOT NULL` и у внешнего ключа — куда он ссылается (`→ users.id`), затем остальное, например
`DEFAULT now()`. Цель ссылки берётся из связи поля с полем другой таблицы и меняется у всех, когда связь проводят или
удаляют и когда переименовывают таблицу или поле, на которые она ведёт. В заголовке таблицы — значок её СУБД: PG
(PostgreSQL), MY (MySQL / MariaDB), ORA (Oracle), MS (SQL Server), LITE (SQLite), CH (ClickHouse). Таблица из панели
фигур и из импорта — PostgreSQL с автошириной; у таблиц из `.drawio` и старых досок СУБД нет.

Выделенная таблица или её поле показывает на панели инструментов «СУБД», а выделенное поле — «Тип» со списком типов
этой СУБД (можно ввести свой, например `numeric(12,4)`), `NULL` / `NOT NULL`, «PK» и «UNIQUE»; те же свойства —
в плашке рядом с таблицей, на высоте выделенного поля (справа, а у правого края холста — слева). Каждое изменение —
один шаг отмены. Двойной щелчок по полю правит только имя; строка целиком (`email text NOT NULL`) по-прежнему
разбирается как поле. Новое поле без имени показывает серую заглушку «имя поля» — двойной щелчок по ней открывает ввод
имени. Данные поля — по-прежнему его текст `имя тип PK FK NOT NULL UNIQUE`, поэтому выгрузки и
`.drawio` его не теряют.

### SQL и Mermaid

Кнопка «SQL и Mermaid» в шапке доски превращает DDL в ER-диаграмму и обратно. «Импорт SQL…» принимает текст или файлы `.sql` —
миграции Flyway применяются по порядку версий (`V1__`, `V1_1__`, `V2__`, затем `R__`; откаты `U…__` пропускаются) — и
понимает `CREATE TABLE`, `ALTER TABLE` и `DROP TABLE` PostgreSQL и общую часть MySQL; индексы, функции и данные
пропускаются, сводка показывает, сколько найдено таблиц и связей и сколько пропущено операторов. Таблицы встают справа
от фигур страницы, разложенные автораскладкой, с полями `имя тип PK FK NOT NULL UNIQUE` и связями от внешних ключей
к полям, на которые они ссылаются; добавление — один шаг отмены. «Скопировать SQL» и «Скачать .sql» выгружают таблицы
страницы в `CREATE TABLE` и `ALTER TABLE … ADD FOREIGN KEY` PostgreSQL, «Скопировать Mermaid» — в `erDiagram`; поля,
написанные руками, читаются так же. Выгрузка доступна и в режиме «Просмотр».

Блок-схему (`flowchart`, `graph`) или ER-диаграмму (`erDiagram`) Mermaid достаточно вставить на холст `Ctrl+V` — или
через «Импорт Mermaid…» того же меню: узлы становятся фигурами палитры по форме (`[ ]` — прямоугольник, `( )` —
скруглённый, `(( ))` — эллипс, `{ }` — ромб, `[( )]` — база данных), связи — связями с подписями, стрелками, пунктиром
(`-.->`) и толщиной (`==>`), `subgraph` — рамкой «Граница» вокруг своих узлов, сущности ER — таблицами со связями
полей `FK`. Схема раскладывается автораскладкой в направлении `LR` или `TD` и вставляется одним шагом отмены; стили
и классы Mermaid пропускаются.

### Пределы

Чтобы одна учётная запись не заняла диски и память всей установки, у пользователя — не больше 100 досок, с одного
адреса — не больше 20 новых гостей в час, документ доски растёт до 16 МБ, а версии доски занимают вместе до 64 МБ,
на доске — не больше 5000 комментариев, живая картинка — до 2 МБ.
У предела размера доска принимает только удаления: правка, которая её увеличит, не сохраняется, и её автор видит
предупреждение. Пределы настраиваются, см. [docs/deploy.md](docs/deploy.md).

### Мониторинг

`backend` и `collab` отдают метрики Prometheus внутри сети стека: нагрузку, ошибки, сохранения документов, пределы и
уборку гостей, — а журналы пишут в JSON. Ошибки, случившиеся в браузерах участников, приложение отправляет в `backend`:
они есть в его журнале и метриках, а участник вместо пустой страницы видит «Что-то пошло не так». С профилем `monitoring` `docker-compose.prod.yml` поднимает Prometheus с
правилами оповещений; подробности — в разделе «Мониторинг и журналы» [docs/deploy.md](docs/deploy.md), решение — в
[ADR-0002](docs/adr/0002-observability.md).

### Персональные данные

Политика конфиденциальности (`/privacy`) и условия использования (`/terms`) открыты без входа; на странице входа
сказано, что вход означает согласие с ними, а ссылки на них есть внизу списка досок. Тексты описывают, что CoDraw
делает на самом деле, и берут сроки хранения и данные оператора из настроек установки (см.
[docs/deploy.md](docs/deploy.md)). Изменение, которое добавляет данные, cookie или получателей, обновляет и политику.

## Спецификации

Работа ведётся по [OpenSpec](https://github.com/Fission-AI/OpenSpec):

- `openspec/specs/` — действующие требования к системе;
- `openspec/changes/` — запланированные изменения: зачем (`proposal.md`), как (`design.md`),
  что поменяется в требованиях (`specs/`) и задачи (`tasks.md`).

CLI ставится через `npm i -g @fission-ai/openspec`. В Claude Code доступны команды `/opsx:propose`,
`/opsx:apply` и `/opsx:archive`.
