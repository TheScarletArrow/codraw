# ADR-0010: Резервные копии

- **Статус:** принято
- **Дата:** 2026-10-10

## Контекст

Состояние установки — в PostgreSQL и в S3-совместимом хранилище картинок ([ADR-0006](0006-image-storage.md)).
`docs/deploy.md` описывал только ручные копии: если оператор их забыл, сбой диска уносит все доски. Нужны копии по
расписанию без участия оператора, хранение вне сервера, шифрование, видимость в мониторинге
([ADR-0002](0002-observability.md)) и восстановление, которое проверяется автоматически (issue #157).

## Решение

| Что | Выбор |
|---|---|
| Где | свой сервис `backup` в `docker-compose.prod.yml`, образ `codraw-backup` на `postgres:18-alpine` |
| База | `pg_dump --format=custom` и `pg_restore` того же мажора, что сервер |
| Картинки, хранилище копий, шифрование | rclone: S3 API для картинок и хранилища копий вне сервера, бэкенд `crypt` для шифрования паролем |
| Расписание | supercronic: cron для контейнеров, работает не от root |
| Хранение | последний архив дня моложе N дней и недели моложе M недель, свежий — всегда |
| Мониторинг | файл метрик Prometheus, который отдаёт `rclone serve http`, и правила оповещений |

## Обоснование

- Сервис стека запускается обычным `up -d`, виден в `ps`, журналах и Prometheus и проверяется в CI вместе со стеком;
  cron хоста забывают и не видят.
- rclone закрывает три задачи одним статическим бинарником: копирует бакет картинок любого S3-совместимого хранилища
  (не только тома RustFS), кладёт архивы во внешнее хранилище и шифрует их с проверкой целостности. Он копируется из
  официального образа `rclone/rclone` с точной версией.
- supercronic передаёт заданиям окружение контейнера и пишет их вывод в журнал контейнера; `crond` busybox требует root.
  Бинарник релиза скачивается с проверкой SHA-256.

Отклонённые альтернативы:

- **restic или borg** — дедупликация и инкрементальные копии, но свой формат репозитория, ещё один инструмент и пароль
  для любой операции; полный архив из `pg_dump` и файлов проще восстановить руками.
- **Архивация WAL (pgBackRest, WAL-G) и восстановление на момент времени** — меньше потерь, но отдельная настройка
  PostgreSQL и хранилища WAL; для MVP хватает суточных копий.
- **Готовые образы вида `postgres-backup-s3`** — копируют только базу, без картинок и без проверки восстановления.
- **age или gpg для шифрования** — нет в базовом образе; rclone уже нужен для S3.
- **cron хоста** — прежний совет `docs/deploy.md`.

## Последствия

- Новые инструменты в стеке: rclone и supercronic в образе `codraw-backup`; CI собирает и публикует его вместе с
  остальными.
- Каждый архив — полная копия базы и картинок: место растёт с числом хранимых архивов.
- Порог оповещения `CodrawBackupMissing` рассчитан на суточное расписание; при другом его меняют вместе с расписанием.
- Срок хранения копий называет политика конфиденциальности, поэтому `backend` получает настройки хранения копий.
