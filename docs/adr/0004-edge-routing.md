# ADR-0004: Маршруты связей

- **Статус:** принято
- **Дата:** 2026-10-05

## Контекст

Связи прокладывал ортогональный стиль maxGraph, который не знает о других фигурах: линии шли сквозь таблицы и фигуры,
к полю таблицы подходили сверху через саму таблицу, сливались общими отрезками и делали лишние изломы. Нужен маршрут,
который обходит фигуры, подходит к полю сбоку, разводит связи и одинаков у всех участников, при этом не хранится в
документе Yjs. Схемы — до сотен таблиц (импорт SQL), всё считается в браузере.

## Решение

| Что | Выбор |
|---|---|
| Алгоритм | libavoid (Adaptagrams): ортогональный граф видимости, поиск со штрафом за изломы, пины с направлениями, разведение отрезков |
| Библиотека | `libavoid-js` 0.4.5 — libavoid, собранный в WebAssembly, без изменений |
| Где считается | Web Worker, отдельный чанк с `libavoid.wasm` (около 175 КБ gzip); один запрос за раз, новый вход ждёт ответа |
| Что маршрутизируется | ортогональные связи без изломов, поставленных участником; прочие — как раньше |
| CSP | `script-src 'self' 'wasm-unsafe-eval'` |

## Обоснование

- libavoid — исследовательский маршрутизатор (Wybrow, Marriott, Stuckey), его используют Inkscape и Dunnart; разведение
  отрезков у фигур, ради которого связи становятся читаемыми, — самая трудная часть, и она в нём есть.
- Прототип: пересчёт страницы целиком — 14 мс для 30 таблиц и 40 связей, 73 мс для 100 и 150, около 0,8 с для 200
  и 300. Worker не даёт этому задерживать интерфейс; маршрутизатор пересоздаётся на каждый расчёт без роста памяти.
- Маршрут считается из ячеек страницы в порядке их id, поэтому у всех участников он одинаковый и не нуждается
  в синхронизации.

Отклонённые альтернативы:

- **`manhattanEdgeStyle` maxGraph** — стороны выхода одной глобальной настройкой, таблица вокруг поля для него
  препятствие, наложения не разводятся.
- **Свой маршрутизатор** — граф видимости и A* несложны, но разведение отрезков у фигур пришлось бы писать
  и отлаживать самим, как и раскладку в ADR-0003.
- **ELK** — маршрутизирует только вместе со своей раскладкой, не при заданных координатах.
- **`libavoid-js` 0.5 (бета)** — бета; переход — сменой версии.

## Последствия

- Зависимость `libavoid-js` под LGPL-2.1-or-later: используется без изменений, отдельным файлом WebAssembly, который
  можно заменить. Изменения в самой libavoid пришлось бы публиковать под LGPL.
- Политика безопасности разрешает компиляцию WebAssembly (`'wasm-unsafe-eval'`); выполнение JavaScript из строк
  по-прежнему запрещено.
- Маршрута нет в `.drawio`: draw.io прокладывает связи сам. Пока маршрут не готов, связь идёт ортогонально, как раньше.
- Штраф за пересечения связей замедляет расчёт в 8–10 раз и не включён.
