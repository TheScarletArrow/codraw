# ADR-0006: Хранилище изображений

- **Статус:** принято
- **Дата:** 2026-10-07

## Контекст

На доску кладут картинки: скриншоты, логотипы, макеты. Документ доски — состояние Yjs, которое `collab` хранит через
`backend` целиком (до 16 МБ), версии хранят его копиями (до 64 МБ на доску), а каждый участник получает документ при
каждом открытии. Картинка внутри документа (строка `data:`, как сейчас приходят картинки из `.drawio`) растила бы его и
каждую версию на свой размер и шла бы ко всем участникам, даже если они не открывают её страницу. ADR-0001 отвёл файлам
«S3-совместимое хранилище (MinIO локально)», но в стеке его не было. С осени 2025 года MinIO не публикует образы
сообщества (`minio/minio`, `quay.io/minio/minio` не скачать), а его открытый репозиторий — в режиме поддержки.

## Решение

| Что | Выбор |
|---|---|
| Где байты | объекты `boards/{boardId}/{imageId}` в бакете `codraw-images` S3-совместимого хранилища |
| Где описание | таблица `board_images` в PostgreSQL: доска, SHA-256, тип по сигнатуре, размер, ширина и высота |
| Что на доске | ссылка `/api/boards/{boardId}/images/{imageId}` в стиле `shape=image` draw.io |
| Доступ | только через `backend`: загрузка — с правом правки доски (или автор открытого предложения), отдача — любой роли на доске; бакет закрыт, браузер в хранилище не ходит |
| Клиент | AWS SDK for Java v2 2.55.12 (`s3`, `url-connection-client`; Apache-2.0) без Netty и Apache HTTP client, path-style, адрес, регион, бакет и ключи — `codraw.images.s3.*` |
| Сервер | RustFS 1.0.1 (`rustfs/rustfs:1.0.1`, Apache-2.0) — в `docker-compose.yml`, `docker-compose.prod.yml`, CI и тестах `backend` |
| Срок хранения | пока жива доска; удаление доски удаляет её картинки, уборка раз в час добирает картинки досок, удалённых уборкой гостей |

## Обоснование

- Байты отдельно от документа: документ и версии хранят только короткие ссылки, а картинку браузер скачивает, когда
  показывает её, и кеширует на год (адрес картинки не меняется). Хранилище растёт и копируется отдельно от базы.
- Через `backend`, а не по прямым или подписанным ссылкам хранилища: права на картинку — права на доску и проверяются
  на каждый запрос (снятый доступ закрывает картинки сразу), адрес тот же, что у приложения, поэтому CSP
  (`img-src 'self'`) и cookie сеанса не меняются, а хранилище не публикуется через nginx. Цена — байты идут через
  `backend`; ответы потоковые, на виртуальных потоках.
- Описание в PostgreSQL: место доски считается запросом, одинаковый файл находится по SHA-256, а права и удаление —
  в той же базе, что доски. Внешнего ключа на доску нет: строки удалённой доски живут, пока уборка не удалит их
  объекты, — хранилище не участвует в транзакциях базы.
- AWS SDK for Java v2 — стандартный клиент S3, который понимают все S3-совместимые серверы. Синхронный клиент на
  `HttpURLConnection` не тянет Netty и Apache HTTP client; контрольные суммы — только где их требует S3
  (`WHEN_REQUIRED`), потому что новые CRC SDK серверы S3 понимают по-разному.
- RustFS среди образов, которые можно скачать:

| Сервер | Лицензия | Зрелость | S3 | Запуск |
|---|---|---|---|---|
| **RustFS** (`rustfs/rustfs`) | Apache-2.0 | молодой: альфа-версии с 2025 года, сейчас выпуск 1.0.1 | API S3 с подписью v4, path-style, многоблочная загрузка; создаёт бакеты по API | один процесс, ключи — переменными окружения (`RUSTFS_ACCESS_KEY`, `RUSTFS_SECRET_KEY`), данные — том `/data`, порт 9000 и `/health` как у MinIO, `curl` для проверки готовности; стартует без команды — подходит для `services:` GitHub Actions |
| SeaweedFS (`chrislusf/seaweedfs`) | Apache-2.0 | зрелый, с 2012 года | шлюз S3 поверх файловой системы SeaweedFS | четыре роли (master, volume, filer, s3) в одном или нескольких процессах, ключи — JSON-конфигом шлюза, нужна команда (`mini`, `server -s3`); образ ~700 МБ |
| Garage (`dxflrs/garage`) | AGPL-3.0 | зрелый, для геораспределённых установок | основное API, ключи и бакеты — своим CLI | TOML-конфиг, после старта — разметка кластера (`garage layout assign/apply`) и ключи командами: в Compose нужен отдельный шаг настройки |
| `pgsty/minio` | AGPL-3.0 | код MinIO, сборка сообщества Pigsty | лучшая совместимость | как MinIO, но сборку проекта в режиме поддержки делает третья сторона |
| `adobe/s3mock` | Apache-2.0 | двойник для тестов | основное API | не для продакшена: другой сервер в тестах проверял бы не то, что работает в стеке |

  RustFS запускается и настраивается как MinIO, которого ожидал ADR-0001, без конфигурационных файлов и шагов
  настройки, под разрешительной лицензией. Его молодость уравновешивает то, что `backend` говорит на обычном S3 без
  расширений: сервер меняется настройками (`CODRAW_IMAGES_S3_*`), а тесты `backend` и e2e идут на том же образе, что
  стек.

Отклонённые альтернативы:

- **`bytea` в PostgreSQL** — без нового сервиса, но база и её копии растут на гигабайты картинок, JDBC читает значение
  целиком в память, а ADR-0001 и задача называют S3.
- **Каталог на диске `backend`** — не делится между экземплярами `backend`, а копирование и перенос — свои.
- **Строки `data:` в документе доски** — растут документ и все версии, каждый участник скачивает все картинки при
  каждом открытии, а предел документа (16 МБ) быстро кончается.
- **Подписанные ссылки хранилища (presigned URL)** — хранилище пришлось бы открыть наружу и в CSP, а снятый доступ
  к доске не закрывал бы уже выданные ссылки до их срока.
- **MinIO Java SDK** — тянет OkHttp, Guava и Jackson своих версий; **своя подпись SigV4** — своя криптография и разбор
  XML ответов ради нескольких мегабайт зависимостей.

## Последствия

- В стеке пятый сервис со своим томом: его надо копировать вместе с базой (`docs/deploy.md`), а `CODRAW_S3_SECRET_KEY`
  — обязательная переменная продакшен-стека.
- Картинки, убранные с доски, занимают её место до удаления доски: на них ссылаются версии, предложения и отмена, а
  `backend` не читает документы Yjs. Предел места доски (100 МБ) и хранение одинаковых файлов один раз ограничивают
  рост; удаление ненужных картинок — отдельное изменение.
- Без хранилища доски работают, а загрузка и показ картинок отвечают 503; `backend` стартует и создаёт бакет, когда
  хранилище появится.
- Новые зависимости `backend`: модули AWS SDK for Java v2 (`s3` и его `aws-core`, `auth`, `regions`, `http-auth-aws`,
  `checksums`, `aws-xml-protocol` и т. п., `url-connection-client`) — Apache-2.0, около 9 МБ в образе.
