# ADR-0009: Задачи трекера у элементов и обсуждений

- **Статус:** принято
- **Дата:** 2026-10-09

## Контекст

Итоги архитектурного обсуждения переносят в трекер вручную, а статус реализации узнают отдельно (issue #124). Нужна
связь элемента схемы или ветки комментариев с задачей: привязать существующую, создать новую со ссылкой обратно, видеть
номер, название и статус. Трекер — внешняя система со своими правами: задача закрытого репозитория видна не всем, токен
доступа даёт писать в репозитории, а сама задача может быть удалена, перенесена или стать недоступной. События трекера
приходят повторно и не по порядку. Двусторонняя синхронизация (закрыть задачу из CoDraw, сменить статус элемента по
задаче) — отдельное решение.

## Решение

| Что | Выбор |
|---|---|
| Трекер | GitHub Issues: github.com или GitHub Enterprise Server по `codraw.issues.github.api-url`; пустое значение выключает задачи |
| Подключение | личный токен пользователя (рекомендуется fine-grained: нужные репозитории, «Issues: Read and write», срок), проверяется `GET /user`; один на пользователя, только у вошедших через провайдера |
| Хранение токена | `issue_tracker_connections` в PostgreSQL, как адреса вебхуков (ADR-0008): API его не отдаёт, в журнал и метрики он не попадает; отказ GitHub (401) помечает подключение, и токен больше не отправляется |
| Сеть | запросы только на `api-url`; перенаправления — только в его пределах (301 переименования репозитория и переноса задачи); тайм-ауты 5 и 10 секунд |
| Привязка | `issue_links`: элемент (`page_id`, `cell_id`) или ветка (`thread_id`, каскад), id задачи в GitHub, `owner/name`, номер, название, статус и причина, ссылка, закрыт ли репозиторий, кто привязал; `UNIQUE NULLS NOT DISTINCT` по цели и id задачи |
| Права | видят все, кому доступна доска; к элементу привязывают и отвязывают владелец и редакторы, к ветке — все, кто комментирует, отвязывает ещё и привязавший; токен — только свой |
| Раскрытие | привязка показывает номер, название и статус задачи всем участникам доски — это выбор привязавшего, которого форма предупреждает, отдельно для закрытого репозитория; чужим токеном задачу не найти и не привязать |
| Обновление статуса | только из GitHub в CoDraw: токеном привязавшего, когда привязку показывают и ей больше 5 минут (не чаще раза в минуту), и вебхуком задач с подписью `X-Hub-Signature-256` секретом `codraw.issues.github.webhook-secret` |
| Повторы | повторная привязка — та же строка; создание с `requestId` клиента — резерв `issue_creations` до запроса к GitHub, повтор получает ту же привязку или 409 «создаётся»; событие вебхука применяется, только если `updated_at` задачи не старше известного |
| Потеря доступа | 404 и 403 — «нет доступа», 410 — «удалена», нет рабочего подключения у привязавшего — «не обновляется»; последнее известное состояние остаётся, «Обновлять через моё подключение» передаёт привязку другому участнику явно |

## Обоснование

- GitHub — провайдер входа CoDraw и место, где команды держат код; его REST API открыт, а fine-grained токены дают
  ровно доступ к задачам выбранных репозиториев. Таблицы хранят вид трекера (`tracker`), и второй трекер (Jira,
  YouTrack, GitLab) — новый клиент и значение, а не новая модель.
- Личный токен, а не OAuth-приложение: OAuth App GitHub даёт только `repo` — полный доступ ко всем закрытым репозиториям
  пользователя, а GitHub App требует установки в каждую организацию, ключа приложения и приёма событий установки.
  Токен пользователь создаёт сам с нужными правами и сроком, и он одинаково работает с GitHub Enterprise Server.
- Токен не шифруется ключом установки по той же причине, что адреса вебхуков в ADR-0008: это ещё один секрет
  развёртывания с ротацией, а база и так хранит секреты (сеансы, токены приглашений). Ущерб от утечки ограничивает сам
  токен — права и срок, которые советует страница «Подключения».
- Снимок задачи хранится в CoDraw, а не запрашивается у GitHub при каждом показе: участник без подключения тоже видит
  статус, доска не зависит от доступности GitHub, а лимит запросов токена (5000 в час) тратится только на устаревшие
  привязки, которые кто-то смотрит. Обновление токеном привязавшего, а не смотрящего: иначе чужой токен раскрывал бы
  доске то, чего привязавший не показывал. Передать привязку себе можно только кнопкой — это то же решение показать
  задачу, что и привязка.
- Статус идёт в одну сторону, и интерфейс говорит это словами: правила, кто побеждает при одновременной правке статуса
  элемента и задачи, — предмет отдельного решения о двусторонней синхронизации.
- Создание задачи — единственная операция, повтор которой оставил бы след во внешней системе. GitHub не принимает ключа
  идемпотентности, поэтому резерв по `requestId` ставится в базе до запроса, а брошенный (экземпляр `backend` упал) через
  2 минуты считается потерянным. Цена — редкий дубль, если экземпляр упал между созданием задачи и записью привязки.
- Вебхук — по желанию: он нужен для мгновенного статуса, но требует прав администратора репозитория. События, которые
  GitHub повторяет и шлёт не по порядку, применяются по `updated_at` задачи, так что дедупликация не требует журнала
  доставок. Событие меняет только уже привязанные задачи и ничего не добавляет.
- Поиск задач по словам вырезает квалификаторы (`repo:…`) из текста пользователя: поиск идёт только в выбранном
  репозитории.

Отклонённые альтернативы:

- **OAuth App с `repo`** — слишком широкий доступ; **GitHub App** — установка в организацию и ключ приложения на
  установку CoDraw; можно добавить позже как второй способ подключения.
- **Общий токен установки** — задачи всех пользователей видны через один токен, и права пользователя в GitHub перестают
  что-либо значить.
- **Только живые запросы к GitHub без снимка** — каждый показ доски тратит лимит запросов, а участник без доступа к
  репозиторию не видит ничего.
- **Хранить задачу в документе доски (Yjs)** — её откатывали бы версии и предложения изменений, а токен и права
  пришлось бы проверять в `collab`.
- **Журнал `X-GitHub-Delivery` для дедупликации** — лишняя таблица и уборка; сравнение `updated_at` решает и повторы, и
  порядок.
