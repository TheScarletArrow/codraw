# ADR-0013: Доставка оповещений

- **Статус:** принято
- **Дата:** 2026-10-11

## Контекст

Prometheus профиля `monitoring` ([ADR-0002](0002-observability.md)) проверяет правила `deploy/prometheus/alerts.yml`,
в том числе правила резервных копий ([ADR-0010](0010-backups.md)), но отправлять их некуда: ADR-0002 оставил доставку
тому, кто разворачивает. Сработавшее правило видит только тот, кто сам открыл страницу Alerts через SSH-туннель, а о
падении самого Prometheus или сервера не узнаёт никто. Перед выпуском MVP оповещения должны доходить до людей после
нескольких строк в `.env.prod`, без знания формата Alertmanager, а секреты каналов — не попадать в образ, конфигурацию
на диске и журналы.

## Решение

| Что | Выбор |
|---|---|
| Доставка | сервис `alertmanager` из официального образа `prom/alertmanager:v0.34.1` в профиле `monitoring`, один экземпляр без кластера, порт `127.0.0.1:9093` |
| Конфигурация | собирается при запуске `deploy/alertmanager/entrypoint.sh` из переменных `.env.prod`; свой файл оператора через `CODRAW_ALERTMANAGER_CONFIG` — запасной путь |
| Каналы | один получатель со всеми заданными каналами: Telegram (`telegram_configs`), почта через SMTP уведомлений CoDraw (`email_configs`, только TLS), Slack-совместимый вебхук (`slack_configs`: Slack, Mattermost, Rocket.Chat) |
| Маршрут | группировка по правилу и сервису, первое сообщение через 30 с, повтор через 4 ч, сообщения о разрешении; `CodrawServiceDown` глушит производные правила своего сервиса |
| Секреты | в файлах с правами владельца, подключаются полями `*_file`; переменные удаляются из окружения процесса; токен Telegram вырезается из журнала фильтром |
| Сторож | правило `Watchdog`, которое срабатывает всегда, отдельным маршрутом раз в 5 минут уходит на адрес внешнего сервиса (dead man's switch: healthchecks.io и подобные) |

## Обоснование

- Официальный образ с точной версией — как у Prometheus: без своей сборки и публикации, обновление — смена тега.
- Alertmanager не подставляет переменные окружения в конфигурацию. Шаблон в entrypoint позволяет задавать получателей
  там же, где всё остальное в стеке, а маршрут, глушение и сторож остаются в репозитории и улучшаются вместе с ним.
  Файл оператора требует знать формат Alertmanager и переносить в него каждое улучшение маршрутов, поэтому он только
  запасной путь — для разных получателей по правилам, дежурств и интеграций, которых нет в переменных.
- Значения, попадающие в YAML, скрипт проверяет и экранирует, а секреты в YAML не пишет вовсе: в собранной конфигурации
  и на странице состояния Alertmanager — только пути к файлам. Адреса вебхуков Alertmanager сам скрывает в ошибках, а
  URL Telegram с токеном печатает целиком, поэтому нужен фильтр журнала.
- Наполовину заданный канал останавливает сервис: ошибку видно при `up --wait`, а не в день аварии. Без каналов стек
  поднимается как раньше, а журнал предупреждает, что оповещения никуда не уходят.
- Мониторинг не может сообщить о собственном падении. Внешний сторож, который ждёт отметок, замечает остановку
  Prometheus, Alertmanager и всего сервера, ничего не открывая наружу.

Отклонённые альтернативы:

- **Оповещения Grafana** — понадобились бы Grafana с её базой и настройкой в стеке ради доставки, которую Alertmanager
  делает один; дашборды остаются за тем, кто разворачивает.
- **Внешний сервис, который опрашивает Prometheus** — потребовал бы открыть Prometheus наружу; сторож с отметками
  работает только на исходящих запросах.
- **Своя отправка оповещений в `backend`** — у `backend` уже есть почта и чаты, но он сам среди того, что ломается, и
  пришлось бы повторить группировку, повторы и глушение Alertmanager.
- **Свой образ с зашитой конфигурацией** — ещё один образ для сборки и публикации, а получатели всё равно приходят из
  окружения установки.

## Последствия

- Новый сервис в стеке с мониторингом — Alertmanager — и том `alertmanager-data` для тишин и журнала отправок.
- Оператор копирует на сервер каталог `deploy/alertmanager` рядом с `deploy/prometheus`.
- Фильтр журнала — лишний процесс в контейнере, пока Alertmanager печатает токен Telegram.
- Почта оповещений уходит только с TLS; для внутреннего релея без TLS — `CODRAW_ALERT_SMTP_REQUIRE_TLS=false`.
- `Watchdog` всегда виден сработавшим на странице Alerts Prometheus.
- CI на каждом пуше проверяет конфигурацию `amtool check-config` и доставку тестового оповещения и сторожа до
  получателя-вебхука в стеке.
