# ADR-0007: Схема из живой базы

- **Статус:** принято
- **Дата:** 2026-10-07

## Контекст

«Импорт SQL» разбирает DDL и миграции Flyway в браузере (`add-sql-import-export`). У существующей базы схема часто
есть только в ней самой (issue #54), и её хочется взять без ручного DDL. Есть два пути: дамп схемы утилитой СУБД,
который открывается файлом, и подключение к базе. Браузер к базе подключиться не может — нужен `backend`, а он
стоит во внутренней сети установки: подключение по адресу, который ввёл пользователь, делает из `backend` дверь в
эту сеть (SSRF), сканер портов и место, через которое проходят чужие пароли. Драйвер PostgreSQL (PgJDBC) в `backend`
уже есть — для своей базы.

## Решение

| Что | Выбор |
|---|---|
| Основной путь | дамп: `pg_dump --schema-only`, `mysqldump`/`mariadb-dump --no-data`, — разбор в браузере понимает их целиком; окно подсказывает команды |
| Подключение | через `backend`, только PostgreSQL, **выключено по умолчанию**: включает администратор списком `codraw.schema-import.allowed-hosts` (имена, адреса, сети CIDR) |
| Ответ | DDL как у `pg_dump`, который встаёт в поле окна «Импорт SQL»: тот же разбор, сводка, автораскладка и отмена |
| Запрос | поля `host`, `port`, `database`, `user`, `password`, `schema`, `sslMode`; строку JDBC `backend` не принимает, URL и свойства драйвера строит сам из белого списка |
| Адреса | имя из списка — доверенное; иначе каждый адрес хоста — в разрешённой сети; подключение — по проверенному адресу (`PinnedSocketFactory`); loopback, link-local, multicast и адрес базы CoDraw — только записью внутри их диапазона |
| Ограничения | соединение 5 с, ответ 20 с, `statement_timeout` 15 с, только чтение, одно соединение без пула, 500 таблиц, 2 МБ DDL, 30 попыток в час на пользователя, только вошедшие не гостями |
| Учётные данные | не хранятся, не пишутся в журнал, метрики и ответы; ошибки — общие категории без текста исключений |

## Обоснование

- Дамп не требует от CoDraw ни сетевого доступа, ни паролей: утилита запускается там, где у пользователя уже есть
  доступ к базе, а файл открывается в браузере. Поэтому он — основной путь и замена отдельной CLI-утилите выгрузки:
  `pg_dump` и `mysqldump` есть везде, где есть база, и их вывод теперь разбирается без потерь.
- Подключение через `backend` удобнее там, где базы доступны из сети установки (внутренний CoDraw команды), и опасно
  там, где не продумано. Поэтому оно включается только явным списком адресов: без списка endpoint отвечает 404, а
  администратор, который его задаёт, решает, к каким базам `backend` может ходить.
- Строку JDBC принимать нельзя: параметры PgJDBC вроде `socketFactory`, `sslfactory`, `sslhostnameverifier`,
  `loggerFile` исторически давали выполнение кода и запись файлов (CVE-2022-21724 и родственные), а `service` и
  отсутствие пароля читают файлы `~/.pg_service.conf` и `~/.pgpass` самого `backend`. Поля и белый список свойств
  закрывают это целиком.
- Проверка адресов должна выдерживать DNS rebinding: имя, которое при проверке ведёт в разрешённую сеть, а при
  подключении — на `127.0.0.1` или в метаданные облака. Подключение по проверенному адресу (свой `SocketFactory`,
  который драйвер получает от `backend`, а не из запроса) делает второе разрешение имени неважным; имя остаётся в
  URL для SNI и проверки сертификата при `verify-full`.
- Широкая сеть в списке (`10.0.0.0/8`, по ошибке `0.0.0.0/0`) не должна открывать loopback, link-local с адресом
  метаданных облака и базу самого CoDraw: их открывает только запись, явно направленная на них.
- Общие категории ошибок («не удалось подключиться» одинаково для отказа, молчания, чужого протокола, SSL и имени)
  не дают по ответам и тексту различать закрытые и фильтруемые порты; предел попыток на пользователя и запрет гостям,
  которых можно создавать без входа, ограничивают перебор.
- DDL вместо JSON-модели: один разборщик на файлы, вставку и базу, пользователь видит, что пришло, и может поправить
  текст до добавления.

Отклонённые альтернативы:

- **Подключение для всех без списка адресов** — SSRF во внутреннюю сеть установки по умолчанию.
- **CLI-утилита CoDraw для выгрузки схемы в файл** — ещё один артефакт сборки и выпуска ради того, что делают
  `pg_dump` и `mysqldump`.
- **MySQL и MariaDB живьём** — драйвер MySQL Connector/J под GPL с исключением для FOSS (лицензия, которую нужно
  отдельно оценивать для образа), около 2,5 МБ ради функции, которая для MySQL уже есть дампом; MariaDB Connector/J
  (LGPL) — ещё одна зависимость с собственными опасными параметрами URL. Можно добавить позже тем же контроллером и
  проверкой адресов, если будет спрос.
- **Хранение подключений для повторного чтения** — пароли баз в базе CoDraw; повторить ввод дешевле, чем охранять
  их.
- **Чтение через `information_schema`** — в нём нет индексов, а определения ограничений пришлось бы собирать заново;
  `pg_catalog` с `pg_get_constraintdef` и `pg_get_indexdef` даёт текст, как у `pg_dump`.

## Последствия

- Без настройки ничего не меняется: «Подключиться к базе…» не видно, endpoint отвечает 404.
- Включённая функция — сетевой доступ `backend` к перечисленным базам: администратор отвечает за список и за сеть
  контейнера; `docs/deploy.md` советует перечислять конкретные базы и выдавать пользователям отдельную роль без прав
  на данные — для чтения каталога права не нужны.
- Пароль базы проходит через `backend` в теле запроса по HTTPS установки и не сохраняется; политика
  конфиденциальности говорит об этом, когда функция включена.
- В журнале `backend` — строка о каждой попытке с пользователем CoDraw, адресом сервера базы и результатом, в
  метриках — `codraw_schema_imports_total{result}` и `codraw_limits_reached_total{limit="schema-imports"}`.
- `verify-full` проверяет сертификат базы доверенными центрами JVM: сертификат своего центра требует добавить его в
  хранилище доверенных `backend`.
- Драйвер PostgreSQL становится зависимостью компиляции `backend`, не только выполнения.
