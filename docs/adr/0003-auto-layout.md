# ADR-0003: Автоматическая раскладка

- **Статус:** принято
- **Дата:** 2026-10-05

## Контекст

Схемы из шаблонов, вставленные из draw.io и собранные наспех, а дальше — импортированные из SQL и Mermaid, где у фигур
нет своих мест, нужно расставлять автоматически. Схемы CoDraw — графы архитектуры и ER: направленные связи, таблицы,
группы и рамки (граница C4, кластер Kubernetes), которые держат фигуры по координатам. Раскладка идёт в браузере:
результат — обычная правка документа Yjs, один шаг отмены.

## Решение

| Что | Выбор |
|---|---|
| Алгоритм | ELK Layered (Sugiyama): слои по связям, минимум пересечений, составные узлы для рамок |
| Библиотека | `elkjs` 0.12 — ELK, собранный в JavaScript, без изменений |
| Загрузка | `import('elkjs/lib/elk.bundled.js')` при первой раскладке, отдельным чанком; расчёт в основном потоке |

## Обоснование

- ELK — исследовательский и промышленный стандарт раскладки графов (Eclipse); `elkjs` использует, например, Mermaid.
  Layered с `hierarchyHandling: INCLUDE_CHILDREN` раскладывает фигуры внутри рамок вместе со связями между рамками.
- Отдельный чанк не утяжеляет открытие доски: 1,4 МБ (около 440 КБ gzip) в сборке грузятся, только когда участник раскладывает.
- Расчёт для 500 фигур — около 0,7 с; для схем, которые рисуют руками, — десятки миллисекунд, поэтому Web Worker пока
  не нужен.

Отклонённые альтернативы:

- **`@dagrejs/dagre`** (MIT, 30 КБ) — тоже слои, но составные узлы слабые, развитие почти остановилось.
- **Раскладки maxGraph** (`HierarchicalLayout`, `CompactTreeLayout`) — алгоритмы mxGraph из draw.io, без рамок по
  координатам и заметно хуже по пересечениям.
- **Свой алгоритм** — месяцы работы ради того, что ELK уже делает.

## Последствия

- Новая зависимость `elkjs` под EPL-2.0 (или GPL-3.0-or-later): используется без изменений как пакет npm. Изменения
  в самой ELK пришлось бы публиковать под EPL-2.0.
- Маршруты связей прокладывает maxGraph: изгибы ELK не переносятся, ручные изгибы между разложенными фигурами
  убираются.
- Перенос расчёта в Web Worker и другие алгоритмы ELK (дерево, силовой) — без смены библиотеки.
