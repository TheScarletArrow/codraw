# Системные требования

Что нужно серверу установки CoDraw, устройству пользователя и машине разработчика. Цифры сервера — из
[нагрузочных тестов](load-testing.md), как развернуть — в [docs/deploy.md](deploy.md), как запустить локально — в
[docs/running.md](running.md).

## Коротко

| | Пробная установка | До 100 одновременно открытых досок | До 300 досок |
|---|---|---|---|
| Процессор | 2 vCPU x86-64 | 2 vCPU от 2,1 ГГц, полные ядра | 4 vCPU от 2,1 ГГц |
| Память | 2 ГБ | 4 ГБ | 8 ГБ |
| Диск | SSD от 20 ГБ | SSD или NVMe, 40–50 ГБ для начала | по формуле в разделе «Диск» |
| Система | Linux с Docker Engine и Docker Compose v2 | то же | то же |
| Сеть | порт 8080 по HTTP | домен, HTTPS на 443, S3 вне сервера для резервных копий | то же |

Доска здесь — открытая доска с 2–3 активными участниками. Больше 300 таких досок один процесс `collab` не держит
([#173](https://github.com/TheScarletArrow/codraw/issues/173)).

Пользователям нужен Chrome, Edge или Яндекс Браузер 111+, Firefox 128+ или Safari 16.4+ — подробнее в разделе
«Устройство пользователя».

## Сервер

### Процессор

- **Архитектура x86-64 (amd64).** CI публикует образы только для неё. На ARM64 образы придётся собрать на самом
  сервере (`docker compose -f docker-compose.prod.yml build`); CI такую сборку не проверяет.
- **Частота ядра важнее числа ядер.** Правки и курсоры всех досок `collab` обслуживает один поток Node.js, поэтому
  установку ограничивает одно ядро. Цифры таблицы сняты на ядре Xeon 2,1 ГГц; ядро медленнее даст пропорционально
  меньше досок. Держите `collab` ниже ~70 % ядра в часы пик: правило `CodrawCollabBusy` предупредит.
- **Полные ядра, а не доли.** Тарифы, где за машиной закреплено 10–30 % ядра (shared, burstable), не подходят: `collab`
  под нагрузкой занимает большую часть ядра, а `backend`, PostgreSQL и nginx — часть второго.
- **Не меньше 2 vCPU.** Одно ядро забирает `collab`, остальным сервисам нужно второе.

### Память

| Сервис | Сколько заложить |
|---|---|
| `collab` | 1,5 ГБ: 250–400 МиБ на 100–200 досок, ~650 МиБ на 300–400 и около 200 МиБ на каждую открытую доску у предела размера |
| `backend` (JVM) | берёт до 75 % памяти контейнера; на стенде без ограничений — 0,9–1,1 ГБ, на сервере с 2 ГБ обходится меньшим |
| PostgreSQL | 130–200 МиБ |
| nginx (`frontend`), RustFS (`s3`), `backup`, Prometheus и Alertmanager (`--profile monitoring`) | нагрузочные тесты их не мерили; оставьте запас в несколько сотен МиБ |

Итого 2 ГБ хватает на десятки досок, 4 ГБ — на сотни. Если обычны доски у предела 16 МиБ, а памяти мало, опустите
`DOCUMENT_SIZE_LIMIT_BYTES` до 8 МиБ.

### Диск

SSD или NVMe: PostgreSQL пишет документы досок при каждом сохранении. Место складывается так:

```
место ≈ 10 ГБ (система и образы)
      + данные (база + картинки)
      × (1 + CODRAW_BACKUP_KEEP_DAILY + CODRAW_BACKUP_KEEP_WEEKLY)
```

- По умолчанию на сервере хранится до 7 + 4 = 11 архивов копий, каждый — вся база и все картинки. При 2 ГБ данных
  это ~2 + 22 + 10 = 34 ГБ. Копии можно держать на отдельном диске: `CODRAW_BACKUP_VOLUME=/mnt/backups`.
- Верхние пределы одной доски: документ — 16 МБ, версии — до 64 МБ вместе, картинки — до 100 МБ; у пользователя — до
  100 досок.
- Prometheus хранит метрики 15 дней (срок по умолчанию).
- Размер последнего архива показывает метрика `codraw_backup_last_size_bytes`: по ней видно, когда расширять диск.

### Программы

- **Linux с Docker Engine и Docker Compose v2** (`docker compose version`), например Ubuntu 24.04 LTS или Debian 12.
  Всё остальное приходит в образах: PostgreSQL 18, RustFS 1.0, JRE 25, Node.js 24, nginx 1.31. На сервере не
  нужны ни Java, ни Node.js.
- **TLS-прокси**, например Caddy. Он должен:
  - передавать исходный `Host` и `X-Forwarded-Proto: https`, а на порту, отличном от 443, ещё и `X-Forwarded-Port`;
  - проксировать WebSocket (`Upgrade`) и держать соединение `/collab` не меньше часа без данных;
  - пропускать тела запросов до 32 МБ: так велики версии доски. Если прокси — nginx, задайте
    `client_max_body_size 32m`: по умолчанию он пропускает 1 МБ.

### Сеть

**Домен и HTTPS обязательны для рабочей установки.** Google принимает адрес возврата OAuth только по HTTPS (кроме
`localhost`), cookie сеанса получает флаг `Secure` только за TLS-прокси, а буфер обмена браузер даёт только защищённым
страницам. По `http://<сервер>:8080` приложение открывается — этого хватает, чтобы проверить запуск.

Входящие порты:

| Порт | Зачем |
|---|---|
| 443 | приложение, API и синхронизация (WebSocket) по одному адресу |
| 80 | выпуск сертификата Let's Encrypt и переадресация на HTTPS |
| 22 | SSH для администратора |

Порт приложения откройте только на самом сервере: `CODRAW_HTTP_PORT=127.0.0.1:8080`. Иначе Docker откроет его наружу в
обход ufw. Prometheus (9090) и Alertmanager (9093) и так слушают только `127.0.0.1`.

Исходящие соединения сервера:

| Куда | Когда нужно |
|---|---|
| `ghcr.io` (образы CoDraw) и Docker Hub (`postgres`, `rustfs`, `prom/*`) | при установке и обновлении; если реестры недоступны — зеркало Docker Hub и свой реестр через `CODRAW_IMAGE_PREFIX` |
| Let's Encrypt | выпуск и продление сертификата прокси |
| GitHub и Google | вход через них; GitHub — и для «Задач GitHub» (`CODRAW_ISSUES_GITHUB_API_URL`) |
| провайдер OpenID Connect | корпоративный вход (`CODRAW_OIDC_ISSUER_URI`) |
| SMTP-сервер, порт 587 или 465 | письма уведомлений и оповещения на почту (`CODRAW_SMTP_*`) |
| чаты Slack, Mattermost, Rocket.Chat | уведомления (`CODRAW_WEBHOOK_ALLOWED_HOSTS`) и оповещения (`CODRAW_ALERT_CHAT_WEBHOOK_URL`) |
| S3-хранилище | копии вне сервера (`CODRAW_BACKUP_S3_ENDPOINT`), внешнее хранилище картинок (`CODRAW_IMAGES_S3_ENDPOINT`) |
| Telegram Bot API | оповещения в Telegram (`api.telegram.org` или `CODRAW_ALERT_TELEGRAM_API_URL`) |
| внешний сторож | `CODRAW_ALERT_WATCHDOG_URL`, POST раз в 5 минут |
| базы PostgreSQL пользователей | «Подключиться к базе…» (`CODRAW_SCHEMA_IMPORT_ALLOWED_HOSTS`) |

Обязательны только реестры образов и Let's Encrypt, остальное — для включённых функций.

## Устройство пользователя

### Браузер

| Браузер | Версия |
|---|---|
| Chrome, Edge, Яндекс Браузер, Opera и другие на Chromium | 111 и новее |
| Firefox | 128 и новее |
| Safari на macOS, iOS и iPadOS | 16.4 и новее; на iPhone и iPad любой браузер работает на движке Safari |

Нижняя граница — от Tailwind CSS 4 (Chrome 111, Safari 16.4, Firefox 128) и цели сборки Vite 8: старые браузеры
не покажут интерфейс. Сквозные тесты Playwright идут в Chromium, остальные браузеры CI не проверяет.

Браузеру нужны:

- JavaScript, cookie сайта (сеанс входа, сеанс гостя — 30 дней), `localStorage` и IndexedDB. В IndexedDB лежат копии
  досок для работы без связи, в `localStorage` — тема, язык и порядок списка досок. Приватное окно стирает их при
  закрытии.
- WebSocket (`wss://<адрес>/collab`) — постоянное соединение синхронизации. Корпоративный прокси или антивирус,
  который рвёт WebSocket, оставит доску в состоянии «Нет связи».
- WebAssembly и Web Workers — для маршрутов связей в обход фигур; они есть во всех браузерах из таблицы.

### Экран и ввод

- **Полная правка** — компьютер с мышью или тачпадом и клавиатурой. Окно от 1024 px показывает всё. Уже 1024 px файлы,
  экспорт и панель правки уходят в «Инструменты», уже 768 px палитра фигур — за кнопку «Фигуры».
- **Телефоны и планшеты** — просмотр, перемещение и масштаб пальцами, комментарии. Правка на касание не подстроена:
  фигуры двигаются и подписи правятся так, как это даёт maxGraph.

### Сеть

- HTTPS до адреса установки, включая WebSocket `/collab`.
- Аватары пользователей GitHub и Google браузер загружает с их серверов.
- Без сети работает только уже открытая доска: правки ложатся в копию на устройстве и уходят, когда связь вернётся.
  Само приложение и список досок без сети не открываются.

## Машина разработчика

| Инструмент | Версия | Зачем |
|---|---|---|
| JDK | 25, любой дистрибутив | `backend` |
| Node.js | 22.12 и новее; рекомендуется версия из `.nvmrc` (24) | `frontend`, `collab`, сквозные и нагрузочные тесты |
| pnpm | 10, через `corepack enable` | зависимости JS-подпроектов |
| Docker с Compose v2 | актуальная | PostgreSQL и хранилище картинок для запуска; Testcontainers в тестах `backend` |
| Git | любая | код |

Gradle ставить не нужно: его скачивает `./gradlew`. Порты, проверки на каждом шаге и частые проблемы — в
[docs/running.md](running.md).
