# yandex-vk-sign-in Specification

## Purpose
Позволяет установке CoDraw для российской аудитории пускать пользователей через их учётные записи Яндекс ID и VK ID,
настроив только приложения этих провайдеров, — вместо или вместе с GitHub и Google.

## Requirements

### Requirement: Включение Яндекс ID и VK ID

Оператор SHALL включать вход через Яндекс ID, задав client id и secret приложения Яндекс OAuth, и вход через VK ID,
задав id приложения VK ID. Провайдер без client id (или с `not-configured`) MUST NOT появляться на странице входа и
MUST NOT принимать вход. Адреса провайдеров SHALL быть настройками `backend` со значениями по умолчанию
`oauth.yandex.ru`, `login.yandex.ru` и `id.vk.ru`.

#### Scenario: Оба провайдера настроены

- **WHEN** оператор задал `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` и `VK_CLIENT_ID`
- **THEN** на странице входа есть кнопки «Войти через Яндекс ID» и «Войти через VK ID», а `GET /api/auth/providers`
  содержит `yandex` с названием «Яндекс ID» и `vk` с названием «VK ID»

#### Scenario: Провайдер не настроен

- **WHEN** оператор не задал `VK_CLIENT_ID`, и браузер открывает `/api/oauth2/authorization/vk`
- **THEN** кнопки VK ID нет, а браузер возвращается на `/login?error`

### Requirement: Вход через Яндекс ID

Вход через Яндекс ID SHALL идти по коду авторизации с правами только `login:info` и `login:avatar`, без почты.
`backend` SHALL передавать секрет приложения в теле обмена кода и читать профиль `login.yandex.ru/info` с заголовком
`Authorization: OAuth <токен>`. Имя пользователя SHALL браться из `real_name`, а без него — из `display_name`, логина
или id; аватар — `https://avatars.yandex.net/get-yapic/<default_avatar_id>/islands-200`, если портрет есть.

#### Scenario: Первый вход через Яндекс ID

- **WHEN** пользователь Яндекса с id `1130000012345678`, именем «Иван Петров» и портретом входит через Яндекс ID
- **THEN** он возвращается в CoDraw вошедшим, учётная запись `yandex` с id `1130000012345678` создана, в шапке — «Иван
  Петров» и его портрет

#### Scenario: Без портрета

- **WHEN** у пользователя Яндекса `is_avatar_empty` равно `true`
- **THEN** у учётной записи нет аватара

#### Scenario: Запрошенные права

- **WHEN** браузер начинает вход через Яндекс ID
- **THEN** адрес авторизации Яндекса запрашивает `scope` = `login:info login:avatar`

### Requirement: Вход через VK ID

Вход через VK ID SHALL идти по коду авторизации OAuth 2.1 с PKCE (S256) без секрета приложения и правом
`vkid.personal_info`. `state` SHALL состоять не меньше чем из 32 символов из латинских букв, цифр, `_` и `-`.

#### Scenario: Запрос авторизации VK ID

- **WHEN** браузер открывает `/api/oauth2/authorization/vk`
- **THEN** он уходит на `https://id.vk.ru/authorize` с `code_challenge`, `code_challenge_method=S256`,
  `scope=vkid.personal_info` и `state` без символов кроме букв, цифр, `_` и `-`

### Requirement: Обмен кода и профиль VK ID

Обмен кода VK ID SHALL передавать `device_id` из обратного вызова VK ID, `state` запроса авторизации, `client_id` и
`code_verifier`. Профиль SHALL читаться `POST`-запросом `/oauth2/user_info` с `client_id` и токеном из поля `user`
ответа: имя — имя и фамилия, аватар — `avatar`. Ответ VK ID без профиля SHALL возвращать пользователя на страницу входа
с ошибкой.

#### Scenario: Первый вход через VK ID

- **WHEN** пользователь VK с `user_id` `1234567`, именем «Анна» и фамилией «Смирнова» входит через VK ID
- **THEN** он возвращается в CoDraw вошедшим, учётная запись `vk` с id `1234567` создана, а в шапке — «Анна Смирнова»
  и её аватар

#### Scenario: Обратный вызов без device_id

- **WHEN** обратный вызов VK ID пришёл без `device_id`, и VK ID отказал в обмене кода
- **THEN** пользователь возвращается на `/login?error`, а учётная запись не создаётся

### Requirement: Учётная запись Яндекс ID и VK ID

Учётная запись SHALL определяться провайдером (`yandex` или `vk`) и id пользователя у него; повторный вход SHALL
находить ту же учётную запись и обновлять имя и аватар. Пол, дата рождения, логин и почта MUST NOT храниться. Гость,
который входит так, SHALL получать свои доски, а заблокированный пользователь SHALL NOT входить — как при входе через
GitHub.

#### Scenario: Повторный вход

- **WHEN** пользователь VK ID уже входил, затем сменил фамилию в VK и входит снова
- **THEN** он попадает в ту же учётную запись со своими досками, а имя обновляется

#### Scenario: Одинаковый id у разных провайдеров

- **WHEN** у пользователей Яндекс ID и VK ID одинаковый id, и оба входят
- **THEN** у них разные учётные записи
