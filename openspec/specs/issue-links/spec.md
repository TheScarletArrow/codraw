# issue-links Specification

## Purpose
Связывает элементы схемы и ветки обсуждений с задачами GitHub: привязка существующих задач, создание задачи со ссылкой
обратно на доску, показ номера, названия и статуса и обновление статуса из GitHub.

## Requirements

### Requirement: Подключение GitHub

Пользователь, вошедший через GitHub или Google, SHALL подключать GitHub на странице «Подключения»
(`/settings/connections`) личным токеном. `backend` SHALL сохранять токен, только если GitHub принимает его, вместе с
именем учётной записи, иначе отвечать 400 `invalid-token`. API SHALL не возвращать токен, `backend` SHALL не писать его в
журнал и метрики. «Отключить» SHALL забывать токен. Гость SHALL получать 403 `guest`.

#### Scenario: Подключение

- **WHEN** пользователь вставляет токен, который GitHub принимает, и нажимает «Подключить»
- **THEN** страница показывает «Подключено» и учётную запись GitHub, поле токена пусто, а ответ настроек токена не
  содержит

### Requirement: Отвергнутый токен

Отказ GitHub в токене (401) при любом запросе SHALL помечать подключение неработающим, и такой токен SHALL не уходить
в GitHub, пока пользователь не введёт новый. Страница «Подключения» SHALL говорить, что GitHub больше не принимает токен,
а формы задач — предлагать подключить GitHub заново.

#### Scenario: Отозванный токен

- **WHEN** пользователь отозвал токен в GitHub, и CoDraw обращается к GitHub с ним
- **THEN** подключение помечается неработающим, а следующие запросы в GitHub с этим токеном не уходят

### Requirement: Адрес API GitHub

`backend` SHALL отправлять токены только на `codraw.issues.github.api-url` (по умолчанию `https://api.github.com`, для
GitHub Enterprise Server — его API) и идти по перенаправлениям только в его пределах. Без адреса задачи SHALL быть
выключены: настройки говорят `available: false`, остальные запросы задач — 404 `tracker-off`.

#### Scenario: Перенаправление за пределы API

- **WHEN** API GitHub отвечает перенаправлением на другой хост
- **THEN** `backend` не идёт по нему и не отправляет туда токен

### Requirement: Привязка задачи

Участник SHALL привязывать к элементу (фигуре, таблице, связи, группе) или к ветке комментариев задачу GitHub, до
которой дотягивается его токен: по номеру в репозитории, ссылке на задачу, `owner/name#N` или из поиска по словам в
выбранном репозитории, и только в нём. Pull request SHALL давать 400 `not-an-issue`, недоступная задача — 404
`not-found`. Повторная привязка той же задачи к той же цели SHALL обновлять существующую привязку (200).

#### Scenario: Повторная привязка

- **WHEN** ту же задачу привязывают к тому же элементу второй раз
- **THEN** привязка одна, ответ 200, а её название и статус — как сейчас в GitHub

### Requirement: Права на привязку

К элементу SHALL привязывать задачи владелец и редакторы доски, к ветке — все, кто может открыть доску. Без своего
подключения SHALL быть 409 `not-connected`. Доска SHALL хранить не больше `codraw.limits.issue-links-per-board`
привязок; сверх — 409 с пределом и рост `codraw_limits_reached_total{limit="issue-links"}`.

#### Scenario: Читатель и элемент

- **WHEN** участник в режиме «Просмотр» привязывает задачу к элементу
- **THEN** ответ 403, и привязки нет; к ветке он задачу привязать может

### Requirement: Предупреждение о раскрытии

Перед привязкой форма SHALL показывать название и статус задачи и говорить, что номер, название и статус увидят все,
кто может открыть доску, а для задачи закрытого репозитория — что репозиторий закрытый.

#### Scenario: Закрытый репозиторий

- **WHEN** редактор находит по ссылке задачу закрытого репозитория
- **THEN** форма предупреждает, что репозиторий закрытый и задачу увидят все, кто может открыть доску

### Requirement: Создание задачи

Участник, который может привязать задачу к цели, SHALL создавать задачу GitHub с названием от 1 до 256 символов и
описанием до 20 000 символов. `backend` SHALL дописывать в конец описания ссылку на элемент
(`/boards/{id}?page=…&cell=…`) с его подписью и названием доски или на ветку (`/boards/{id}?thread=…`) и привязывать
задачу к цели. Подпись и название SHALL не давать в задаче разметки, ссылок и упоминаний.

#### Scenario: Задача из элемента

- **WHEN** редактор в «Создать задачу» элемента «API» пишет описание «Нужен Redis» и нажимает «Создать в GitHub»
- **THEN** в GitHub появляется задача «API» с описанием и ссылкой на элемент, а у элемента — привязка к ней

### Requirement: Повтор создания

Запрос создания SHALL нести `requestId` клиента. Повтор с тем же `requestId` SHALL не создавать второй задачи, а
получать ту же привязку (200); пока первый запрос создаёт задачу — 409 `creation-in-progress`. Неудачный запрос SHALL
разрешать повтор. Токен без права записи SHALL давать 409 `tracker-forbidden`.

#### Scenario: Повтор после обрыва

- **WHEN** ответ на создание задачи потерялся, и браузер отправляет ту же форму ещё раз
- **THEN** в GitHub одна задача, а ответ — её привязка

### Requirement: Задачи на доске

Привязки доски SHALL видеть все, кому доступна доска, в том числе в режиме «Просмотр». Панель «Задачи элемента» SHALL
показывать у задачи значок и словами статус («Открыта», «Закрыта: выполнена», «Закрыта: не планируется», «Закрыта:
дубликат»), название ссылкой на задачу в GitHub — только адрес `http` или `https`, — `owner/name#N` и замок у закрытого
репозитория.

#### Scenario: Закрытая задача в панели

- **WHEN** участник открывает «Задачи…» элемента с задачей, закрытой как не планируемая
- **THEN** панель показывает «Закрыта: не планируется», а щелчок по названию открывает задачу в GitHub

### Requirement: Значок задач элемента

У элемента с задачами на холсте SHALL быть значок с их числом под левым нижним углом: зелёный, пока есть открытые,
фиолетовый, когда все закрыты. Щелчок по значку SHALL открывать панель задач элемента.

#### Scenario: Значок элемента

- **WHEN** к элементу привязаны открытая и закрытая задачи
- **THEN** у элемента зелёный значок «2», а щелчок по нему открывает панель с обеими задачами

### Requirement: Отвязка задачи

Отвязка SHALL удалять только привязку, не задачу в GitHub: у элемента — владелец и редакторы, у ветки — ещё и
привязавший. Изменение привязок SHALL сообщаться остальным участникам сообщением `issues-changed`, и они перечитывают
привязки.

#### Scenario: Отвязка в ветке

- **WHEN** участник в режиме «Просмотр» отвязывает задачу, которую сам привязал к ветке
- **THEN** привязка удаляется у всех участников, а задача остаётся в GitHub

### Requirement: Обновление статуса при показе

Статус SHALL идти только из GitHub в CoDraw, и интерфейс SHALL говорить это словами. Привязку, которую показывают и
которую не обновляли дольше 5 минут, и по кнопке «Обновить из GitHub» `backend` SHALL обновлять токеном привязавшего,
не чаще раза в минуту на привязку, не больше 20 привязок за запрос. Перенесённая задача SHALL оставаться привязанной под
новым репозиторием и номером.

#### Scenario: Закрытая задача

- **WHEN** задачу закрыли в GitHub, и участник открывает панель элемента позже чем через 5 минут после обновления
- **THEN** панель показывает «Закрыта: выполнена», а остальные участники получают `issues-changed`

### Requirement: Вебхук задач

С `codraw.issues.github.webhook-secret` `POST /api/integrations/github/webhook` SHALL принимать события «Issues» без
сеанса и CSRF, только с подписью `X-Hub-Signature-256` этим секретом, иначе 401; без секрета — 404. Событие SHALL менять
только уже привязанные задачи и только если `updated_at` задачи не старше известного: повторное и запоздавшее событие
ничего не меняют. Событие удаления SHALL помечать привязку удалённой, переноса — переносить её на новую задачу.

#### Scenario: Повтор события

- **WHEN** GitHub повторно присылает событие о закрытии задачи, а затем запоздавшее событие о её правке до закрытия
- **THEN** привязка остаётся закрытой с последним названием

### Requirement: Потеря доступа и удаление

Привязка SHALL сохранять последнее известное состояние и говорить, почему оно может быть устаревшим: «Задача удалена в
GitHub» (410), «Нет доступа» — задачи нет или токен привязавшего до неё не дотягивается (404, 403), «Не обновляется» — у
привязавшего нет работающего подключения или его удалили. Удалённую задачу и привязку без подключения SHALL не
обновлять автоматически.

#### Scenario: Привязавший отключился

- **WHEN** участник, привязавший задачу, отключает GitHub
- **THEN** привязка остаётся с прежним статусом и пометкой «Не обновляется», и CoDraw больше не обращается за ней в GitHub

### Requirement: Передача привязки

Участник, который может привязать задачу к цели и у которого работает подключение, SHALL делать привязку своей кнопкой
«Обновлять через моё подключение»; его токен должен дотягиваться до задачи. После этого привязку SHALL обновлять его
токен. Без этого действия чужой токен SHALL не использоваться.

#### Scenario: Задача другого редактора

- **WHEN** привязка помечена «Не обновляется», и другой редактор с подключением нажимает «Обновлять через моё
  подключение»
- **THEN** привязка показывает актуальный статус и его имя как привязавшего
