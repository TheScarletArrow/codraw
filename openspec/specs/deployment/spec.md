# deployment Specification

## Purpose
Позволяет развернуть CoDraw на сервере из готовых образов: приложение, API и синхронизация работают с одного
адреса, за TLS-прокси, с заголовками безопасности, а образы собираются, публикуются и выкатываются на сервер автоматически.

## Requirements

### Requirement: Образы сервисов

Репозиторий SHALL собирать из исходников образы `backend`, `collab` и `frontend`. Процесс в каждом образе SHALL
работать не от root, а образ SHALL объявлять проверку работоспособности, по которой Docker отмечает контейнер
`healthy`.

#### Scenario: Сборка образов

- **WHEN** образы собираются из чистой копии репозитория без заранее собранных файлов
- **THEN** сборка проходит, и каждый образ запускает свой сервис от непривилегированного пользователя

#### Scenario: Контейнер готов

- **WHEN** контейнер сервиса запущен, а сервис готов принимать запросы
- **THEN** Docker отмечает контейнер как `healthy`

### Requirement: Единый адрес приложения

Контейнер `frontend` SHALL отдавать приложение и с того же адреса передавать запросы `/api/` в `backend`,
а WebSocket-подключения `/collab` — в `collab`. Путь, которому не соответствует файл сборки, SHALL открывать
приложение. Внутренний API `backend` и его служебные эндпоинты SHALL быть недоступны через этот адрес.

#### Scenario: Глубокая ссылка

- **WHEN** браузер открывает `/boards/{id}` на адресе приложения
- **THEN** ответ — страница приложения, и оно открывает доску

#### Scenario: Совместная работа через адрес приложения

- **WHEN** два пользователя открывают одну доску через адрес приложения, и один добавляет фигуру
- **THEN** второй видит фигуру, и оба видят статус «Синхронизировано»

#### Scenario: Внутренний API закрыт

- **WHEN** клиент запрашивает `/internal/boards/{id}/document` или `/actuator/health` на адресе приложения
- **THEN** ответ имеет статус 404, и запрос не доходит до `backend`

### Requirement: Заголовки безопасности

Ответы с приложением SHALL содержать `Content-Security-Policy`, которая разрешает скрипты, стили, подключения
и шрифты только с адреса приложения и компиляцию WebAssembly из них (`'wasm-unsafe-eval'`), а также
`X-Content-Type-Options: nosniff`, `Referrer-Policy` и запрет показа во фрейме. Приложение SHALL работать с этой
политикой без её нарушений. Файлы сборки с хешем в имени SHALL кешироваться браузером на год, а страница приложения
и файл версии сборки `/version.json` SHALL проверяться при каждом запросе.

#### Scenario: Политика не мешает приложению

- **WHEN** пользователь входит, создаёт доску, добавляет фигуры, связывает таблицы и работает вместе с другим участником
- **THEN** браузер не сообщает о нарушениях Content Security Policy, и связи прокладываются в обход фигур

#### Scenario: Кеширование

- **WHEN** браузер запрашивает страницу приложения и файл сборки из `/assets/`
- **THEN** страница приходит с `Cache-Control: no-cache`, а файл — с `max-age` в год и `immutable`

#### Scenario: Файл версии не кешируется

- **WHEN** браузер запрашивает `/version.json`
- **THEN** ответ — JSON с `Cache-Control: no-cache`, а не страница приложения

### Requirement: Работа за TLS-прокси

Когда перед приложением стоит прокси, который завершает TLS и передаёт `X-Forwarded-Proto` и исходный `Host`,
`backend` SHALL строить адреса возврата OAuth по схеме и адресу, которые видит пользователь, и выдавать cookie
сеанса с признаком `Secure`. Без такого прокси адрес возврата SHALL содержать порт, на котором открыто приложение.

#### Scenario: Вход через провайдера по https

- **WHEN** пользователь открывает `https://codraw.example.com` за TLS-прокси и нажимает «Войти через GitHub»
- **THEN** адрес возврата в запросе к GitHub — `https://codraw.example.com/api/login/oauth2/code/github`

#### Scenario: Вход без прокси на нестандартном порту

- **WHEN** пользователь открывает приложение по `http://<сервер>:8080` без TLS-прокси и нажимает «Войти через GitHub»
- **THEN** адрес возврата в запросе к GitHub — `http://<сервер>:8080/api/login/oauth2/code/github`

#### Scenario: Cookie сеанса по https

- **WHEN** пользователь за TLS-прокси продолжает без входа
- **THEN** cookie сеанса выдаётся с признаком `Secure`

### Requirement: Запуск стека одной командой

Продакшен-конфигурация Docker Compose SHALL поднимать PostgreSQL, S3-совместимое хранилище изображений, `backend`,
`collab` и `frontend` в порядке зависимостей, хранить данные PostgreSQL и хранилища в томах и открывать наружу только
порт приложения. Без пароля базы, секретного ключа хранилища, общего секрета внутреннего API или ключа подписи токенов
синхронизации конфигурация SHALL отказываться запускаться.

#### Scenario: Запуск

- **WHEN** администратор задаёт обязательные переменные и запускает конфигурацию
- **THEN** все пять контейнеров становятся `healthy`, приложение открывается на порту приложения, а порты
  PostgreSQL, хранилища, `backend` и `collab` снаружи недоступны

#### Scenario: Нет обязательного секрета

- **WHEN** администратор запускает конфигурацию без `CODRAW_COLLAB_TOKEN_SIGNING_KEY`
- **THEN** Docker Compose отказывается запускать стек и называет недостающую переменную

#### Scenario: Данные переживают пересоздание контейнеров

- **WHEN** администратор пересоздаёт контейнеры, например при обновлении образов
- **THEN** доски, пользователи и картинки досок остаются

### Requirement: Публикация образов

CI SHALL при каждом пуше собирать три образа, поднимать из них стек и проверять его в браузере через адрес
приложения. При пуше в `main` CI SHALL публиковать проверенные образы в GitHub Container Registry с тегом коммита,
а тег `latest` SHALL ставить на них только после того, как прошли все проверки CI этого коммита.

#### Scenario: Пуш в ветку

- **WHEN** в ветку, отличную от `main`, пушат коммит
- **THEN** CI собирает и проверяет образы, но не публикует их

#### Scenario: Пуш в main

- **WHEN** в `main` пушат коммит, и все проверки CI прошли
- **THEN** в GitHub Container Registry появляются образы `codraw-backend`, `codraw-collab` и `codraw-frontend`
  с тегами `latest` и коммита

#### Scenario: Пуш в main с упавшими тестами

- **WHEN** в `main` пушат коммит, проверка стека прошла, а тесты упали
- **THEN** `latest` указывает на прежние образы

### Requirement: Хранилище изображений

`backend` SHALL хранить картинки досок в S3-совместимом хранилище, адрес, регион, бакет и ключи доступа которого
задаются переменными окружения, обращаясь к нему с путём бакета в адресе (path-style), и SHALL создавать бакет, если его
нет. Недоступное хранилище SHALL NOT мешать `backend` запуститься и работать с досками; загрузка и отдача картинок тогда
SHALL отвечать 503. Хранилище SHALL быть доступно только `backend`, а браузеры SHALL получать картинки через `backend`.

#### Scenario: Пустое хранилище

- **WHEN** `backend` запускается с хранилищем, в котором нет бакета
- **THEN** бакет создаётся, и первая загруженная картинка сохраняется

#### Scenario: Хранилище недоступно

- **WHEN** хранилище остановлено, и участник открывает доску и добавляет фигуру
- **THEN** доска работает, а загрузка картинки отвечает 503

### Requirement: Почта и чаты для уведомлений

Стек `docker-compose.prod.yml` SHALL передавать `backend` из переменных окружения адрес приложения для ссылок в
сообщениях (`CODRAW_APP_URL`), SMTP-сервер (`CODRAW_SMTP_HOST`, `CODRAW_SMTP_PORT`, `CODRAW_SMTP_USERNAME`,
`CODRAW_SMTP_PASSWORD`), адрес отправителя писем (`CODRAW_MAIL_FROM`) и хосты вебхуков чатов
(`CODRAW_WEBHOOK_ALLOWED_HOSTS`). Без SMTP-сервера стек SHALL запускаться, а почта — оставаться выключенной.

#### Scenario: Стек без почты

- **WHEN** администратор запускает стек без `CODRAW_SMTP_HOST`
- **THEN** стек запускается, и страница настроек уведомлений говорит, что почта на этом сервере не настроена

#### Scenario: Стек с почтой

- **WHEN** заданы `CODRAW_APP_URL`, `CODRAW_SMTP_HOST` и `CODRAW_MAIL_FROM`
- **THEN** пользователь подтверждает адрес почты письмом со ссылкой на `CODRAW_APP_URL`

### Requirement: Ресурсы одной установки

Руководство по развёртыванию SHALL называть ресурсы, которые нужны одной установке под нагрузку, и ссылаться на отчёт о
нагрузочных тестах: сколько досок и участников на доске выдерживает один процесс `collab` при p95 доставки правки
≤ 200 мс, что упирается первым, сколько памяти занимают `collab` и `backend`, и когда менять окно рассылки
`CODRAW_COLLAB_BROADCAST_DELAY_MS`.

#### Scenario: Оператор подбирает сервер

- **WHEN** оператор читает `docs/deploy.md` перед развёртыванием
- **THEN** он находит рекомендуемые процессор и память для ожидаемого числа одновременно открытых досок и ссылку на
  `docs/load-testing.md` со стендом и цифрами

### Requirement: Соединения единого адреса

nginx образа `frontend` SHALL принимать не меньше 4096 соединений на рабочий процесс, чтобы предел одновременных
участников задавал `collab`, а не nginx: каждый участник доски держит два соединения nginx — от браузера и к `collab`.

#### Scenario: Сервер с одним ядром

- **WHEN** стек запущен на сервере с одним ядром, и к доскам подключены 600 участников
- **THEN** nginx принимает все соединения, и ни один участник не получает отказа из-за `worker_connections`

### Requirement: Автоматическая выкатка

Когда в `main` прошли все проверки CI коммита и `latest` поставлен на его образы, CI SHALL выкатывать образы этого
коммита на сервер по SSH вместе с `docker-compose.prod.yml` и конфигурациями `deploy/` того же коммита, не меняя
`.env.prod` сервера. Выкатки SHALL идти по одной. Без настроенного сервера задача выкатки SHALL проходить, ничего не
делая.

#### Scenario: Мерж в main

- **WHEN** в `main` пушат коммит, все проверки CI проходят, и выкатка настроена
- **THEN** на сервере `backend`, `collab`, `frontend` и `backup` работают на образах этого коммита и `healthy`

#### Scenario: Выкатка не настроена

- **WHEN** в `main` пушат коммит, а сервер для выкатки не задан
- **THEN** задача выкатки проходит с пометкой, что выкатка не настроена

#### Scenario: Проверки упали

- **WHEN** в `main` пушат коммит, и тесты падают
- **THEN** выкатка не начинается, и сервер остаётся на прежней версии

#### Scenario: Два мержа подряд

- **WHEN** выкатка коммита A идёт, а в `main` проходят проверки коммиты B и C
- **THEN** после A выкатывается только C

### Requirement: Проверки до переключения

Выкатка SHALL до остановки любого контейнера проверить конфигурацию коммита вместе с `.env.prod`, получить и найти все
образы и снять резервную копию. Неудача любой проверки SHALL останавливать выкатку, оставляя работающий стек и его
файлы без изменений.

#### Scenario: Новая обязательная переменная

- **WHEN** коммит требует переменную, которой нет в `.env.prod` сервера
- **THEN** выкатка завершается ошибкой, называет переменную, а стек работает на прежней версии

#### Scenario: Нет образа

- **WHEN** образа коммита нет в реестре
- **THEN** выкатка завершается ошибкой до переключения, контейнеры не перезапускаются

#### Scenario: Резервная копия перед выкаткой

- **WHEN** выкатка начинается на сервере с работающим сервисом `backup`
- **THEN** до перезапуска контейнеров появляется новая резервная копия, а если копия не удалась, выкатка
  останавливается

### Requirement: Откат неудачной выкатки

Если контейнеры новой версии не стали `healthy` за время ожидания, выкатка SHALL вернуть прежние файлы и прежнюю
версию образов, дождаться `healthy` и завершиться ошибкой, показав состояние и журналы контейнеров.

#### Scenario: backend не поднимается

- **WHEN** `backend` нового коммита завершается при старте
- **THEN** стек возвращается на прежнюю версию, все контейнеры `healthy`, а задача выкатки красная

### Requirement: Проверка выкатки в CI

CI SHALL при каждом пуше проверять скрипт выкатки на поднятом из образов стеке: выкатку образов коммита, отказ без
образов и откат выкатки, у которой `backend` не поднимается.

#### Scenario: Пуш в ветку

- **WHEN** в любую ветку пушат коммит, меняющий скрипт выкатки
- **THEN** задача `images` проверяет выкатку и откат и падает, если стек после них не `healthy` на образах коммита
