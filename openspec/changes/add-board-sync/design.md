# Design

## Context

После `bootstrap-monorepo` есть три подпроекта. `collab` синхронизирует Yjs-документы только в
памяти: после перезапуска всё теряется, а документ создаётся для любого имени. Требования —
в `specs/`, мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**

- Документ доски переживает перезапуск `collab` и уход всех участников.
- Схемой БД владеет только `backend`, `collab` не ходит в БД напрямую (ADR-0001).
- Сквозной тест доказывает, что три сервиса и PostgreSQL работают вместе.

**Non-Goals:**

- Содержимое документа: модель фигур и редактор — в `add-diagram-editor`. Для `backend` и `collab`
  документ остаётся непрозрачным бинарным состоянием Yjs.
- Аутентификация и права — в `add-user-auth`.
- История версий, удаление и переименование досок.

## Decisions

### Две таблицы: метаданные и документ

```
boards           (id uuid PK, title text NOT NULL, created_at, updated_at)
board_documents  (board_id uuid PK → boards ON DELETE CASCADE, state bytea NOT NULL, updated_at)
```

Список досок не тянет `bytea`. Пустая доска не имеет строки в `board_documents`.

Альтернатива — журнал инкрементальных апдейтов Yjs. Отклонена: для MVP достаточно снапшота, а журнал
понадобится только для истории версий.

### Внутренний API backend

| Метод | Путь | Ответ |
|-------|------|-------|
| `GET` | `/internal/boards/{id}/document` | 200 + `application/octet-stream`; 204, если у доски ещё нет состояния; 404, если доски нет |
| `PUT` | `/internal/boards/{id}/document` | 204; 404, если доски нет |

- Каждый запрос несёт заголовок `X-Internal-Token` с общим секретом из переменной
  `CODRAW_INTERNAL_TOKEN`. Без него — 401.
- `/internal/**` не проксируется ни Vite, ни nginx.
- `PUT` обновляет и `boards.updated_at`, чтобы список досок сортировался по последнему изменению.

### Хранение в collab через extension-database

- `@hocuspocus/extension-database` с хуками `fetch` и `store`, которые вызывают внутренний API.
- Имя документа — UUID доски. Имя, которое не является UUID, отклоняется сразу, без запроса в backend.
- Ответ 404 при загрузке → ошибка в хуке → Hocuspocus закрывает соединение. Клиент показывает
  «Доска не найдена».
- Сохранение — встроенный debounce Hocuspocus (2 с, не дольше 10 с при непрерывных правках), плюс
  сохранение при выгрузке документа после ухода последнего участника.

### Фронтенд

- `react-router`: `/` — список досок, `/boards/:id` — доска.
- `@tanstack/react-query` для REST.
- `HocuspocusProvider` подключается к `${origin}/collab`, по протоколу `wss`, если страница открыта
  по `https`.
- Участники — через awareness: `{ user: { name, color } }`. Пока нет входа, имя — «Гость N» со
  случайным номером, цвет — из фиксированной палитры.

### Тестирование

- `backend` — MockMvc + Testcontainers (PostgreSQL 18).
- `collab` — настоящий сервер Hocuspocus на случайном порту и фейковый HTTP-сервер вместо `backend`.
- Сквозной тест — Playwright: два контекста браузера на одной доске. В CI PostgreSQL поднимается как
  service container, а три сервиса запускаются из собранных артефактов.

## Risks / Trade-offs

- [Падение `collab` до срабатывания debounce теряет последние правки] → не больше 10 с правок;
  клиенты при переподключении досылают свои изменения, потому что Yjs хранит их локально.
- [Утечка сервисного токена даёт доступ к любому документу] → токен только в переменных окружения,
  `/internal/**` не проксируется наружу. После `add-user-auth` можно перейти на подписанные
  сервисные JWT.
- [Две открытые копии `collab` для одной доски перезаписывают состояние друг друга] → пока один
  инстанс `collab`. Масштабирование через Redis и sticky-маршрутизацию — отдельное изменение.

## Migration Plan
