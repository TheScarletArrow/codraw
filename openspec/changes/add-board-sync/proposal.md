# Proposal

## Why

Ядро продукта — совместная работа над доской, и это самая рискованная часть: синхронизация, хранение
и связка `collab` ↔ `backend`. Её стоит проверить первой, сквозным минимальным срезом через все три
подпроекта, до редактора и аутентификации.

## What Changes

- `backend`: доски в PostgreSQL (миграции Flyway) и REST API для создания доски, списка досок и
  получения доски по идентификатору.
- `backend`: внутренний API для `collab` — загрузка и сохранение состояния документа доски. Доступен
  только по сервисному токену и не проксируется наружу.
- `collab`: документ загружается из `backend` при первом подключении к доске и сохраняется после
  изменений. Подключение к несуществующей доске отклоняется.
- `frontend`: главная страница со списком досок и кнопкой «Создать доску», страница доски
  `/boards/:id` со статусом синхронизации и списком участников. Редактора на странице ещё нет.
- `docker-compose.yml` с PostgreSQL для локальной разработки.
- Сквозной тест Playwright в CI.

## Capabilities

### New Capabilities

- `board-management`: создание досок, список досок и получение доски.
- `realtime-sync`: подключение к документу доски, доставка изменений между участниками и сохранение
  состояния.
- `presence`: кто сейчас находится на доске.

### Modified Capabilities

Нет.

## Impact

- `backend`: новые зависимости — JDBC, Flyway, драйвер PostgreSQL, Testcontainers; новые эндпоинты
  `/api/boards/**` и `/internal/boards/**`.
- `collab`: новая зависимость `@hocuspocus/extension-database`; переменные окружения `BACKEND_URL`
  и `CODRAW_INTERNAL_TOKEN`.
- `frontend`: новые зависимости — `react-router`, `@tanstack/react-query`, `@hocuspocus/provider`,
  `yjs`.
- CI: job для сквозных тестов с PostgreSQL как service container.
- Пока нет аутентификации, любой, кто знает идентификатор доски, может её открыть. Это закрывает
  `add-user-auth`.
