# Proposal

## Why

После `add-board-sync` и `add-diagram-editor` любой, кто знает идентификатор доски, может открыть
и изменить её, а все участники — анонимные гости. Нужны вход в систему, владельцы досок и проверка
доступа при подключении к синхронизации.

## What Changes

- `backend`: вход через GitHub и Google (OAuth2), пользователи в БД, сессия в cookie, выход из системы.
- `backend`: работа без входа — гостем «Гость N» со своими досками; гостевой сеанс живёт 30 дней, при входе
  через провайдера доски гостя переходят к аккаунту.
- `backend`: у каждой доски есть владелец — её создатель. Список возвращает только свои доски, а открыть
  и редактировать любую доску может каждый, у кого есть ссылка на неё.
- `backend`: краткоживущий токен доступа к синхронизации конкретной доски и публичные ключи (JWKS)
  для его проверки.
- `collab`: подключение к документу доски только с действительным токеном для этой доски.
- `frontend`: страница входа с кнопкой «Продолжить без входа», переход на неё при 401, выход; имя и аватар
  пользователя из профиля, «Гость N» — только для гостей.
- **BREAKING**: все эндпоинты `/api/**`, кроме входа (в том числе входа гостем), требуют аутентификации. Доски, созданные до
  этого изменения, удаляются миграцией: до релиза пользовательских данных нет.

## Capabilities

### New Capabilities

- `user-auth`: вход через внешних провайдеров и гостем, сеанс пользователя и выход.
- `board-access`: владение досками, доступ по ссылке и проверка доступа через API и синхронизацию.

### Modified Capabilities

- `board-management`: список досок ограничивается досками текущего пользователя.
- `presence`: вошедшие участники отображаются под именами из профиля, имя «Гость N» остаётся за гостями
  и не меняется, пока действует гостевой сеанс.

## Impact

- `backend`: новые зависимости — Spring Security, OAuth2 Client, Spring Session JDBC; новые таблицы
  `users` и сессий, столбец `boards.owner_id`; гости хранятся в `users` с провайдером `guest`.
- `collab`: новая зависимость `jose` для проверки JWT; переменная `BACKEND_JWKS_URL`.
- `frontend`: обработка 401, получение токена перед каждым подключением к синхронизации.
- Конфигурация: OAuth-приложения GitHub и Google, их client id и secret в переменных окружения.
