# Proposal

## Why

Итоги архитектурного обсуждения на доске приходится вручную переносить в трекер, а статус реализации узнавать отдельно:
у элемента «Кэш каталога» не видно, есть ли под него задача и закрыта ли она, а у ветки «Почему без кэша?» — во что она
превратилась. Связь элемента и обсуждения с задачей сохраняет контекст решения и показывает, какие изменения архитектуры
действительно выполнены. Это задача #124 эпика #114.

**До:** задачи живут в GitHub отдельно от схемы, ссылки на них — в тексте комментариев, статус — только в GitHub.

**После:** у элемента и у ветки — привязанные задачи GitHub с номером, названием и статусом, новая задача создаётся из
CoDraw со ссылкой обратно, а статус приходит из GitHub сам.

## What Changes

- Трекер — GitHub Issues (github.com или GitHub Enterprise Server). Пользователь, вошедший через провайдера, подключает
  GitHub своим токеном на странице «Подключения»; токен хранится на сервере и не показывается.
- «Задачи…» в меню фигуры, таблицы, связи и группы открывает панель задач элемента; у элемента с задачами — значок на
  холсте. В каждой ветке комментариев — её задачи и кнопка «Задача».
- «Привязать задачу» — по номеру, ссылке, `owner/name#N` или словам из названия, с предупреждением, что задачу увидят
  все участники доски, отдельно — для закрытого репозитория. «Создать задачу» — с описанием и ссылкой обратно на элемент
  или ветку; повтор той же отправки второй задачи не создаёт.
- Статус идёт только из GitHub: привязка обновляется токеном привязавшего, когда её показывают, и вебхуком задач, если
  его настроил администратор; повторные и запоздавшие события ничего не меняют. Удалённая задача, пропавший доступ и
  отключённый привязавший показываются явно, привязку можно взять на себя.
- Политика конфиденциальности называет токен и привязанные задачи.

## Capabilities

### New Capabilities

- `issue-links`: подключение GitHub, привязка и создание задач у элементов и веток, показ, обновление статуса, вебхук.

### Modified Capabilities

- `comments`: задачи ветки.
- `canvas-context-menu`: пункт «Задачи…».
- `legal-pages`: токен GitHub и привязанные задачи в политике конфиденциальности.

## Impact

- `backend`: пакет `issue/` (`GitHubClient`, `IssueTrackerService`, `IssueLinkService`, `GitHubWebhookService`,
  контроллеры, `IssueProblems`), миграции V25/U25, `codraw.issues.github.*`, предел
  `codraw.limits.issue-links-per-board` с метрикой, открытый `POST /api/integrations/github/webhook` без CSRF,
  `LegalController` (`issues`); тесты с GitHub на этой машине.
- `collab`: сообщение `issues-changed`.
- `frontend`: `api/issues.ts`, `issues/` (панель, значки, задачи ветки, формы), страница «Подключения», пункт меню,
  `ThreadCard`, `BoardPage`, `useBoardConnection`, политика конфиденциальности, «Что нового» 0.25.0.
- `docs/adr/0009-issue-tracker.md`, `docs/deploy.md`, `docker-compose.prod.yml`, `.env.prod.example`, README.
- Новых зависимостей нет: запросы к GitHub идут HTTP-клиентом JDK, подпись вебхука — `javax.crypto`.
- Вне рамок: другие трекеры, OAuth и GitHub App, двусторонняя синхронизация статусов, pull request, привязка задач при
  импорте и в предложениях изменений.
