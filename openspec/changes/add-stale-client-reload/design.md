# Design

## Context

- Ленивые части приложения: маршруты `BoardPage`, `ProposalPage`, `AdminPage`, `HelpPage`, `PublicBoardPage`
  (`routes.tsx`, свойство `lazy` React Router) и модули внутри страниц — ELK (`diagram/layout.ts`), YAML
  (`apiSpec/loadDocument.ts`, `edgeApi/EdgeApiPanel.tsx`), jsPDF, значки технологий.
- nginx отдаёт `/assets/` с `immutable` и `try_files $uri =404`, остальное — `index.html` с `no-cache`. Старых файлов
  в новом образе нет: после выкатки запрос старого чанка получает 404, `import()` отклоняется, React Router
  показывает `errorElement` — общий `AppError`.
- Все образы (`backend`, `collab`, `frontend`) выкатываются вместе одним тегом (`CODRAW_VERSION`,
  `docs/deploy.md`); открытые вкладки после перезапуска `collab` подключаются заново сами.
- Документ доски несёт `meta.schemaVersion` (сейчас 2); `initializeDocument` переводит старые документы вперёд, но
  ничего не делает с документом новее себя.
- Офлайн-режим: y-indexeddb хранит документ страницы в локальной копии; `useBoardConnection` знает, есть ли правки,
  которые `collab` ещё не принял (`unsent`), и ведёт ли страница локальную копию (`cached`).

## Goals / Non-Goals

**Goals:** вкладка, открытая до выкатки, не показывает «Что-то пошло не так», а сама перезагружается или ясно просит
обновить страницу; узнаёт о новой версии без перезагрузки; обновление по кнопке не теряет правок.

**Non-Goals:** service worker и офлайн-кеш файлов сборки; хранение старых чанков рядом с новыми; принудительная
перезагрузка открытой вкладки; минимальная версия клиента на сервере (см. ниже).

## Decisions

- **`version.json` из плагина Vite.** `vite/versionFile.ts` один раз на сборку выбирает идентификатор (переменная
  `CODRAW_BUILD_ID`, иначе время сборки в base36), передаёт версию и идентификатор в код через `define`
  (`__CODRAW_VERSION__`, `__CODRAW_BUILD__`) и кладёт в корень сборки `version.json`
  `{"version":"0.41.0","build":"…"}`; dev-сервер отдаёт тот же файл. Сравнивается идентификатор сборки, а не
  версия: выкатка без подъёма версии (исправление, откат) тоже меняет файлы. Хеш содержимого не годится —
  код не может знать хеш файла, в котором он сам лежит.
- **nginx: `location = /version.json` с `no-cache` и `try_files $uri =404`.** Без своего `location` отсутствующий
  файл вернул бы `index.html` со статусом 200; клиент всё равно проверяет форму ответа и молча пропускает ошибку.
- **Когда проверять.** Раз в 5 минут, пока вкладка видна; при `visibilitychange` в видимое состояние и при `online`
  (не чаще раза в 30 секунд); после `vite:preloadError`. `fetch` с `cache: 'no-store'`; ошибка сети, не-JSON или
  чужая форма — «ничего не известно». После обнаружения новой версии проверки прекращаются.
- **Плашка — одна на приложение.** `UpdateBanner` смонтирован в `App` рядом с `RouterProvider`, поэтому есть на всех
  страницах, включая `/help` и `/view/:boardId` вне `Layout`. Плашка фиксирована внизу по центру, не сдвигает
  раскладку страниц высотой `h-dvh`, `role="status"`; «Позже» прячет её до перезагрузки страницы. Во встраивании
  (`/view` во фрейме) плашка та же: читателю нечего терять, а без неё он увидит устаревшую доску.
- **`vite:preloadError` не перезагружает сам.** Событие приходит и при неудачной загрузке модуля посреди работы
  (автораскладка, импорт OpenAPI, PDF). Перезагрузка в этот момент закрыла бы диалог с вставленным текстом и
  незавершённые действия. Поэтому обработчик только запускает проверку версии (плашка появится, если сборка
  сменилась), а ошибку получает вызывающий код и показывает своё сообщение, как и раньше. `preventDefault` не
  вызывается.
- **Ленивые маршруты перезагружаются сами один раз.** Обёртка `lazyPage(load, pick)` превращает отказ `import()` в
  `ChunkLoadError`; `AppError` по `useRouteError()` показывает для неё `StaleClient`. При переходе на ленивую
  страницу прежняя страница уже ушла, так что перезагрузка с тем же адресом ничего не теряет сверх того, что потерял
  бы сам переход. `StaleClient`:
  - нет связи (`navigator.onLine === false`) — не перезагружает (браузер показал бы свою страницу ошибки), пишет
    «Нет связи» и перезагружает по событию `online`;
  - иначе `reloadOnce()`: отметка времени в `sessionStorage` (`codraw.reload-after-deploy`); если отметка моложе
    минуты или `sessionStorage` бросает исключение — не перезагружает и показывает экран «CoDraw обновился» с
    кнопкой «Обновить страницу». Окно в минуту, а не флаг навсегда: следующая выкатка в той же вкладке снова
    получит автоматическую перезагрузку.
- **Сообщение об ошибке.** `ChunkLoadError` по-прежнему уходит в отчёты об ошибках клиента (`onCaughtError`): частые
  отказы загрузки после выкатки — сигнал для эксплуатации.

## Правила: обновление страницы не теряет правок

1. **Сама страница перезагружается только там, где нечего терять:** ленивый маршрут не загрузился, а прежняя
   страница уже закрыта переходом. Посреди работы (плашка, `vite:preloadError`) страницу обновляет только
   пользователь кнопкой.
2. **Кнопка «Обновить» плашки сначала готовит страницу** (`prepareReload`). Каждая открытая страница редактора
   регистрирует себя (`registerUnsavedWork`) с двумя функциями:
   - `flush` — применить незавершённую правку подписи (`graph.stopEditing(false)`): текст попадает в документ Yjs, а
     оттуда в `collab` и локальную копию;
   - `unsaved` — есть правки, которых нет ни на сервере, ни в локальной копии: `connection.unsent && !connection.cached`
     (у доски), `unsent` без локальной копии у черновика предложения.
3. **Ожидание.** После `flush` плашка показывает «Сохраняем правки…» и ждёт до 3 секунд, пока `unsaved` станет
   ложным (в сети правки уходят за доли секунды); затем — 100 мс на запись транзакции IndexedDB y-indexeddb.
4. **Офлайн-режим.** Правки в локальной копии (`cached`) переживают перезагрузку: после неё страница загрузит копию и
   отправит правки сама, как при обычном открытии доски без связи. Поэтому `unsent && cached` не мешает обновлению.
   Если же правки есть только в памяти (локальные копии недоступны, копия отложена), плашка пишет «Не все правки
   сохранены…» и предлагает «Обновить всё равно» — решает пользователь.
5. **Открытые формы** (диалоги импорта, правила представлений, поля панелей) не отслеживаются: глобального признака
   «форма изменена» в приложении нет, а плашка не перезагружает страницу сама и не закрывает формы — пользователь
   обновляет, когда закончит. Кнопка «Позже» прячет плашку.
6. **Предпросмотр, публичный просмотр, справка, администрирование** ничего не регистрируют: правок, которые жили бы
   только во вкладке, у них нет.

## Минимальная версия клиента на сервере: для MVP не нужна

Решение: `collab` и `backend` в этом изменении не проверяют версию клиента.

- Все сервисы выкатываются вместе; API и протокол синхронизации пока меняются только совместимо: новые поля
  необязательны, старый клиент их не трогает (стиль ячейки — свободная карта, неизвестные ключи переживают
  чтение и запись).
- Схема документа уже версионирована, и с этим изменением клиент **сам** защищается от документа новее себя:
  `useNewerDocument` смотрит `meta.schemaVersion > SCHEMA_VERSION`; редактор доски и черновика тогда открывает
  документ только для чтения (ничего не пишет, не переводит схему), а плашка просит обновить страницу и не
  прячется. Защита работает только в клиентах, которые её уже содержат, — поэтому она входит сейчас, до первого
  несовместимого изменения, а не вместе с ним.
- Отказ на сервере без версии в подключении закрыл бы и все уже открытые вкладки 0.40.0 и старше, которые версию
  не передают, — то есть сам стал бы несовместимым изменением.

**При первом несовместимом изменении формата документа:**

1. Поднять `SCHEMA_VERSION` и перевести документы вперёд в `initializeDocument`; вкладки 0.41.0+ увидят новую схему
   и перейдут в режим чтения с плашкой.
2. Передавать версию схемы клиента при подключении (`parameters` провайдера Hocuspocus или утверждение в токене
   `collab`) и в `onAuthenticate` `collab` отказывать клиенту со схемой ниже минимальной (а также без версии — это
   вкладки до 0.41.0) с новой причиной `CLIENT_OUTDATED`; `useBoardConnection` по ней показывает плашку обновления и
   не переподключается.
3. Для несовместимого изменения REST API — тот же приём: заголовок версии клиента и ответ `426` с той же реакцией
   клиента.
4. Записать минимальную версию и причину в ADR.

## Risks / Trade-offs

- Идентификатор сборки по времени отличается у двух сборок одного коммита: повторная сборка без изменений покажет
  плашку. Митигация: `CODRAW_BUILD_ID` можно задать (например, хешем коммита); образы собираются один раз в CI.
- Каждая вкладка раз в 5 минут запрашивает маленький файл у nginx — нагрузка несущественна, `backend` не участвует.
- Перезагрузка по `online` на экране «Нет связи» может снова не загрузить страницу при плохой связи — тогда сработает
  защита от цикла и останется экран с кнопкой.
