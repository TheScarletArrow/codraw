# Proposal

## Why

Схему микросервисов рисуют по тому, что уже описано: у сервисов есть спецификации API — OpenAPI для HTTP и AsyncAPI
для сообщений. Перерисовывать их руками долго, а схема быстро расходится с API: забытый эндпоинт, топик, на который
никто не подписан, модель с другим набором полей. В CoDraw уже есть импорт SQL и Mermaid, но нет способа получить из
файлов спецификаций сервисы, их эндпоинты, топики с отправителями и получателями и модели данных, которые можно двигать,
обсуждать и править вместе. draw.io такого импорта не имеет вовсе.

## What Changes

- В меню «SQL и Mermaid» появляется «Импорт OpenAPI / AsyncAPI…» (только у тех, кто правит доску): поле для текста,
  «Открыть файлы» (`.yaml`, `.yml`, `.json`, несколько сразу), галочка «Модели таблицами» (включена), сводка
  «Сервисов, эндпоинтов, топиков, моделей, связей, пропущено ссылок», ошибки разбора со строкой и столбцом и
  «Добавить на страницу». Схема встаёт справа от фигур страницы, разложенная автораскладкой, одним шагом отмены.
- OpenAPI 3.x (3.0, 3.1) и Swagger 2.0 — фигура «Сервис» с названием API и списком эндпоинтов `МЕТОД /путь` в порядке
  документа. Это обычная фигура палитры с многострочной подписью, а не таблица: SQL-выгрузка, поля и индексы её не
  касаются.
- AsyncAPI 2.x и 3.0 — сервис приложения, «Топик событий» на каждый канал и связи: отправка — от сервиса к топику,
  получение — от топика к сервису, с именами сообщений. Смысл `publish`/`subscribe` AsyncAPI 2 (описаны со стороны
  клиента) и `action: send|receive` AsyncAPI 3 учитывается. Каналы с одним адресом из разных файлов — один топик, так
  что несколько AsyncAPI дают карту обмена сообщениями между сервисами.
- С галочкой «Модели таблицами» схемы данных (`components.schemas`, `definitions` Swagger 2.0, тела сообщений
  AsyncAPI) становятся таблицами: поле на свойство `имя тип`, `NOT NULL` для обязательных, связи по `$ref` от поля
  к таблице модели с ER-маркерами, `allOf`, `oneOf` и `anyOf` — подписанные связи к базовым моделям и вариантам; пунктир от сервиса к моделям его
  запросов и ответов и от топика к моделям его сообщений.
- Разрешаются только ссылки внутри документа; внешние и ведущие в никуда считаются в сводке как пропущенные. Циклы
  ссылок не зацикливают разбор; размер файла, якоря YAML, число моделей и топиков ограничены.
- Новая зависимость `yaml` (ISC, без зависимостей) загружается отдельным чанком только при разборе YAML.

## Capabilities

### New Capabilities

- `api-spec-import`: сервисы, эндпоинты, топики, модели и связи доски из OpenAPI, Swagger 2.0 и AsyncAPI.

### Modified Capabilities

- `sql-schema`: меню «SQL и Mermaid» предлагает «Импорт OpenAPI / AsyncAPI…», а выгрузка SQL и Mermaid берёт таблицы
  моделей и не берёт фигуры сервисов и топиков.
- `diagram-editing`: элементы из импорта OpenAPI и AsyncAPI отмечены участником, который их добавил.

## Impact

- `frontend`: новый модуль `apiSpec/` (загрузка YAML и JSON, разбор OpenAPI и AsyncAPI, граф и ячейки, окно импорта),
  меню `sql/SqlMenu.tsx`, экспорт оценки ширины таблицы из `sql/erDiagram.ts`, зависимость `yaml`.
- `backend`, `collab` и документ доски не меняются: разбор идёт в браузере, файлы никуда не отправляются.
- Вне объёма: вставка спецификации на холст `Ctrl+V`, внешние `$ref` (другие файлы и адреса), запрос-ответ AsyncAPI 3
  (`reply`), привязки протоколов (очередь AMQP как «Очередь»), выгрузка схемы обратно в OpenAPI или AsyncAPI.
