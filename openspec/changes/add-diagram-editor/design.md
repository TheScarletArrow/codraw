# Design

## Context

После `add-board-sync` у каждой доски есть общий Yjs-документ, который синхронизирует и сохраняет
`collab`. Модель документа и выбор maxGraph обоснованы в ADR-0001, требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Источник истины — Yjs-документ; maxGraph только отображает его и превращает действия пользователя
  в изменения документа.
- Одновременные правки разных свойств одной фигуры не теряются.
- Undo/redo отменяет только свои изменения.

**Non-Goals:**

- Несколько страниц, слои, группы и контейнеры — модель их допускает, интерфейса пока нет.
- Импорт и экспорт `.drawio` — отдельное изменение.
- Библиотеки фигур draw.io (AWS, UML, BPMN).

## Decisions

### Модель документа

```
meta:  Y.Map                      { title, schemaVersion: 1 }
pages: Y.Map<pageId, Y.Map>
  └── cells: Y.Map<cellId, Y.Map>
        parent, kind (vertex | edge), value, order,
        geometry { x, y, width, height, points },
        source, target,
        style: Y.Map<ключ, значение>
```

- При создании доски документ получает одну страницу и корневую ячейку со слоем по умолчанию, как
  в mxGraph.
- `style` — отдельный `Y.Map`, чтобы смена заливки и обводки разными участниками не конфликтовала.
- `geometry` — значение целиком: перемещение и ресайз всё равно меняют его всё.
- `order` — дробный индекс (`fractional-indexing`) для порядка отрисовки.
- Документ создаёт первый подключившийся клиент. Чтобы два клиента не создали две страницы,
  идентификаторы страницы и корневых ячеек фиксированы.

Альтернатива — хранить строку стиля draw.io как есть. Отклонена: одновременные правки стиля
перетирали бы друг друга.

### Связка Yjs ↔ maxGraph

- **Локальные изменения.** Слушаем событие изменения модели maxGraph и переводим его изменения
  (добавление и удаление ячейки, геометрия, стиль, подпись, концы связи) в одну транзакцию Yjs
  с origin `local`.
- **Удалённые изменения.** `observeDeep` на `cells` применяет их к модели maxGraph в одном пакетном
  обновлении. На это время включается флаг, чтобы изменения не вернулись обратно в Yjs.
- Связка — отдельный модуль без React, чтобы её можно было тестировать отдельно и заменить рендерер,
  не трогая модель.

### Undo/redo

- `Y.UndoManager` над `cells` с `trackedOrigins = {local}`: отменяются только свои транзакции.
- Встроенный undo maxGraph отключён.
- Горячие клавиши: `Ctrl/Cmd+Z` и `Ctrl/Cmd+Shift+Z`.

### Курсоры и выделения

- Awareness хранит `cursor { x, y }` в координатах диаграммы, а не экрана, поэтому курсоры
  совпадают при разном масштабе у участников.
- Также хранится `selection: cellId[]`.
- Обновление курсора — не чаще 20 раз в секунду.
- Отрисовка — отдельный SVG-слой поверх холста, не ячейки maxGraph, чтобы курсоры не попадали
  в документ.

### Интерфейс

- Tailwind CSS 4 и shadcn/ui: панель фигур слева, тулбар (undo, redo, масштаб) и участники сверху.
- Холст maxGraph живёт в React-компоненте, который создаёт граф один раз и уничтожает при уходе
  со страницы.

### Тестирование

- Модель и связка — unit-тесты на двух Y.Doc, связанных в памяти: изменение через модель maxGraph
  в одном документе даёт то же состояние в другом.
- Взаимодействие с холстом — Playwright: перетаскивание, связи, подписи, два браузера одновременно.

## Risks / Trade-offs

- [maxGraph ещё до 1.0, API меняется] → версия зафиксирована точно, весь код работы с maxGraph
  собран в связке и компоненте холста.
- [Ошибка в связке рассинхронизирует холст и документ] → round-trip-тесты на каждый тип изменения;
  при сомнении холст можно перестроить из документа целиком.
- [maxGraph может не работать в jsdom (нет измерения SVG)] → связку тестируем на уровне модели без
  отрисовки, всё визуальное — в Playwright.
- [Частые обновления курсора нагружают сеть] → ограничение 20 Гц; awareness не сохраняется в БД.
