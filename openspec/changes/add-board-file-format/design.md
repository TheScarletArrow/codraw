## Context

Доска — документ Yjs: `meta`, `pages` (страницы с порядком, детализацией и представлением), `cells:<pageId>` (ячейки
страницы: вид, родитель, дробный ключ порядка, подпись, геометрия, концы, стиль-`Y.Map`, свойства `<object>`, а также
статус и отметки авторства), `elements` (свойства элементов архитектуры, «часть чего» и окружение) и `checks` (настройки
проверок схемы). Модель повторяет модель ячеек mxGraph, поэтому `.drawio` пишется из неё почти напрямую, но всё, чего в
draw.io нет, при экспорте превращается в обычные фигуры или пропадает (`drawio-files`).

Картинки доски лежат в хранилище картинок, в документе — их адреса `/api/boards/<board>/images/<image>`. Экспорт в
`.drawio` вписывает их в файл `data:`-адресами, импорт загружает их обратно на доску (`storePageImages`).

Новая доска из файла создаётся пустой, а её страницы пишет клиент, когда документ синхронизирован
(`setPendingImport` / `takePendingImport`). `backend` и `collab` ничего не знают о файлах — так и остаётся.

## Goals / Non-Goals

**Goals:**

- Файл, из которого получается та же доска, что сохранили: всё, что лежит в документе доски и не является
  персональными данными участников.
- Файл заметно компактнее `.drawio` той же доски и быстро читается.
- Формат версионируется и проверяется при чтении так же строго, как любой файл извне.

**Non-Goals:**

- Совместимость с draw.io и другими редакторами: `.codraw` открывает только CoDraw.
- Комментарии, версии, участники, предложения, решения и задачи — это данные `backend`, а не документа доски.
- Слияние файла с доской «по месту»: импорт добавляет страницы, как импорт `.drawio`.

## Decisions

### Контейнер — ZIP с JSON и двоичными картинками

```
Платёжный сервис.codraw  (ZIP)
├── board.json        deflate — документ доски
└── images/
    ├── 1.png         stored — каждая картинка один раз
    └── 2.jpg
```

- **Почему не Yjs-снимок (`Y.encodeStateAsUpdate`).** Он компактен и без потерь «бесплатно», но непрозрачен, тянет
  идентификаторы клиентов, удалённые элементы и внутренности Yjs, его нельзя проверить до применения и нельзя очистить от
  авторства без разбора. Импорт страниц в существующую доску всё равно требует читать страницы и ячейки по одной.
- **Почему не один JSON с base64.** Картинки в base64 на треть больше, весь файл приходится держать строкой и разжимать
  целиком. ZIP хранит картинки как есть (PNG и JPEG уже сжаты — `stored`), сжимает только JSON и открывается любым
  архиватором: `board.json` можно посмотреть глазами.
- **Без библиотек.** `lib/zip.ts` уже пишет ZIP без сжатия; к нему добавляются сжатие `deflate` через
  `CompressionStream('deflate-raw')` и чтение через `DecompressionStream` — тем же способом `drawio/parse.ts` разжимает
  диаграммы draw.io. ZIP64, шифрование и методы, кроме `stored` и `deflate`, не поддерживаются: CoDraw их не пишет.
- **Расширение `.codraw`, тип `application/vnd.codraw.board+zip`.** Формат определяется по содержимому, а не по
  расширению: файл, который начинается с `PK\x03\x04`, читается как `.codraw`, остальное — как draw.io.

### `board.json`, версия 1

```json
{
  "format": "codraw",
  "version": 1,
  "title": "Платёжный сервис",
  "pages": [
    {
      "id": "page-1",
      "name": "Контейнеры",
      "view": { "rule": { "kind": "containers", "scope": "e1" }, "hidden": [], "places": {} },
      "cells": [
        { "id": "1", "kind": "layer" },
        { "id": "a", "value": "API", "geometry": { "x": 40, "y": 40, "width": 160, "height": 80 },
          "style": { "rounded": true, "codrawElement": "e2" }, "status": "review" },
        { "id": "b", "kind": "edge", "source": "a", "target": "c",
          "geometry": { "relative": true }, "style": { "endArrow": "block" } },
        { "id": "i", "geometry": { "x": 300, "width": 64, "height": 64 },
          "style": { "shape": "image", "image": "images/1.png" } }
      ]
    }
  ],
  "elements": {
    "e1": { "name": "Платежи", "kind": "c4SoftwareSystem" },
    "e2": { "name": "API", "kind": "c4Container", "technology": "Kotlin", "parent": "e1" }
  },
  "checks": { "rule:edge-technology": false },
  "images": ["images/1.png"]
}
```

- **Страницы — массив в порядке доски, ячейки — массив в порядке рисования**: сначала слои, за каждой ячейкой её
  потомки. Дробные ключи порядка (`order`) — артефакт CRDT, в файл не пишутся; при чтении они строятся заново по порядку
  массива. Корень `0` подразумевается.
- **Значения по умолчанию опускаются**: `kind` — `vertex`, `parent` — основной слой `1` (у слоя — корень), пустая
  подпись, нулевые координаты и размеры, `relative: false`, пустые стиль и свойства. Ячейка без родителя на доске
  (её родителя удалили одновременно с правкой) пишется в основной слой — там её и показывает холст.
- **Стиль — объект с типизированными значениями** (`true`, `14`, `["pci"]`), а не строка draw.io: не нужен ни разбор
  `key=value;`, ни преобразование чисел и флагов. Подписи — простой текст, как в документе, без HTML.
- **Свойства элемента хранятся один раз** в `elements`, ячейки ссылаются на элемент ключом `codrawElement`. Вместе со
  свойствами сохраняются поля модели: `parent` (элемент, частью которого он является) и `environment` (окружение узла).
- **Страница** несёт `detailOf` (элемент, который она детализирует) и `view` (правило представления, скрытое и места).
- **Ячейка** несёт `attrs` (свойства `<object>` из draw.io, которые CoDraw хранит) и `status` (`draft`, `review`,
  `done`) — без того, кто и когда его поставил.
- **`checks`** — включённые и выключенные правила (`rule:*`) и скрытые замечания (`hidden:*`).
- **`images`** — пути картинок в архиве. Стиль `image` ячейки равен такому пути только для картинок из списка, поэтому
  относительные адреса библиотек draw.io (`img/lib/...`) с ними не путаются. Картинка доски, растровый `data:`-адрес
  и картинка с той же последовательностью байт под другим адресом попадают в архив один раз (сравнение по CRC-32,
  размеру и байтам). Картинку, которую не удалось скачать (нет связи), ячейка сохраняет адресом, как `.drawio`. SVG
  `data:`-адреса draw.io остаются в стиле как есть.

### Что не пишется

Белый список вместо чёрного: в файл попадают только перечисленные поля страниц, ячеек, элементов и проверок. Отметки
`modifiedBy*`, `textAuthor*`, `statusBy*`, `statusAt` ячейки и ключ стиля `codrawLockedBy` (кто закрепил элемент или
слой) не пишутся: это персональные данные, и в другой установке их id ничего не значат. `meta.schemaVersion` заменяет
`version` файла; при открытии документ инициализируется как обычно. Новое поле документа попадает в файл только вместе
с правкой формата и его тестом — это цена белого списка, зато файл не унесёт персональные данные, о которых формат
не знает.

### Чтение и проверка

- Архив: не больше 10 000 записей; `board.json` — не больше 64 МиБ в распакованном виде (предел документа доски в
  `collab` — 16 МиБ), все записи вместе — не больше 512 МиБ; распаковка останавливается, как только вывод превышает
  размер из центрального каталога; CRC-32 каждой записи сверяется. Иначе — `BoardFileError` «Файл .codraw повреждён».
- `format` не `codraw` или нет `board.json` — «Это не файл CoDraw или draw.io»; `version` больше 1 — «Файл сохранён
  более новой версией CoDraw».
- Каждое поле проверяется по типу; неизвестные поля и значения отбрасываются. Ссылки (`link`), описания API
  (`codrawApi`) и запросы представлений (`codrawViewQuery`) проходят те же проверки, что при импорте draw.io
  (`linkOf`, `edgeApiOf`, `viewQueryOf`). Повторяющиеся id страниц и ячеек, ячейка с id корня и слой не в корне
  отбрасываются; ячейка с неизвестным родителем попадает в основной слой.
- Картинки принимаются только PNG, JPEG, GIF и WebP — по расширению пути; хранилище доски проверяет их ещё раз.

### Открытие и импорт

Одна функция `importBoardFile(doc, file, author)` для обоих случаев, по правилам импорта `.drawio`:

- Страницы файла добавляются после страниц доски; единственная пустая страница доски заменяется страницами файла —
  и тогда её id освобождается, так что у новой доски из файла остаются те же id страниц, что у сохранённой.
- Id страницы сохраняется, если на доске он свободен, иначе страница получает новый, и ссылки (`data:page/id,…`),
  `detailOf` и ключи скрытых замечаний ведут на новый.
- Id элемента сохраняется, если на доске нет такого элемента и ячейки, которая его называет; иначе элемент получает
  новый id, а ссылки на него — `codrawElement`, `parent` других элементов, `detailOf`, правило, скрытое и места
  представлений, ключи вычисленных ячеек `codrawComputed` и скрытых замечаний — переписываются. Так файл, импортированный
  в ту же доску, даёт отдельные элементы, а не общие с исходными; а новая доска из файла получает те же id, что были, и
  ключи представлений и проверок остаются верными без переписывания.
- Ячейки получают импортировавшего как того, кто изменил их последним (как при импорте `.drawio`); статусы пишутся без
  автора. Настройки правил проверок переносятся только когда файл заменяет пустую доску; скрытые замечания — всегда.
- Всё — одной транзакцией с источником `codraw:import`, которую история отмены не отслеживает.
- Картинки архива сначала загружаются в хранилище доски (`ImageHost.store`), и стиль ячейки получает адрес доски.
  Картинку, которую сохранить не удалось (квота, нет связи), ячейка получает `data:`-адресом, как при импорте `.drawio`.

### Интерфейс

- Страница доски: «Импорт из файла» (`.codraw` и draw.io, для тех, кто может править), «Сохранить в .codraw» и
  «Экспорт в .drawio» (для всех, кто видит доску). Поле файла называется «Файл CoDraw или draw.io».
- Список досок: «Открыть файл» — `.codraw` или draw.io. Название новой доски — из `title` файла `.codraw`, для draw.io —
  из имени файла, как раньше. Файл читается до создания доски, поэтому неверный файл не оставляет пустую доску.
- Ожидающий импорт новой доски хранит прочитанный файл любого из двух форматов (`OpenedFile`), а не только страницы
  draw.io.

### Размер

Для доски из `frontend/src/boardFile/write.test.ts` (сто фигур со свойствами элементов, связи, одна картинка 40 КиБ на
пяти фигурах) тест сравнивает `.codraw` с несжатым `.drawio`, как его сохраняет кнопка экспорта: `.codraw` меньше в
несколько раз, прежде всего за счёт сжатия JSON и одной копии картинки без base64.

## Risks / Trade-offs

- **Белый список отстаёт от документа.** Новая возможность, которая хранит данные в документе, должна добавить их в
  формат, иначе файл их потеряет. Смягчение: формат и его тест в одном модуле, ссылка на него в комментарии модели
  документа.
- **Id элемента, свободный сейчас, может вернуться отменой.** Если на доске удалили элемент, а потом импортировали файл
  этой же доски, отмена удаления вернёт ячейку, которая назовёт уже импортированный элемент. Это тот же элемент из той
  же доски, поэтому вреда нет; импорт `.drawio` по-прежнему всегда даёт новые id.
- **`CompressionStream` нет в очень старых браузерах.** CoDraw уже требует его для импорта сжатых диаграмм draw.io.
- **Изменение названий кнопок и поля** ломает тесты, которые их ищут; они обновляются в этом же изменении.

## Migration Plan

Миграций нет: формат новый, документы доски и API не меняются. Откат — удаление кнопок; файлы `.codraw`, сохранённые
до отката, откроет следующая версия с форматом.
