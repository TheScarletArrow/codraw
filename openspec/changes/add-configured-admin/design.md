## Context

Администраторов назначает только конфигурация (`CODRAW_ADMINS`, `AdminProperties.accounts`), в том числе
пользователей с паролем — `password:<логин>`, логин которых нельзя зарегистрировать (`add-password-sign-in`). Учётная
запись с паролем — строка `users` (`provider = 'password'`, логин в нижнем регистре в `provider_user_id`) и хеш bcrypt в
`password_credentials`; создаёт её `PasswordService` через `UserService.signUp`. Вход по паролю включается
`codraw.passwords.enabled`, регистрация — `codraw.passwords.sign-up`.

## Goals / Non-Goals

**Goals:**

- Администратор с первого запуска, без внешних провайдеров и без шага «зарегистрироваться, вписать, перезапустить».
- Настройка — единственный источник пароля этого администратора: забытый пароль восстанавливается сменой настройки.

**Non-Goals:**

- Несколько администраторов из настроек: остальные назначаются, как раньше, через `CODRAW_ADMINS`.
- Хеш пароля в настройках вместо пароля; секрет и так живёт в `.env.prod` рядом с паролем базы.

## Decisions

### Настройки в `AdminProperties`

`codraw.admin.login` и `codraw.admin.password` — поля `AdminProperties` с пустыми значениями по умолчанию. При
создании свойства проверяют: заданы оба или ни одного; логин и пароль проходят `PasswordRules`. Ошибка не даёт
`backend` запуститься и называет переменную, но не значение пароля. `toString` у класса переопределён без пароля:
data class иначе напечатал бы его в сообщениях о привязке настроек. `accounts` включает `password` + логин в нижнем
регистре, поэтому администратор, резерв логина и запрет блокировки работают без изменений.

### Учётная запись при старте

`ConfiguredAdmin` по `ApplicationReadyEvent` (после миграций) вызывает `PasswordService.ensureAccount(login, password)`
в одной транзакции:

1. пользователь `password` + логин — найти или создать (`UserService.signUp` без гостя; имя — логин из настроек);
2. хеш нет или не подходит к паролю из настроек — записать новый и удалить все сеансы пользователя;
3. снять блокировку, если она была (администратора заблокировать нельзя, но строка могла быть заблокирована до того,
   как её логин вписали в настройки).

Подходящий хеш не пересчитывается: старт стоит одну проверку bcrypt. При нескольких экземплярах `backend` создание
не гонится — `INSERT … ON CONFLICT DO NOTHING`, — а запись хеша одинакова у всех.

Если логин уже зарегистрировал кто-то другой до того, как оператор вписал его в настройки, учётная запись переходит к
оператору с паролем из настроек. Это ожидаемо: настройка решает, кто администратор; `docs/deploy.md` об этом говорит.

### Вход по паролю без общего входа по паролю

`PasswordSignIn` (в пакете `password`) отвечает на два вопроса для `GET /api/auth/providers`, `/api/legal` и
`PasswordController`: предлагается ли вход по паролю (`codraw.passwords.enabled` или задан администратор) и
регистрация (`enabled` и `sign-up`). Установка только с администратором из настроек показывает форму входа без
«Зарегистрироваться»; политика конфиденциальности говорит о хеше пароля, раз он хранится.

### Пароль меняет только настройка

`/api/me` получает `passwordFromSettings`. Раздел «Пароль» на странице «Учётная запись» для такого пользователя
вместо формы говорит: «Пароль этой учётной записи задаёт настройка сервера `CODRAW_ADMIN_PASSWORD`…».
`PUT /api/me/password` отвечает 403 `password-from-settings`: иначе следующий старт молча вернул бы прежний пароль.

## Risks / Trade-offs

- [Пароль в переменной окружения] → виден тому, у кого есть доступ к Docker на сервере, как и пароль базы; после
  первого входа оператор может оставить его там — он и есть способ восстановить доступ.
- [Логин, занятый до настройки] → переходит к оператору; описано в `docs/deploy.md`.

## Migration Plan

Миграции нет. Без `CODRAW_ADMIN_LOGIN` поведение прежнее. Чтобы убрать администратора из настроек, оператор убирает
переменные и перезапускает `backend`: учётная запись остаётся обычной учётной записью с паролем, без прав
администратора.
