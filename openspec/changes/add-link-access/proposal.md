# Proposal

## Why

Любой, у кого есть ссылка на доску, может её редактировать, и это нельзя ни ограничить, ни отозвать. Показать схему
коллеге или заказчику только для чтения нельзя, а разосланную по ошибке ссылку не закрыть: доступ остаётся навсегда.

## What Changes

- `backend`: у доски есть режим доступа по ссылке: `none` — только владелец, `view` — просмотр, `edit` —
  редактирование. Новые и уже существующие доски получают `edit`, как сейчас. Владелец меняет режим запросом
  `PATCH /api/boards/{id}` с полем `linkAccess`.
- `backend`: новая роль `viewer`. При режиме `none` не владелец получает 403 и на сведения о доске, и на токен
  синхронизации. Токен синхронизации содержит роль пользователя.
- `collab`: соединение с ролью `viewer` только читает документ: сервер не применяет его изменения.
- `collab`: доступ открытого соединения перепроверяется без переподключения: сервер запрашивает у клиента новый
  токен, когда истекает прежний и когда участник сообщил об изменении доски. Пониженная роль переводит соединение
  в чтение, отозванный доступ закрывает его.
- `frontend`: у владельца на странице доски кнопка «Поделиться»: ссылка на доску, «Скопировать ссылку» и выбор
  режима доступа.
- `frontend`: режим просмотра: без палитры, инструментов правки, меню холста, быстрых связей, правки страниц
  и импорта, с меткой «Только просмотр»; масштаб, прокрутка, переход между страницами и к участникам и экспорт
  остаются. Смена роли во время работы меняет режим страницы без перезагрузки.
- `frontend`: «Нет доступа к доске» — при открытии доски с закрытым доступом и сразу после того, как владелец закрыл
  доступ во время работы.
- Раздел «Открытые по ссылке» не показывает доски с закрытым доступом и отмечает доски только для просмотра.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `board-access`: доступ по ссылке зависит от режима доски; новый режим доступа и его настройка владельцем, роль
  в токене синхронизации, соединения только для чтения, перепроверка доступа открытых соединений, режим просмотра
  и сообщение «Нет доступа к доске».
- `board-management`: сведения о доске сообщают роль `viewer` и режим доступа по ссылке и отвечают 403 при закрытом
  доступе; список открытых по ссылке не показывает закрытые доски.

## Impact

- `backend`: столбец `boards.link_access` и пара миграций V/U, `BoardController`, `BoardService`,
  `CollabTokenController`, `CollabTokenService` (claim `role`). API: поле `linkAccess` в ответах и в `PATCH`, роль
  `viewer`, статус 403, поле `role` в ответе токена.
- `collab`: `auth.ts` (роль из токена), `server.ts` (`readOnly`, перепроверка через `onTokenSync`, таймеры
  продления).
- `frontend`: `api/boards.ts`, `BoardPage.tsx`, `useBoardConnection.ts`, `diagram/editor.ts` и `binding.ts`
  (холст и связка только для чтения), `PageTabs.tsx`, `EditorToolbar.tsx`, `DrawioActions.tsx`, новый компонент
  «Поделиться», `BoardsPage.tsx`.
- Зависит от `add-board-management`: роль в сведениях о доске, `PATCH /api/boards/{id}` и сообщение
  `board-changed`.
