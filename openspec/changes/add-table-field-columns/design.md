# Design

## Context

Таблица — ячейка `swimlane` со стопкой полей (`childLayout: stackLayout`, `TableLayout` в `diagram/editor.ts`), поле —
дочерняя ячейка с текстом `имя тип PK FK NOT NULL UNIQUE …`, подпись — обычный текст maxGraph (`htmlLabels` выключены
ради безопасности). Из этого текста `sql/erDiagram.ts` (`parseFieldLabel`, `diagramSchema`) собирает схему для
выгрузки SQL и Mermaid; внешний ключ — связь между полями, направление определяет `referenceOf` (пометка `FK`, затем
первичный ключ на другом конце, затем маркеры). Тот же текст пишут импорт SQL и Mermaid (`fieldLabel`), шаблоны
(`DiagramBuilder.table`), импорт draw.io; ячейки синхронизируются через Yjs как есть. Автоширина
(`fitAutoWidth`/`fittedWidthOf`) меряет подписи через canvas (`measureLabel`).

## Goals / Non-Goals

**Goals:**

- Поле видно колонками: значок PK/FK, имя, тип, `NULL`/`NOT NULL`, `→ таблица.поле`, остальной текст.
- Тип, нулабельность, PK и UNIQUE задаются без набора текста; у таблицы есть СУБД со значком и своими типами.
- Ни одной миграции данных: старые доски, файлы draw.io, шаблоны, импорт и выгрузки работают как раньше.

**Non-Goals:**

- Выгрузка SQL в диалектах, кроме PostgreSQL (СУБД на неё не влияет).
- Выбор цели внешнего ключа на панели; `ON DELETE`, индексы, комментарии столбцов.
- Перенос колонок поля на несколько строк; таблица без автоширины, которая уже колонок, обрезает их.

## Decisions

### Текст поля остаётся единственным источником данных

- Колонки — это способ показать текст, а не новые данные. Альтернатива — хранить имя в `value`, а тип и флаги в стиле
  ячейки — отклонена: потребовала бы миграции всех досок, правки импорта/выгрузок/шаблонов, а в draw.io поля ушли бы
  без типов. HTML-подписи с разметкой отклонены: разметка попала бы в данные и в редактор подписи, а HTML от других
  участников — риск внедрения скриптов.
- Разбор поля — новый модуль `sql/tableField.ts`: `splitField(text)` → имя как написано, тип как написан (регистр
  сохраняется: `VARCHAR2(255)` у Oracle), флаги PK/FK/NOT NULL/UNIQUE и остаток (`DEFAULT now()`); `fieldText(parts)`
  собирает канонический текст `имя тип [PK] [FK] [NOT NULL] [UNIQUE] остаток` (у PK `NOT NULL` не пишется, nullable —
  без пометки, как в `fieldLabel`). Токены — `tokenize` из `parseSql.ts`; склейка токенов в текст — `typeText` с
  флагом сохранения регистра. `parseFieldLabel` (выгрузка) не меняется.

### Отрисовка: фигура подставляется при отрисовке, а не хранится

- `graph.getCellStyle` в редакторе дополняет стиль поля таблицы: `shape: 'codraw.tableField'` и отступы, которые
  ограничивают подпись колонкой имён (слева — место под значок, справа — до колонки типов), так что выравнивание
  текста работает внутри колонки имён. В данных (Yjs, draw.io) стили не меняются.
- `codraw.tableField` (наследник прямоугольника) берёт ячейку из `this.state`, строит строку таблицы функцией
  `tableRows` и рисует значок (путями — ключ или звено, одинаково на холсте и в SVG/PNG) и колонки тип / NULL /
  ссылка+остаток через `c.text` цветом текста поля с прозрачностью 0,6. Имя рисует обычная подпись maxGraph:
  `graph.getLabel` у поля возвращает имя, поэтому размер, начертание, цвет текста и выделение работают как раньше.
- `diagram/tableRows.ts` — чистая функция: поля таблицы (текст, шрифт), связи → для каждого поля значок, части и
  X-позиции колонок (ширина колонки — самое длинное значение в таблице, промежуток 12 px) и полная ширина строки.
  Измерение текста передаётся параметром: в редакторе — `measureLabel` (canvas), при импорте — оценка по числу
  символов (`ширина ≈ 7,5 × длина`), в тестах — детерминированная.
- Цель ссылки: для каждой связи поля с полем другой таблицы ссылающийся конец определяет то же правило, что и
  выгрузка, — `referenceOf` выносится из `erDiagram.ts` в общую функцию. Поле со значком FK — ссылающийся конец или
  поле с `FK`/`REFERENCES` в тексте; ключ (PK) важнее звена.
- Фигура `swimlane` заменяется наследником `SwimlaneShape` (как `rectangle` — своим прямоугольником), который у
  таблицы с `dbVendor` рисует в заголовке слева скруглённый значок СУБД с сокращением (PG #336791, MY #00758F,
  ORA #C74634, MS #A91D22, LITE #0F80CC, CH #FAFF69 с чёрным текстом). Своё имя фигуры у таблицы отклонено: maxGraph
  узнаёт заголовок и раскладку полей по `shape=swimlane` (`isSwimlane`). Логотипы не используются: чужие товарные
  знаки и картинки в репозитории не нужны, а сокращение читается при любом масштабе.
- Перерисовка: колонки поля зависят от соседних полей и от связей, а maxGraph перерисовывает только изменённые
  ячейки. Поэтому после каждого изменения модели (своего или пришедшего от других участников) редактор собирает
  затронутые таблицы — таблицы изменённых полей и таблиц, таблицы на концах изменённых связей и таблицы, связанные
  с ними связями между полями, — и перерисовывает их поля заново, со стилем (граница колонки имён). Строки таблицы
  кэшируются до следующего изменения модели (`InternalEvent.EXECUTE`), так что таблица раскладывается раз на отрисовку.

### Редактирование

- Имя: `graph.getEditingValue` у поля возвращает имя; `graph.cellLabelChanged` у поля пишет `renameField(старый,
  введённый)`: одно слово (или имя в кавычках) заменяет имя, сохраняя остальное; больше одного слова — текст поля
  целиком, как раньше, чтобы новое поле можно было набрать строкой. Пустой ввод у поля с текстом оставляет поле как
  было.
- Панель (`EditorToolbar`): состояние редактора получает `field` (тип, PK, NOT NULL, UNIQUE, СУБД таблицы) для одного
  выделенного поля и `tableVendor` для выделенной таблицы или её поля. Команды `setFieldProps(patch)` и
  `setTableVendor(vendor)` — один шаг отмены, затем `fitAutoWidth`; обе в `CHANGING_COMMANDS` (в режиме «Просмотр»
  не выполняются).
- «Тип» — `<input list>` с `<datalist>` типов СУБД: браузер сам фильтрует список и даёт ввести свой тип; применение —
  по Enter, уходу из поля и выбору из списка, Escape возвращает текущий тип (как `NumberField`). «СУБД» — `<select>`
  в стиле маркеров связи. `NULL`/`NOT NULL`, «PK», «UNIQUE» — кнопки с `aria-pressed`.
- Типы СУБД — `sql/dbVendors.ts`: id, название, сокращение, цвета, 15–25 частых типов (PostgreSQL: `uuid`, `text`,
  `varchar(255)`, `integer`, `bigint`, `numeric(10,2)`, `boolean`, `timestamptz`, `jsonb`…; MySQL/MariaDB: `int`,
  `varchar(255)`, `datetime`, `json`…; Oracle: `NUMBER(10)`, `VARCHAR2(255)`, `CLOB`, `TIMESTAMP`…; SQL Server:
  `int`, `nvarchar(255)`, `uniqueidentifier`, `datetime2`…; SQLite: `INTEGER`, `TEXT`, `REAL`, `BLOB`, `NUMERIC`;
  ClickHouse: `UInt64`, `String`, `DateTime64(3)`, `Nullable(String)`…). Ключ стиля таблицы — `dbVendor`.

### Новые таблицы и ширина

- Пресет «Таблица» в палитре получает `dbVendor: postgresql` и автоширину (`autosize`); через пресет их получают и
  таблицы шаблонов, импорта SQL и Mermaid — всё, что строит `DiagramBuilder.table`. `TABLE_STYLE` (признак таблицы,
  сопоставление с draw.io) не меняется; у таблиц из draw.io и со старых досок СУБД нет.
- `fittedWidthOf` у таблицы берёт ширину строки из `tableRows`, у заголовка добавляет ширину значка СУБД (с обеих
  сторон, так как имя таблицы по центру). `fitAutoWidth` вызывается и после смены СУБД и свойств поля, а также для
  таблиц, чьи поля показывают ссылку на изменённое поле, таблицу или новую связь.
- Импорт: `tableWidth` в `erDiagram.ts` считает по той же раскладке с оценкой по символам, верхняя граница — 560.

## Risks / Trade-offs

- [Старая таблица без автоширины уже своих колонок] → колонки обрезаются по правому краю; участник включает
  «Автоширину» или растягивает таблицу. Миграцию ширины не делаем: она поменяла бы чужие доски без их участия.
- [Перерисовка связанных таблиц на каждое изменение] → затрагиваются только таблицы изменённых ячеек и их соседи по
  связям; разбор поля — микросекунды, сотни полей перерисовываются без заметной задержки.
- [Подмена `getCellStyle`/`getLabel`/`cellLabelChanged` и фигуры `swimlane`] → касается только полей таблиц и таблиц
  с СУБД; остальные ячейки идут исходным путём. Выгрузка draw.io пишет данные Yjs, а не отрисованный стиль, поэтому подмена в файл не попадает.
- [Тип из нескольких слов или с запятыми (`timestamp with time zone`, `numeric(10, 2)`)] → `splitField` читает тип
  до первой пометки, как `parseFieldLabel`; тесты покрывают такие типы.
- [jsdom не меряет текст] → раскладка тестируется с переданной функцией измерения; вид проверяется e2e в браузере.

## Migration Plan

Не требуется: новые ключи стиля (`dbVendor`, `autosize`) появляются только у новых таблиц, текст полей не меняется.
Откат — откат фронтенда; доски с `dbVendor` открываются старой версией без значка.
