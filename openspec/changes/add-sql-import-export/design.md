# Design

## Context

Таблица БД в CoDraw — ячейка со стопкой полей (`childLayout: stackLayout`), поле — дочерняя ячейка с текстом вида
`id uuid PK`; так их строят шаблон ER-диаграммы (`DiagramBuilder.table`) и палитра. Связи между полями — обычные связи
с маркерами «воронья лапка» (`ERzeroToMany`, `ERmandOne` и др.). Автораскладка (`diagram/layout.ts`) раскладывает
фигуры слоями по связям. Вставка ячеек одним шагом отмены — `editor.insertCells`.

## Goals / Non-Goals

**Goals:**

- Разбор реального DDL PostgreSQL, в том числе миграций Flyway целиком, без сервера.
- Выгрузка, которую можно выполнить в PostgreSQL как есть, и Mermaid, который рисует GitHub.

**Non-Goals:**

- Синхронизация уже нарисованных таблиц с новым DDL (обновление на месте) — отдельное изменение.
- Индексы, представления, перечисления, схемы (`schema.table` берётся по имени таблицы), комментарии столбцов.
- Liquibase XML/YAML, диалекты кроме PostgreSQL и общей части MySQL.

## Decisions

### Свой разборщик DDL вместо библиотеки

- Лексер (идентификаторы в двойных кавычках и обратных апострофах, строки, `$$`-тела функций, комментарии) и разбор
  только нужных операторов: `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`. Остальное считается пропущенным, а не
  ошибкой: миграции полны индексов, функций и данных.
- Альтернативы: `node-sql-parser` (около 1 МБ, падает на целом файле при первом незнакомом операторе, слаб в
  PostgreSQL), `pgsql-parser` (парсер PostgreSQL в WebAssembly, 2+ МБ ради трёх операторов). Отклонены по размеру и
  устойчивости: нам нужна схема, а не полное дерево.
- Состояние схемы меняется по операторам по порядку, поэтому цепочка миграций даёт итоговую схему: переименования
  таблиц и столбцов переносятся во внешние ключи, удаление таблицы убирает ссылки на неё.

### Порядок файлов

- Миграции Flyway: `V<версия>__` по версии (`1_1` < `2` < `10`), затем повторяемые `R__`, затем прочие файлы по имени;
  `U<версия>__` (откаты) не применяются.

### Таблицы → ячейки

- `DiagramBuilder.table` с шириной по самому длинному тексту (160–420), поле — `fieldLabel`: имя (в кавычках, если
  не простой идентификатор), тип, `PK`, `FK`, `NOT NULL`, `UNIQUE`.
- Связь — от поля внешнего ключа к полю, на которое он ссылается (к первичному ключу, если столбцы не названы);
  составной ключ — связь на каждую пару столбцов. Маркеры: у ссылающегося — `ERzeroToMany` или `ERzeroToOne` для
  уникального столбца, у таблицы, на которую ссылаются, — `ERmandOne` для `NOT NULL` и `ERzeroToOne` иначе.
- Раскладка — `layoutShapes` слева направо по связям таблиц; новые таблицы встают справа от фигур страницы с отступом
  80 (на пустой странице — у угла), вставка — `insertCells`, один шаг отмены, таблицы выделены.

### Ячейки → SQL и Mermaid

- Таблицы страницы — ячейки со стопкой полей; столбец — разбор текста поля: первое слово — имя, дальше тип до слов
  `PK`, `FK`, `NOT NULL`, `UNIQUE`, `PRIMARY KEY`, `REFERENCES`, `DEFAULT`; без типа — `text`. Так читаются и поля,
  написанные руками.
- Внешний ключ — связь между полями двух таблиц. Ссылающийся конец: поле с `FK`; иначе поле, не являющееся первичным
  ключом, когда другой конец им является; иначе конец без маркера «один»; иначе начало связи.
- SQL: `CREATE TABLE` всех таблиц, потом `ALTER TABLE … ADD FOREIGN KEY` — порядок таблиц и циклы ссылок не важны.
  Имена — в кавычках, если не простые идентификаторы или зарезервированные слова PostgreSQL.
- Mermaid: `erDiagram` с атрибутами `тип имя PK, FK, UK` (пробелы и запятые типа — `_`) и отношениями
  `||--o{` / `|o--o{` / `||--o|` по обязательности и уникальности.

### Интерфейс

- Кнопка «SQL» (иконка базы данных) в шапке рядом с экспортом в изображение: окно с «Импорт SQL…» (у тех, кто правит
  доску) и выгрузками с числом таблиц страницы. Импорт — в том же окне: поле для текста, «Открыть файлы .sql»
  (несколько), сводка «Таблиц: N, связей: M, пропущено операторов: K» и «Добавить на страницу».

## Risks / Trade-offs

- [Незнакомый синтаксис] → оператор пропускается, сводка показывает число пропущенных; в худшем случае таблица
  получится без части столбцов, а не сломается импорт.
- [Текст поля, изменённый руками] → разбор поля терпим к лишнему: всё после типа, кроме ключевых слов, отбрасывается.
- [Большая схема] → сотни таблиц раскладываются за доли секунды; размер страницы не ограничивается сверх пределов
  документа.
