# Proposal

## Why

README обещает «Офлайн-режим — правки сохраняются локально и синхронизируются при восстановлении связи», а ADR-0001
называет `y-indexeddb` в стеке, но сделано это только наполовину. Страница доски держит документ в памяти: при потере
связи она показывает «Нет связи» и копит правки, пока вкладка открыта, а закрытая без связи вкладка теряет их совсем.
Каждое открытие доски ждёт сервер, даже если эта доска была открыта минуту назад. В поезде, в самолёте и на плохом
Wi-Fi на конференции схему правят именно без связи; Figma и Miro приучили, что такие правки не пропадают.

## What Changes

- `frontend`: копия доски на устройстве. Документ каждой открытой доски хранится в IndexedDB браузера отдельно для
  каждого пользователя и доски: другой пользователь того же браузера её не видит. Страница сразу показывает копию, не
  дожидаясь сервера, без связи правки сохраняются в копию и уходят в `collab` при восстановлении связи — и в той же
  вкладке, и когда доску открывают снова после закрытия вкладки.
- Статус: без связи — «Нет связи», а под шапкой — «Нет связи — правки сохраняются на этом устройстве», с
  неотправленными правками — ещё «Не отправлено: есть правки», после отправки — «Синхронизировано». Когда браузер
  сообщает о потере сети, страница сама закрывает соединение, а при появлении сети подключается сразу.
- Правки копии уходят только по соединению с правом правки. Участник, потерявший право правки (ссылка или его роль
  участника дают «Просмотр» или ничего), с неотправленными правками видит «Правки, сделанные без связи, не отправлены:
  у вас больше нет права правки» с «Скачать копию (.drawio)» и «Удалить копию с устройства»; когда право правки
  возвращается, например в ответ на «Запросить правку», правки уходят на доску. У удалённой доски копия удаляется, а с
  неотправленными правками сначала предлагается скачать её. Отказ по предельному размеру — прежнее предупреждение,
  копия с неотправленными правками остаётся на устройстве с теми же «Скачать» и «Удалить».
- Восстановление версии и страницы версии, которое сначала сохраняет доску версией «Перед восстановлением», доступно
  только при синхронизированном соединении: копия без связи не знает чужих правок.
- Читатель хранит копию для чтения и ничего из неё не отправляет.
- Гигиена: выход и смена пользователя в браузере удаляют копии прежнего пользователя; у пользователя — не больше 20
  копий, сначала удаляются давно не открытые. Удалённая владельцем доска не оставляет копий.
- Политика конфиденциальности и README: копии досок в хранилище браузера и как их удалить.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `realtime-sync`: копия доски на устройстве, работа без связи и отправка правок после восстановления связи, статус
  неотправленных правок, правки без права правки и их отправка, когда право вернулось, восстановление версии только со
  связью, копии при выходе и смене пользователя, копия при отказе по размеру.
- `legal-pages`: политика конфиденциальности называет копии досок в хранилище браузера и способы их удалить.

## Impact

- `frontend`: зависимость `y-indexeddb` (и `fake-indexeddb` для тестов), модуль `offline/` (копии досок, их реестр,
  сообщение о неотправленной копии), `useBoardConnection` (документ страницы с копией и документ соединения),
  статус и сообщения на странице доски и под «Нет доступа», восстановление версии и страницы только со связью
  (`VersionPreview`), удаление копий при выходе, смене пользователя и удалении доски, политика конфиденциальности.
- `collab` и `backend` не меняются: правки копии доходят до `collab` обычными правками Yjs, а соединение только для
  чтения `collab` по-прежнему не принимает.
- Вне изменения: загрузка самого приложения без сети (service worker), список досок без сети, открытие доски, которую
  страница ещё не загрузила из API.
