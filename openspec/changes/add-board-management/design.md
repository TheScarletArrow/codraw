# Design

## Context

Доска — строка `boards` с владельцем (`owner_id`) и Yjs-документ в `board_documents`, который `collab` загружает
и сохраняет через внутренний API `backend`. Название доски живёт только в `boards`: страница доски получает его
запросом `GET /api/boards/{id}` один раз при открытии. Доступ к доске даёт ссылка: `GET /api/boards/{id}` и токен
синхронизации выдаются любому вошедшему пользователю или гостю. Требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Удалённая доска не возвращается: ни один участник не может пересохранить её документ.
- Участники открытой доски узнают о переименовании и удалении без опроса сервера.

**Non-Goals:**

- Корзина и восстановление удалённой доски.
- Переименование доски участниками, которые ею не владеют, передача владения.
- Удаление доски из списка «Открытые по ссылке» вручную, поиск и сортировка в списках.

## Decisions

### API

- `PATCH /api/boards/{id}` с телом `{"title": "…"}` переименовывает доску, `DELETE /api/boards/{id}` удаляет её.
  `PATCH`, а не `PUT /title`: следующие изменения добавят в тело другие поля доски.
- Права проверяет контроллер: несуществующая доска — 404, доска другого владельца — 403. Ответ 403, а не 404:
  участник уже открыл доску по ссылке и знает, что она существует.
- В ответ о доске добавляются `owner` (`id`, `name`, `avatarUrl`) и `role` — роль того, кто спрашивает: `owner` или
  `editor`. Фронтенд по `role` решает, показывать ли переименование и удаление, и не сравнивает идентификаторы сам.
- Переименование меняет `updated_at`: список своих досок отсортирован по нему, и переименованная доска поднимается
  наверх.

### Удаление

- Удаление жёсткое: `DELETE FROM boards`, документ и посещения удаляются каскадом по внешним ключам. Альтернатива —
  мягкое удаление с отметкой времени — отложена вместе с корзиной: без интерфейса восстановления она только
  усложняет каждый запрос к доскам.
- После удаления внутренний API документа отвечает 404 и на загрузку, и на сохранение (это уже так: `touch` не
  находит доску). Когда `collab` получает 404 на сохранение, он закрывает все соединения документа с причиной
  `board-not-found` и не повторяет сохранение. Так удаление из списка досок доходит до участников с их первой же
  правкой, а изменения удалённой доски не сохраняются.

### Доски, открытые по ссылке

```
board_visits (user_id uuid → users ON DELETE CASCADE, board_id uuid → boards ON DELETE CASCADE,
              visited_at timestamptz NOT NULL, PRIMARY KEY (user_id, board_id))
INDEX (user_id, visited_at DESC)
```

- Посещение записывает `GET /api/boards/{id}`, когда доску спрашивает не владелец: `INSERT … ON CONFLICT DO UPDATE
  SET visited_at`. Страница доски делает этот запрос при каждом открытии, поэтому другой точки записи не нужно.
  Альтернативы: запись при выдаче токена синхронизации — отклонена, токен запрашивается при каждом переподключении,
  то есть посещение записывалось бы на каждое переподключение; отдельный `POST /api/boards/{id}/visits` — лишний
  запрос, о котором фронтенд должен помнить. Побочный эффект `GET` безопасен: повтор запроса только обновляет время.
- `GET /api/boards/shared` — один запрос с соединением `board_visits`, `boards` и `users` (владелец), условием
  `owner_id <> текущий пользователь` и `LIMIT 50`. Условие по владельцу, а не удаление строки посещения, убирает
  из списка доску, которая перешла к пользователю вместе с досками гостя.
- При входе из гостевого сеанса посещения гостя переносятся в той же транзакции, что и доски:
  `INSERT … SELECT … ON CONFLICT DO UPDATE SET visited_at = GREATEST(…)`, затем строки гостя удаляются.

### Как участники узнают о переименовании и удалении

- После переименования или удаления на странице доски фронтенд владельца отправляет через провайдер Hocuspocus
  служебное сообщение (stateless) `{"type":"board-changed"}`.
- `collab` принимает от клиента только этот тип и рассылает остальным соединениям того же документа своё
  сообщение `{"type":"board-changed"}`, а не полученную строку: клиент не может переслать через `collab` произвольный
  текст.
- Фронтенд, получив `board-changed`, заново запрашивает `GET /api/boards/{id}`: новое название появляется в шапке,
  а ответ 404 показывает «Доска не найдена» и закрывает провайдер.
- Сообщение ничего не меняет само, это только подсказка обновить данные. Участник, который рассылает его без
  причины, добивается лишь лишних `GET` — меньше, чем может навредить правками документа.

Альтернативы:

- Хранить название в Yjs-документе. Отклонено: у названия стало бы два источника — `boards` для списков и документ
  для страницы, и `backend` пришлось бы писать в документ через `collab`.
- Сигнал от `backend` в `collab`. Отклонено: новое направление зависимости между сервисами, а при нескольких
  экземплярах `collab` `backend` не знает, какой из них держит документ. Служебное сообщение приходит именно
  в тот экземпляр, к которому подключены участники.
- Периодический опрос `GET /api/boards/{id}`. Отклонено: запросы от каждой открытой вкладки ради редкого события.

### Фронтенд

- Общий компонент поля названия: Enter или потеря фокуса сохраняют, Escape отменяет, пустое после обрезки название
  не отправляется. Он используется и в списке досок, и в шапке доски.
- Меню доски и подтверждение удаления — на `Popover`, который уже есть в проекте; подтверждение называет доску
  и предупреждает, что её нельзя восстановить.
- После переименования ответ `PATCH` кладётся в кэш запроса доски, список досок помечается устаревшим. После
  удаления запрос доски удаляется из кэша, и открывается главная страница.

## Risks / Trade-offs

- [Доску удалили по ошибке] → подтверждение с названием доски; восстановления нет, это записано в предупреждении.
- [Участник удалённой доски, который ничего не меняет, видит её до перезагрузки, если доску удалили из списка] →
  ничего не теряется: его правки и так не сохранились бы; первая же правка закрывает соединение.
- [Переименование из списка досок не доходит до открытых страниц доски сразу] → страница доски обновит название при
  следующем запросе, например при возвращении фокуса во вкладку; мгновенно название меняется при переименовании
  на странице доски.
- [`board_visits` растёт] → одна строка на пару «пользователь — доска», строки удаляются каскадом вместе с доской.

## Migration Plan

1. Пара миграций V3/U3: таблица `board_visits` и её индекс; U3 удаляет таблицу.
2. Выкатить `backend`, затем `collab`, затем `frontend`: новые поля ответа старый фронтенд игнорирует, а `collab`
   без сообщений `board-changed` работает как раньше.
3. Откат — U3 и предыдущие версии сервисов; удалённые доски откат не возвращает.
