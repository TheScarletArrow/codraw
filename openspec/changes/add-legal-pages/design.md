# Design

## Context

Маршруты приложения: `/login` открыта всем, остальные — в `Layout`, который без сеанса уводит на `/login`. `backend`
без входа отдаёт только проверки здоровья, метрики, JWKS, вход гостя и (после `add-client-error-reports`) отчёты об
ошибках. Настройки развёртывания — `@ConfigurationProperties` с переменными окружения `CODRAW_*` в
`docker-compose.prod.yml`. Образ `frontend` статический: настроек времени запуска у него нет. Требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Тексты описывают то, что CoDraw делает на самом деле: данные, cookie, сроки, получателей.
- Оператор задаётся при развёртывании, без пересборки образов.

**Non-Goals:**

- Юридическая экспертиза текстов и их переводы.
- Баннер согласия на cookie: CoDraw ставит только необходимые cookie, для них согласие не нужно.
- Удаление аккаунта из интерфейса: удаление — по обращению к оператору.

## Decisions

### Данные оператора

- `codraw.legal.operator` и `codraw.legal.contact-email` (`LegalProperties`, по умолчанию пустые), отдаёт их
  `GET /api/legal` без входа: страницы открыты всем. Альтернатива — подставлять их в статику nginx при запуске
  контейнера. Отклонена: `backend` уже читает настройки окружения, а nginx-шаблон пришлось бы усложнять.
- Пустые значения — `null` в ответе; страницы тогда пишут «оператор не указал свои данные» вместо пустого места.

### Страницы

- `legal/LegalPage.tsx` — общая вёрстка (заголовок, оглавление разделов, «Обновлено», ссылки друг на друга и на
  вход); тексты — в `legal/privacy.tsx` и `legal/terms.tsx` как разметка React: так в них подставляются оператор и
  ссылки, и их видно в ревью.
- Факты в тексте берутся из кода: 30 дней хранения досок ушедших гостей, 100 версий доски, cookie `SESSION` и
  `XSRF-TOKEN`, адреса в журналах и счётчиках пределов, отчёты об ошибках без содержимого досок. Тест сверяет
  ключевые числа текста с константами, где они есть во `frontend`.
- Маршруты `/privacy` и `/terms` — вне `Layout`, рядом с `/login`, с тем же `errorElement`.

### Согласие

- На странице входа под кнопками — строка о том, что вход и «Продолжить без входа» означают согласие с условиями
  и политикой, со ссылками. Отдельной галочки нет: так делают GitHub и Figma, а пользоваться без согласия нельзя
  в любом случае.

## Risks / Trade-offs

- [Текст расходится с поведением после будущих изменений] → изменения, которые добавляют данные или cookie, должны
  обновлять политику; это записано в README рядом с разделом о данных.
- [Оператор не задал данные] → страницы честно говорят об этом, а `docs/deploy.md` требует задать их перед
  открытым запуском.
