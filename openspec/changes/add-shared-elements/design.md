# Design

## Context

После #82 свойства фигуры хранятся в карте документа `elements`: `elementId → {name, kind, technology, description,
owner, tags}`. Ячейка ссылается на элемент ключом стиля `codrawElement`. Для всего, кроме хранения, свойства — ключи
стиля ячейки (`codrawName`, `codrawTechnology`, …): их добавляет `readCell` и раскладывает обратно `writeCell`. Привязка
страницы перечитывает свои ячейки, когда меняется элемент, на который они ссылаются. Каждая копия сейчас получает новый
элемент (хук `graph.cloneCells`, дублирование страницы, импорт). Элемент удаляется, когда ни одна ячейка ни одной
страницы на него больше не ссылается.

Подпись ячейки (`value`) хранится у каждой ячейки отдельно. У элемента C4 она собирается из свойств:
`имя / [Тип: технология] / описание`. У прочих фигур это имя, `[технология]` по флагу ячейки и свои строки. Подпись
собирает редактор той страницы, на которой правят свойства. Модуль подписей `diagram/elementProps.ts` зависит от
`shapes.ts`, а через него от maxGraph, поэтому живёт в ленивом бандле страницы доски. `readCell` в `model.ts` — в
основном бандле (им пользуется экспорт `.drawio` списка досок). Текст доски для поиска в списке досок `collab` читает
прямо из `value` ячеек.

История отмены — `Y.UndoManager` страницы над `cells:<pageId>` и `elements` с происхождением своей страницы
`localOrigin(pageId)`.

## Goals / Non-Goals

**Goals:**

- Один элемент — много ячеек на любых страницах: свойства и подписи всех ячеек следуют за элементом в одной правке,
  которая отменяется одним шагом там, где её сделали.
- Способы получить ячейку того же элемента: вставка, панель, объединение. Узнать, где он используется, отделить ячейку
  и удалить элемент со всех страниц.
- Без миграции документов и без новых данных: те же `elements` и `codrawElement`.

**Non-Goals:**

- Общие связи, неявные связи и вычисляемые представления (#96).
- Элементы, общие для нескольких досок. Общий для всех ячеек статус или закрепление.
- Дублирование страницы с теми же элементами: копия страницы по-прежнему получает новые элементы. Тот же результат
  даёт «Выделить всё», «Копировать» и «Вставить как тот же элемент» на новой странице.

## Decisions

### Подписи всех ячеек элемента пишутся в той же транзакции

Изменение свойств элемента одной транзакцией переписывает `value` всех остальных его ячеек на всех страницах. Новая
подпись каждой ячейки собирается по правилам #82 из новых свойств, её собственных строк и её флага «Технология на
схеме». Своё у ячейки считается по её стилю и подписи до правки, то есть с прежними свойствами. Иначе смена типа на
C4 по новым свойствам выбросила бы свои строки.

- Где это делается: в привязке страницы (`DiagramBinding.handleLocalChanges`) для любой локальной правки, которая
  изменила свойства элемента. Неважно, откуда правка: панель, подпись на холсте, восстановление части версии, вставка
  тем же элементом или объединение. Кроме привязки, это делают `restorePage` и `mergeProposal`: они пишут документ
  мимо привязки. Ячейки текущей страницы, которых правка не коснулась (вторая ячейка элемента на той же странице),
  привязка после транзакции перечитывает в модель maxGraph.
- Альтернатива — подпись ячейки элемента вычисляется при чтении (`readCell`). Тогда подписи согласованы по построению,
  и одновременные правки не расходятся. Отклонена: сборка подписи зависит от фигур палитры и maxGraph, а `readCell` — в
  основном бандле. Кроме того, `collab` и комментарии читают сохранённое `value`, и поиск по доскам находил бы старые
  имена.
- Альтернатива — подписи чинит каждый клиент на своей странице, когда видит изменение элемента. Отклонена как основной
  путь: правка перестала бы быть атомарной, отмена не вернула бы подписи страниц, которые никто не открыл, а в списке
  досок искались бы старые имена. Как запасной путь она нужна, см. ниже.

### История страницы отслеживает весь документ

`createUndoManager` получает областью весь `Y.Doc`, а `trackedOrigins` остаётся происхождением своей страницы. Поэтому
переименование вместе с подписями других страниц и удаление со всех страниц — один шаг отмены той страницы, где их
сделали. Отмена другой страницы их не трогает: у неё другое происхождение. Прежняя область `[cells, elements]` не
видела бы подписей других страниц, а держать в области карты всех страниц и добавлять новые по мере появления —
лишний код ради того же результата.

### Починка подписей после одновременных правок

Если два участника одновременно меняют разные свойства одного элемента, свойства сливаются по ключам, а `value`
ячеек — по правилу «последний пишущий». Подпись может показать только одну из правок. Привязка, которая правит доску,
при открытии страницы и при каждом изменении элемента извне сверяет подписи ячеек своей страницы с подписью по
свойствам. Расхождение она переписывает отдельной транзакцией с происхождением `codraw:relabel`: такую транзакцию не
отменяет ни одна история и она не меняет отметку «кто изменил». Запись детерминирована, поэтому несколько клиентов,
починивших одно и то же, сходятся к одному значению. Починка не вызывает новых изменений элементов, а значит, и
бесконечных повторов. Заодно она чинит подписи, которые разошлись у клиентов прошлой версии без переподписи.

### Модуль общих элементов поверх документа

`diagram/sharedElements.ts` работает с `Y.Doc` и не зависит от maxGraph:

- `elementUses(doc)` — ячейки каждого элемента по страницам;
- `relabelElementCells` — переподпись после правки;
- `healLabels` — починка;
- `ensureElement` — сделать элементом ячейку без элемента, взяв свойства из подписи;
- `mergeElements`, `detachCell`, `removeElementCells` — с закрытием по вложенным ячейкам и связям, как удаление на
  холсте.

Команды редактора, которые меняют и другие страницы (объединение, отделение, удаление со всех страниц, назначение
элемента источнику вставки и пункту панели), выполняют эти функции внутри `doc.transact(…, localOrigin(pageId))`.
Ячейки текущей страницы привязка затем перечитывает в модель (`DiagramBinding.refresh`). Вставка и добавление ячейки
идут через maxGraph (`importCells`, `insertVertex`) внутри той же транзакции: вложенная транзакция привязки
присоединяется к внешней. Получается один путь для всех страниц и одна правка — один шаг отмены. Его можно проверить
без холста.

### Вставка тем же элементом

Буфер обмена вкладки при копировании запоминает документ, страницу и исходные ячейки скопированных клонов. Сами клоны
при копировании больше не получают новых элементов: новые элементы им даёт обычная вставка, потому что `importCells`
клонирует ещё раз. «Вставить как тот же элемент» вставляет клоны, не обновляя `codrawElement`, если буфер из того же
документа, иначе работает как обычная вставка.

- Перед вставкой у каждой фигуры, которая может быть элементом, проставляются нынешние свойства её элемента. Иначе
  `writeCell` вписал бы в общий элемент свойства на момент копирования и откатил бы правки, сделанные после.
- Клон без элемента получает элемент своего источника: `ensureElement` для исходной ячейки, если она ещё есть на
  доске. Если её нет — новый элемент со свойствами клона.
- Вырезанное и вставленное тем же элементом сохраняет `codrawElement`. Элемент, удалённый вместе с последней ячейкой,
  `writeCell` создаёт заново с теми же свойствами.
- Тождество доски определяется по объекту `Y.Doc`. Если уйти с доски и вернуться в той же вкладке, документ создаётся
  заново, и вставка тем же элементом становится обычной. Так безопаснее, чем угадывать по совпадению идентификаторов.

### Панель «Элементы доски» и значки

Список строится из `elementUses` и `readCell` всех страниц. Пункт — элемент (ключ `elementId`) или фигура с типом без
элемента (ключ `pageId/cellId`). Свойства берутся из элемента, у фигуры без элемента — из подписи
(`elementProperties`). Хранилище для `useSyncExternalStore` наблюдает за `pages`, `cells:*` и `elements`, сбрасывает
снимок при изменениях и уведомляет не чаще раза в 150 мс, как эскиз мини-карты. Значки текущей страницы берут из того
же хранилища число других страниц, а положение — из `cellBounds` редактора, как значки статусов. Перетаскивание
передаёт `application/x-codraw-element` с ключом пункта, холст вызывает `placeElement(ключ, точка)`. Для новой ячейки
берётся ячейка элемента на текущей странице, иначе первая по порядку страниц: её собственный стиль, размер и подпись.

### Закрепление и статус — у ячейки

Закрепление защищает ячейку на её странице: положение, вид и правку через неё. Свойства элемента можно менять через
любую незакреплённую ячейку, и подпись закреплённой ячейки следует за ними. Это MODIFIED-требование «Свойства фигуры».
Статус («Черновик», «Нужно ревью», «Готово») описывает состояние рисунка на странице, а не сущности, поэтому он тоже
свой у ячейки. Общий статус элемента можно добавить позже: это ещё одно поле элемента. «Удалить со всех страниц…»
оставляет закреплённые ячейки и называет их в подтверждении. Отделение и объединение не трогают закреплённые
выделенные ячейки: это изменяющие команды меню.

### Версии и предложения

- Сравнение версий видит изменения подписей ячеек на всех страницах: переименование общего элемента — изменение каждой
  его ячейки.
- `restorePage` после синхронизации элементов страницы переподписывает ячейки этих элементов на других страницах
  (MODIFIED «Восстановление страницы»).
- Восстановление части версии идёт через модель и привязку и переподписывает так же.
- `mergeProposal` переподписывает ячейки элементов, чьи свойства изменило слияние, кроме ячеек, записанных самим
  слиянием.

### `.drawio`

Экспорт уже пишет `codrawElement` и свойства в `<object>` каждой ячейки. Импорт (`importPages`) уже даёт одному
`codrawElement` один новый элемент на всю вставку. Проверяем, что это так для ячеек на разных страницах файла
(требование «Общие элементы в файлах draw.io»).

## Risks / Trade-offs

- [Переподпись и починка проходят все ячейки всех страниц на каждую правку элемента] → проход только по ячейкам со
  `codrawElement` из множества изменённых. Доски — сотни ячеек на страницу, проход линейный и без maxGraph.
- [Починку пишут несколько клиентов одновременно] → значения детерминированы и одинаковы, конфликт Yjs выбирает одно
  из равных. Режим «Просмотр» не пишет.
- [Область отмены — весь документ] → отслеживаются только транзакции происхождения страницы. Транзакции страниц,
  восстановления, слияния и починки другого происхождения в историю не попадают.
- [Ячейка ссылается на элемент, удалённый одновременно другим участником] → свойства читаются из подписи, как у
  фигуры без элемента. Первая правка свойств создаёт элемент с тем же идентификатором заново.
- [Вставка тем же элементом после ухода с доски становится обычной] → это видно по результату: новый элемент, без
  значка. Сценарий редкий, ошибиться в обратную сторону хуже.
- [Значок может закрыть другой значок] → снаружи углов уже стоят закрепление (вверху слева), комментарии (вверху
  справа), ссылка (внизу справа) и статус (внизу слева). Значок общего элемента стоит внутри правого верхнего угла
  ячейки.
