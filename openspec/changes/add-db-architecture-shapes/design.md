## Context

Редактор из `add-diagram-editor` хранит ячейки в Yjs, а maxGraph их только рисует. Палитра — плоский список
из пяти пресетов `shapes.ts` (размер, подпись, стиль), фигура добавляется через `editor.addShape`. Связи
создаются с ортогональной разводкой и стрелкой на конце, отдельной настройки связей нет. HTML-подписи
выключены: подпись чужого участника не должна исполнять разметку. Модель уже допускает вложенные ячейки
(`parent`), но интерфейса для них не было. Требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Таблицы, фигуры архитектуры и C4 синхронизируются, отменяются и сохраняются так же, как базовые фигуры,
  без изменений в модели документа и связке Yjs ↔ maxGraph.
- Стили, имена фигур и маркеров совпадают с draw.io.

**Non-Goals:**

- Типы полей, ключи и индексы как отдельные свойства: поле — строка текста.
- Перестановка полей перетаскиванием, сворачивание таблиц.
- Генерация SQL из схемы и импорт схемы из БД.
- Вложение фигур в границу как в контейнер: граница — рамка поверх фигур, а не группа.
- Панель свойств фигур (цвет, шрифт), кроме маркеров связи.
- Библиотеки облачных провайдеров (AWS, GCP, Azure).

## Decisions

### Пресеты и разделы палитры

- `shapes.ts` описывает разделы и пресеты: `id`, название, размер, подпись, стиль. Палитра рисует разделы
  с заголовками, перетаскивание и щелчок работают как сейчас.
- Пресет может описывать дочерние ячейки: так таблица создаётся одним действием вместе с первым полем.
- Иконки фигур в палитре — маленькие SVG в `ShapePalette.tsx`, как у базовых фигур.

### Таблица

- Таблица — `swimlane` (заголовок — имя таблицы, `startSize=30`, `fontStyle=1`) со стилем
  `childLayout=stackLayout`, как список в библиотеке Entity Relation draw.io.
- Поле — дочерняя ячейка таблицы со стилем текста: выравнивание влево, без заливки и рамки,
  `portConstraint=eastwest`, `movable=0`, `resizable=0`.
- Раскладку делает `LayoutManager` maxGraph со `StackLayout` (`horizontal=false`, `fill`,
  `resizeParent`) для ячеек с `childLayout=stackLayout`. Поля встают друг под другом на всю ширину,
  таблица меняет высоту под них. Порядок полей — по координате `y`, новое поле получает `y` сразу под
  выделенным.
- Раскладка выполняется в той же транзакции, что и действие пользователя, поэтому результат попадает
  в Yjs одним шагом undo. У остальных участников та же детерминированная раскладка даёт те же координаты.
- «Добавить поле» — кнопка тулбара, видимая при выделенной таблице или поле; новое поле сразу открывается
  для ввода текста. Удаление — общий обработчик Delete.
- `movable=0` не даёт вытащить поле из таблицы; таблица перемещается за заголовок. Сворачивание отключено.

Альтернатива — одна фигура с многострочным списком полей. Отклонена по выбору пользователя: связь
нельзя провести к конкретному полю. Альтернатива — `shape=table` draw.io с `tableLayout`: в maxGraph такой
раскладки нет, а её реализация заметно сложнее ради возможностей (несколько колонок), которые не нужны.

### Маркеры связей

- Маркеры ER регистрируются в `EdgeMarkerRegistry` maxGraph под именами draw.io: `ERone`, `ERmandOne`,
  `ERmany`, `ERoneToMany`, `ERzeroToOne`, `ERzeroToMany`. Круг «ноль» заливается цветом фона, чтобы
  линия под ним не просвечивала.
- Выбор маркеров — два выпадающих списка в тулбаре, видимые при выделенных связях. Значение пишется
  в ключи стиля `startArrow` и `endArrow` (`classic`, `none` или имя ER-маркера) у всех выделенных связей
  одним действием.
- Начало и конец — разные ключи `Y.Map` стиля, поэтому одновременная смена разных концов не конфликтует.
- Если у выделенных связей разные маркеры, список показывает пустое значение.

### Фигуры архитектуры и C4

| Фигура | Стиль draw.io |
|---|---|
| Сервис | скруглённый прямоугольник |
| База данных, Кэш | `shape=cylinder` |
| Очередь | `shape=cylinder`, `direction=south` |
| Пользователь | `shape=actor`, подпись под фигурой |
| Внешняя система | `shape=cloud` |
| Документ | `shape=document` — своя фигура с волнистым низом |
| Граница | прямоугольник без заливки, пунктир, подпись слева сверху, `pointerEvents=0` |
| C4 Person | `shape=mxgraph.c4.person2` — своя фигура: голова и туловище |
| C4 Software System, Container, Component, External System | скруглённый прямоугольник в цветах C4 |
| C4 Database | `shape=cylinder` в цвете контейнера |
| Граница системы C4 | как «Граница», с подписью «Имя» и «[Software System]» |

- Цвета C4 — стандартные: Person `#08427B`, Software System `#1168BD`, Container и Database `#438DD5`,
  Component `#85BBF0`, External System `#999999`; текст белый, у Component — чёрный.
- Подпись C4 — три строки простого текста: имя, тип в квадратных скобках, описание. В draw.io C4 использует
  HTML-подписи с полями `c4Name`, `c4Type`, `c4Description`; их поддержка — задача импорта `.drawio`.
- Отсутствующие в maxGraph фигуры (`document`, `mxgraph.c4.person2`) регистрируются в `ShapeRegistry`
  при создании редактора.
- `pointerEvents=0` у границ: щелчок внутри рамки проходит к фигурам под ней, граница выделяется по рамке.

## Risks / Trade-offs

- [Два участника одновременно добавляют поле в одну таблицу, и их поля получают одинаковый `y`] → раскладка
  у каждого клиента раскладывает поля заново детерминированно, по `y` и затем по порядку ячеек, поэтому
  картинка у всех одинаковая; координаты в Yjs выравниваются при следующем изменении таблицы.
- [Раскладка срабатывает и на изменения от других участников] → эти изменения уже разложены отправителем,
  и повторная раскладка даёт те же координаты; связка не пишет изменения во время применения чужих правок.
- [Подписи C4 — простой текст, а не HTML с полями, как в draw.io] → при импорте и экспорте `.drawio`
  понадобится преобразование.
- [`direction=south` у очереди поворачивает подпись вместе с фигурой] → проверить на холсте; если подпись
  повернётся, задать `horizontal=1` для подписи или рисовать очередь своей фигурой.
