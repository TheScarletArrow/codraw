## Why

Сейчас в CoDraw входят только через GitHub и Google (или гостем). Компании, которые ставят CoDraw у себя, входят в
свои системы через собственный провайдер удостоверений — Keycloak, Microsoft Entra ID, Okta — и не могут требовать от
сотрудников личных учётных записей GitHub или Google, а гостевой вход в закрытой установке и вовсе лишний (issue
#158).

## What Changes

- Один или несколько провайдеров OpenID Connect задаются настройками `backend` (`codraw.auth.oidc.<id>.*`, в
  окружении — `CODRAW_AUTH_OIDC_<ID>_*`): issuer (его метаданные `/.well-known/openid-configuration`), client id и
  secret, scope и название для кнопки «Войти через …». Провайдер без issuer или client id не включается, и кнопки нет.
- Имя и аватар берутся из claims (`name`, `preferred_username`, `picture`). Учётная запись связывается по паре `iss` +
  `sub`: повторный вход находит ту же учётную запись, даже если у пользователя сменились почта или имя, а пользователи
  разных провайдеров с одинаковым `sub` — разные учётные записи. Почта не хранится.
- Необязательные ограничения провайдера: домены почты (`allowed-email-domains`) и группы из claim
  (`allowed-groups`, `groups-claim`). Не прошедший их возвращается на страницу входа с сообщением, что вход в эту
  установку ему не разрешён, и учётная запись не создаётся.
- Закрытая установка: вход через GitHub или Google есть, только если задано его OAuth-приложение, а гостевой вход
  выключается настройкой `codraw.guests.enabled=false` (`CODRAW_GUESTS_ENABLED`). Можно оставить только
  корпоративный вход.
- Страница входа показывает те способы входа, которые включены в установке: `GET /api/auth/providers` (открыт без
  входа) отдаёт список провайдеров с названиями и признак гостевого входа.
- Необязательный выход у провайдера (RP-initiated logout, `logout=true`): после «Выйти» браузер уходит на
  `end_session_endpoint` провайдера и возвращается на страницу входа CoDraw.
- Политика конфиденциальности называет провайдеров входа, включённых в установке, в том числе выбранный оператором
  корпоративный, и что CoDraw получает от них и хранит; `/api/legal` отдаёт их названия.
- `docs/deploy.md`: настройка корпоративного входа с примером для Keycloak, закрытая установка; README — раздел о
  входе, «Что нового», «План работ»; ADR-0010 о выборе OIDC.

## Capabilities

### New Capabilities

- `oidc-sign-in`: вход через корпоративные провайдеры OpenID Connect — настройка провайдеров, связь учётной записи по
  `iss` + `sub`, ограничения по доменам почты и группам, выход у провайдера.

### Modified Capabilities

- `user-auth`: способы входа на странице входа зависят от настроек установки, гостевой вход можно выключить, сообщение
  о пределе гостей и строка согласия не называют конкретных провайдеров.
- `legal-pages`: политика конфиденциальности называет включённых провайдеров входа, в том числе корпоративного.

## Impact

- `backend`: настройки `codraw.auth.oidc`, свой `ClientRegistrationRepository` (GitHub и Google из настроек Spring
  Boot, провайдеры OIDC с ленивым чтением метаданных), сервис пользователя OIDC с проверками допуска, фильтр, который
  при недоступном провайдере возвращает на страницу входа, `GET /api/auth/providers`, `codraw.guests.enabled`, выход
  у провайдера, `/api/legal`, интеграционный тест с Keycloak в Testcontainers. Миграции нет: пара `iss` + `sub`
  хранится в существующих `users.provider` и `users.provider_user_id`.
- `frontend`: страница входа по списку провайдеров, сообщение об отказе в допуске, выход с переходом к провайдеру,
  политика конфиденциальности, «Что нового», тесты.
- e2e: страница входа со способами входа установки и возврат с ошибкой при недоступном провайдере.
- `docker-compose.prod.yml`, `docs/deploy.md`, `docs/running.md`, README, ADR-0010.
