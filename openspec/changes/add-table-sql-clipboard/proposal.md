# Proposal

## Why

Скопированная таблица попадает в системный буфер закодированным XML draw.io: вставленная в редактор кода, мессенджер или
консоль базы, она — нечитаемая строка `%3CmxGraphModel…`. Таблицы копируют, чтобы отдать схему коллеге или выполнить её,
поэтому снаружи нужен SQL, а внутри CoDraw — по-прежнему таблица со стилем, связями и положением.

## What Changes

- Копирование и вырезание таблиц (без других фигур) кладут в текст системного буфера `CREATE TABLE` PostgreSQL этих
  таблиц со внешними ключами между ними, как «Скопировать SQL», а саму схему CoDraw — в HTML-формат буфера:
  `<pre>` с тем же SQL и схемой в атрибуте `data-codraw`. Другие приложения вставляют SQL, CoDraw — таблицы.
- Копирование фигур без таблиц и смеси таблиц с другими фигурами — как раньше, в формате draw.io.
- Вставка читает схему CoDraw из HTML-формата буфера; «Вставить» из контекстного меню читает HTML через Clipboard API,
  где браузер это позволяет.
- Вставка текста DDL, в котором импорт SQL находит таблицы, добавляет эти таблицы, как «Импорт SQL»: так SQL из другого
  приложения и таблица, скопированная без HTML-формата, становятся таблицами.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `editing-commands`: системный буфер при копировании таблиц, чтение HTML-формата при вставке, вставка SQL.

## Impact

- `frontend`: `diagram/clipboardFormat.ts` (SQL и HTML для таблиц, чтение `data-codraw`, SQL как схема),
  `diagram/clipboard.ts` (запись и чтение текста и HTML через Clipboard API), `diagram/editor.ts` (копирование,
  вырезание и вставка с HTML-форматом).
- `backend`, `collab` не меняются; новых зависимостей нет.
