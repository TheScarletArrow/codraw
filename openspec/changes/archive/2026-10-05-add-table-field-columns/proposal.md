# Proposal

## Why

Таблица БД на доске — строки текста вида `owner_id uuid FK NOT NULL`: по полю не видно, что оно внешний ключ и на
какое поле ссылается (это видно только по линии, которую в большой схеме трудно проследить), тип и `NOT NULL`
приходится печатать руками и помнить их написание, а nullable-поле ничем не отличается от поля, у которого
нулабельность просто забыли указать. Непонятно и то, для какой СУБД нарисована схема: типы PostgreSQL, MySQL и Oracle
выглядят одинаково.

## What Changes

- Поле таблицы рисуется колонками, выровненными по всей таблице: значок ключа (PK) или звена (FK) и ромб у
  уникального поля, имя, тип,
  `NULL` / `NOT NULL` и у внешнего ключа — цель ссылки `→ users.id`, взятая из связей поля. Текст поля остаётся
  тем же (`owner_id uuid FK NOT NULL`), поэтому старые доски, шаблоны, импорт и выгрузки работают без изменений.
- У таблицы есть СУБД: PostgreSQL, MySQL / MariaDB, Oracle, SQL Server, SQLite, ClickHouse. Она показана цветным
  значком в шапке таблицы и выбирается на панели инструментов, когда выделена таблица. Таблица из панели фигур и из
  импорта SQL — PostgreSQL; у таблиц без СУБД (старые доски, Mermaid, draw.io) значка нет.
- Когда выделено поле, на панели инструментов: «Тип» — список типов СУБД таблицы с возможностью ввести свой
  (`numeric(12,4)`), переключатель `NULL` / `NOT NULL`, «PK» и «UNIQUE». Изменения пишутся в текст поля.
- Двойной щелчок по полю редактирует только имя; введённая целиком строка (`email text NOT NULL`) по-прежнему
  разбирается как поле целиком.
- Автоширина таблицы и ширина таблиц из импорта считаются по колонкам.
- Выгрузка SQL остаётся в диалекте PostgreSQL; выбор цели внешнего ключа в панели — вне этого изменения (FK
  по-прежнему задаётся связью между полями).

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `diagram-shapes`: таблица получает СУБД со значком; поле рисуется колонками со значками ключей, типом,
  нулабельностью и целью внешнего ключа; тип, нулабельность и ключи задаются на панели инструментов; двойной щелчок
  по полю редактирует имя.
- `sql-schema`: импортированные таблицы получают СУБД PostgreSQL.
- `shape-geometry`: автоширина таблицы считается по колонкам полей.

## Impact

- `frontend`: `diagram/` (отрисовка поля и шапки таблицы, редактирование имени поля, автоширина, панель полей и
  таблицы в `EditorToolbar`), новый модуль типов СУБД в `sql/`, `sql/erDiagram.ts` (СУБД и ширина при импорте),
  палитра (`diagram/shapes.ts`).
- Данные доски: в стиле таблицы появляется ключ `dbVendor`; текст полей и связи не меняются, миграция не нужна.
- `backend`, `collab` не меняются.
