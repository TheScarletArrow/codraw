# Design

## Context

Гость — пользователь с `provider = 'guest'`. Его сеанс хранит Spring Session JDBC в `spring_session`: срок —
30 дней с последнего обращения, `principal_name` — id пользователя (имя принципала `DefaultOAuth2User` — атрибут
`userId`). Истёкшие сеансы Spring Session удаляет сам раз в минуту. Других способов войти гостем нет: при входе через
провайдера доски гостя переходят пользователю, а гостевая запись остаётся пустой. `boards.owner_id` ссылается на
`users` без каскада; документ, версии и посещения доски удаляются каскадом вместе с ней, посещения пользователя —
вместе с ним.

## Goals / Non-Goals

**Goals:**

- Не держать в базе гостей, которые не вернутся, и их доски, с которыми никто не работает.
- Не удалять доску, которую ещё открывают участники по ссылке, даже если её владелец-гость ушёл.

**Non-Goals:**

- Удаление неактивных пользователей GitHub и Google и их досок.
- Предупреждение гостя о скором удалении: вернуться он не может, предупреждать некого.

## Decisions

### Кто считается ушедшим

- Гость ушёл, если в `spring_session` нет строки с его id в `principal_name` и `expiry_time` позже текущего
  момента. Так учитывается и сеанс, который истёк, но ещё не убран Spring Session. Индекс по `principal_name` уже
  есть (`spring_session_ix3`).
- Гость, созданный меньше суток назад, не трогается: сеанс сохраняется в конце запроса, и задача, запущенная в этот
  момент, увидела бы гостя без сеанса.
- Альтернатива — своя отметка «последний вход» у пользователя. Отклонено: сеанс уже знает, может ли гость вернуться,
  а отметку пришлось бы обновлять на каждом запросе.

### Какие доски удаляются

- Доска ушедшего гостя удаляется, если последняя работа с ней была раньше, чем `codraw.guests.board-retention`
  (30 дней) назад. Последняя работа — позднейшее из `boards.updated_at` (меняется при изменении документа и
  названия) и `board_visits.visited_at` других пользователей.
- Затем удаляются ушедшие гости, у которых не осталось досок. Гость с живыми досками остаётся их владельцем: у доски
  всегда есть владелец (`owner_id NOT NULL`), а участники по ссылке продолжают с ней работать.
- Удаление идёт пачками по 500 строк, каждая — в своей транзакции, чтобы не держать долгих блокировок на большой
  базе.

### Запуск

- `@Scheduled(cron = "${codraw.guests.cleanup-cron}")`, по умолчанию раз в час в 23-ю минуту, `@EnableScheduling`
  в отдельной конфигурации. Задачу можно выключить значением `-`, как принято для cron в Spring.
- Несколько экземпляров `backend` могут запустить задачу одновременно: удаления идемпотентны, лишняя работа не вредит.
  Блокировка через ShedLock или `pg_advisory_lock` — когда экземпляров станет много.
- Задача пишет в журнал число удалённых досок и гостей, если что-то удалила.

## Risks / Trade-offs

- [Доска гостя, открытая по ссылке, но без изменений и посещений 30 дней, удаляется] → это и есть брошенная доска;
  участник, которому она нужна, сохранит копию экспортом в `.drawio`, пока её открывает.
- [Сеанс гостя удалили вручную, например очисткой `spring_session`] → гость считается ушедшим, как и при истечении
  сеанса: вернуться он и правда не может.
- [Большая база при первом запуске] → пачки по 500 строк и отдельные транзакции.

## Migration Plan

Схема не меняется. После выкатки первая задача удалит накопившихся ушедших гостей и их брошенные доски. Откат —
предыдущая версия `backend`; удалённое не восстанавливается, как и при удалении доски владельцем.
