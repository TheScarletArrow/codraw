# Design

## Context

Документ доски — состояние Yjs, которое `collab` хранит через `backend` целиком (до 16 МБ), а версии — копиями (до
64 МБ на доску); каждый участник при открытии получает документ полностью. maxGraph уже рисует `shape=image` draw.io
(`ImageShape`, элемент `<image>` в SVG холста), а `.drawio` с картинками сейчас кладёт их в документ строками
`data:image/…;base64,…`. CSP приложения: `img-src 'self' data: blob:` и аватары, `connect-src 'self'`. Права на доску —
роли `owner`/`editor`/`viewer` (`BoardService.participated`), черновик предложения правит его автор при любой роли на
доске (`ProposalService.draftAccess`). Экспорт PNG рисует SVG в `<canvas>` через `<img>`, а SVG-как-картинка не грузит
внешних ресурсов. Живая картинка (`board-embed`) — SVG из браузера, очищенный по белому списку, где у `<image>`
допустимы только `data:image/(png|jpeg|gif|webp);base64`. Стек меняется только новым ADR (ADR-0001 называет
«S3-совместимое хранилище (MinIO локально)»). Требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Картинка на доске одной вставкой, перетаскиванием или из панели; на доске — ссылка, байты — в хранилище.
- Права на картинку — права на доску; хранилище защищено пределами от переполнения.
- `.drawio`, PNG, SVG и PDF самодостаточны; перенос картинок между досками и из draw.io не теряет их.

**Non-Goals:**

- Обрезка, фильтры, замена картинки у существующей фигуры, картинка как заливка фигуры.
- SVG-файлы как картинки доски и скачивание картинок по чужим адресам.
- Удаление картинок, на которые доска больше не ссылается, до удаления доски.
- Картинки в комментариях и аватарах.

## Decisions

### Хранение: S3-совместимое хранилище и описание в PostgreSQL

- Байты — объекты `boards/{boardId}/{imageId}` в бакете `codraw-images`; описание — таблица `board_images`: `id`
  (`uuidv7()`), `board_id`, `sha256`, `content_type`, `size`, `width`, `height`, `created_at`, уникальность
  `(board_id, sha256)`. Кто загрузил, не хранится: незачем, а политике меньше данных.
- `board_id` без внешнего ключа: строки картинок удалённой доски должны дожить до удаления их объектов из хранилища,
  которое не умеет участвовать в транзакции. Уборка `ImageCleanup` раз в час (`codraw.images.cleanup-cron`) находит
  картинки досок, которых нет (`NOT EXISTS` по первичному ключу `boards`), пачками по 500 удаляет объекты
  (`DeleteObjects`), затем строки. Удаление доски владельцем сразу вызывает то же для неё; ошибка хранилища не мешает
  удалению доски — картинки уберёт следующая уборка. Удаление досок уборкой гостей (`GuestCleanup`, SQL пачками)
  не меняется: его картинки уходят при ближайшей уборке картинок.
- Загрузка: доска блокируется (`SELECT … FOR UPDATE`), тот же файл на доске (`sha256`) возвращается без новой строки
  (200), иначе проверяется место и вставляется строка; после коммита объект кладётся в хранилище, а при ошибке строка
  удаляется (503). Транзакция не держит соединение с базой, пока байты идут в хранилище. Если процесс упал между
  строкой и объектом, картинка отвечает 404 и занимает место до удаления доски — это лучше, чем объекты без строк,
  которые не удалил бы никто.
- Картинки не удаляются, пока жива доска: на них ссылаются версии, черновики и базы предложений, история отмены
  участников и офлайн-копии, а `backend` не читает документы Yjs, чтобы узнать, на что ссылки остались. Место доски
  считается по всем её картинкам; одинаковые файлы хранятся один раз.
- Альтернативы: `bytea` в PostgreSQL (база и её копии растут на гигабайты картинок, JDBC читает значение целиком в
  память; ADR-0001 и задача называют S3), каталог на диске `backend` (не делится между экземплярами, нет готовых
  резервных копий и переноса), строки `data:` в документе (как сейчас у `.drawio`: документ и версии растут, каждый
  участник скачивает всё при каждом открытии). Решение — в ADR-0006.

### Сервер хранилища — RustFS

- MinIO перестал публиковать образы сообщества (`minio/minio`, `quay.io/minio/minio`), а его репозиторий — в режиме
  поддержки. Сравнение доступных образов — в ADR-0006: RustFS (Apache-2.0, выпуск 1.0.1, один процесс, настраивается
  переменными окружения, порт 9000 и `/health`, стартует без команды — подходит для `services:` GitHub Actions),
  SeaweedFS (Apache-2.0, зрелый, но S3 — шлюз поверх четырёх процессов, ключи — JSON-конфигом, нужна команда),
  Garage (AGPL-3.0, нужны TOML-конфиг и ручная разметка кластера и ключей CLI), `pgsty/minio` (AGPL-3.0, сборка MinIO
  третьей стороной), `adobe/s3mock` (только для тестов).
- Образ закреплён тегом `rustfs/rustfs:1.0.1`. `backend` говорит на обычном S3, поэтому заменить сервер (SeaweedFS,
  сборка MinIO, облачный S3) можно настройками без кода.

### Клиент S3 — AWS SDK for Java v2

- `software.amazon.awssdk:s3` 2.55.12 с `url-connection-client` вместо Netty и Apache HTTP client (исключены): синхронные
  вызовы на виртуальных потоках, как остальной `backend`, без лишних зависимостей. Path-style, адрес (`endpoint`;
  пустой — AWS), регион, бакет и ключи — `codraw.images.s3.*`; контрольные суммы запросов и ответов — только где их
  требует S3 (`WHEN_REQUIRED`), потому что S3-совместимые серверы понимают новые CRC по-разному.
- Бакет создаётся при старте, если его нет; если хранилище недоступно, `backend` всё равно стартует (доски работают
  без картинок), пишет предупреждение и пробует снова при первой загрузке. Хранилище не входит в готовность `backend`.
- Альтернативы: MinIO Java SDK (тянет OkHttp, Guava и Jackson своих версий), своя подпись SigV4 на `java.net.http`
  (меньше кода в зависимостях, но своя криптография и разбор XML ответов ради экономии мегабайтов).

### API и права

- `POST /api/boards/{id}/images` — тело запроса — сам файл (не multipart: нет пределов multipart Spring и разбора
  форм). Право — роль с правкой доски; с `?proposal={id}` — ещё и автор открытого предложения этой доски: он правит
  черновик и при роли «Просмотр», а картинки черновика после принятия станут картинками доски. Ответ — `{ id, url,
  width, height, contentType, size }`, 201, или 200 для файла, который уже есть на доске.
- `GET /api/boards/{id}/images/{imageId}` — любая роль на доске (картинку доски видит тот, кто видит доску), как
  `<img>` с cookie сеанса; 403 без роли, 404 для чужой или несуществующей картинки. Заголовки: `Content-Type` из
  сигнатуры, `Content-Length`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none';
  sandbox`, `Cache-Control: private, max-age=31536000, immutable` и `ETag` — картинка по своему адресу никогда не
  меняется, а кеш браузера показывает её и без связи. Общие кеши её не хранят (`private`); снятый доступ не отзывает
  уже скачанное — как и скачанный PNG.
- `GET /api/boards/{id}/images/usage` — `{ used, quota, imageSize }` для любой роли: браузер проверяет файл до загрузки.
- Ошибки — problem details, как у остальных пределов: 413 с `limit` (байты) или с `limit` и `scope: "pixels"`, 415
  для неизвестного формата и SVG, 409 «Image quota reached» с `limit`, 503, если хранилище недоступно.

### Проверка файла

- Формат — по сигнатуре: PNG (`\x89PNG` и `IHDR`), JPEG (`FFD8FF`, размеры — из маркера `SOFn`), GIF (`GIF87a`/`GIF89a`),
  WebP (`RIFF…WEBP` с `VP8 `, `VP8L` или `VP8X`). Заголовок `Content-Type` запроса не учитывается: тип ответа — из
  сигнатуры, поэтому HTML или скрипт под видом картинки не будет отдан как исполняемый документ.
- Размеры из заголовка файла ограничены 50 Мп (`ImageFormats.MAX_PIXELS`): маленький файл с огромными размерами
  («бомба») распаковался бы в каждом браузере в сотни мегабайт.
- SVG не принимается: он может нести скрипты и внешние ссылки, а открытый по своему адресу с того же домена —
  выполнить их. Очистка (`SvgSanitizer` живой картинки) выбросила бы заметную часть настоящих SVG (стили, шрифты,
  ссылки), а `sandbox` защищает только при открытии адреса, но не при сохранении и повторной загрузке файла. SVG-иконки
  из файлов draw.io (`data:image/svg+xml`) остаются строками в документе, как сейчас: в `<image>` SVG не выполняет
  скрипты и не грузит внешнее.

### Пределы

- `codraw.limits.image-size` (10 МБ) — больше файл не принимается: скриншоты и макеты меньше, а nginx пропускает
  тела до 32 МБ. `codraw.limits.images-size-per-board` (100 МБ) — сколько занимают картинки доски вместе; при пределе
  числа досок 100 это ограничивает и пользователя. Оба — через существующий механизм `LimitProperties`, с метриками
  `codraw_limits_reached_total{limit="image"|"images"}`; новые картинки — `codraw_images_stored_bytes`, удалённые
  уборкой — `codraw_images_cleanup_deleted_total`.

### Фигура-изображение

- Стиль — как вставка картинки в draw.io: `shape=image;image=<ссылка>;aspect=fixed;imageAspect=0;
  verticalLabelPosition=bottom;verticalAlign=top`. Ссылка — путь `/api/boards/{boardId}/images/{imageId}` от корня
  сайта: работает за любым доменом и под CSP `img-src 'self'`. `imageAspect=0` растягивает картинку на фигуру, а
  `aspect=fixed` держит пропорции фигуры при изменении размера ручками; Shift, который у остальных фигур включает
  пропорции, у изображения их отпускает. «Размер» с одной изменённой стороной у фигуры с `aspect=fixed` меняет и вторую.
- Новая фигура — в натуральную величину в пикселях из ответа сервера, вписанная в 600 × 600; середина — в точке, куда
  отпустили файлы, или в середине видимой части холста; несколько — в ряд с промежутком 20. Все — одним изменением
  модели, то есть одним шагом отмены, после того как все файлы загружены; не загрузившиеся пропускаются.
- Подпись под картинкой, как в draw.io; автоширины и переноса слов нет (подпись снаружи фигуры), быстрого соединения
  нет (фигура не из палитры). В списке изменений версий и предложений элемент называется «Изображение», а смена
  картинки — «изображение».
- Загрузка в редакторе: опция `images` (`ImageHost`: `store(blob)` и `holds(url)`) и команда `addImages(files, at)`.
  Хост — у страницы доски и черновика (`useImageUploads` в `board/imageUploads.ts`): он проверяет тип и размер до
  загрузки, грузит через `XMLHttpRequest` ради прогресса и сам показывает прогресс и ошибки строкой под шапкой — как
  «Нет связи» и предел размера доски. Без хоста (версия, сравнение, режим «Просмотр») команд нет.

### Откуда картинки

- `Ctrl+V`: файл картинки из `clipboardData` берётся, если текста нет или HTML — только `<img>` («Копировать
  изображение» браузера); иначе вставляется текст, как сейчас (Word и Excel кладут и текст, и картинку-снимок). «Вставить»
  меню берёт картинку из `navigator.clipboard.read()` в точку щелчка.
- Перетаскивание файлов: холст принимает `Files`, отпускание всегда отменяет действие браузера (иначе он открыл бы
  файл вместо доски), а не картинки получают сообщение об ошибке.
- «Изображение» в панели фигур — под поиском, открывает выбор файлов (`accept` четырёх форматов, несколько файлов).

### Перенос картинок

- Ячейки, которые приходят на доску из вставки, `.drawio` (кнопка импорта, новая доска из файла) и фрагментов
  draw.io, проходят `storeImages`: растровые `data:image/…` загружаются на доску, ссылки на картинки другой доски того
  же сайта скачиваются браузером (у вставившего есть доступ к доске, с которой он копировал) и загружаются заново;
  одинаковые адреса — один раз, не больше четырёх загрузок сразу. Не загрузившаяся картинка остаётся как была: строка
  `data:` по-прежнему видна, а ссылка без доступа — заглушкой.
- Внешние `http(s)://` остаются ссылками: CSP не пускает картинки с чужих адресов, браузер не может их скачать
  (`connect-src 'self'`), а скачивание сервером открыло бы SSRF. Так `.drawio` при обмене с draw.io не теряет их.
- Буфер обмена при копировании несёт ссылку, а не байты: событие копирования синхронное. Вставка в другую доску CoDraw
  переносит картинку, draw.io её не покажет — для него есть экспорт `.drawio`.

### Экспорт

- `.drawio` (кнопка, «Скачать копию» без связи, схема внутри SVG): перед записью браузер скачивает картинки доски и
  пишет их строками `data:image/png,<base64>` — `;` в стиле draw.io разделяет ключи, поэтому draw.io пишет без
  `;base64`, а импорт читает обратно. Не скачавшаяся картинка остаётся ссылкой.
- PNG, SVG, PDF, «Копировать PNG»: `inlineImages` заменяет `href` у `<image>` с адресом сайта на `data:` (кеш браузера
  отдаёт их без сети), не скачавшуюся — на заглушку. PNG рисуется из SVG без внешних ресурсов, поэтому холст не
  «загрязнён», а файл не зависит от доступа. Для PDF GIF и WebP перекодируются в PNG через `<canvas>`: их разбор в jsPDF
  не нужен.
- Живая картинка: картинки вкладываются уменьшенными до вдвое большего размера фигуры (PNG, у JPEG — JPEG), чтобы
  уложиться в 2 МБ; если `backend` всё же ответил 413, публикуется SVG без картинок (очистка выбросит ссылки).

### Заглушка и без связи

- `ImageShape` заменена своей (`image` в реестре фигур): если `<image>` на холсте не загрузилась, она показывает
  серую рамку с значком картинки, запоминая адрес; событие `online` возвращает адреса, и браузер пробует снова. Офлайн-копия
  доски хранит ссылки, а картинки — кеш браузера (`max-age` на год); картинка, которую браузер ещё не видел, без связи —
  заглушка.

## Risks / Trade-offs

- [Картинки удалённых с доски фигур занимают место до удаления доски] → одинаковые файлы хранятся один раз, предел места
  доски, сообщение о пределе; удаление ненужных — отдельное изменение (нужен разбор документов Yjs на сервере).
- [RustFS моложе MinIO и SeaweedFS] → обычный S3 без расширений, образ закреплён тегом, сервер меняется настройкой;
  тесты `backend` и e2e идут на том же образе.
- [Хранилище — новый сервис со своим томом] → проверка готовности, `depends_on`, разделы резервного копирования
  и переменных в `docs/deploy.md`.
- [Байты идут через `backend`, а не напрямую из хранилища] → права проверяются на каждый запрос, один адрес и CSP
  без изменений; ответы потоковые, а браузер кеширует их на год.
- [Гонка удаления доски и загрузки] → строка без доски уберётся уборкой; объект, положенный после уборки, останется —
  окно — доли секунды раз в час.
- [Буфер обмена не несёт байтов] → вставка в CoDraw переносит картинку, в draw.io — экспорт `.drawio`.
- [jsdom не грузит картинки и не рисует] → unit-тесты проверяют стиль, размеры, загрузку с подменённым хостом и замену
  ссылок; загрузку, отображение, экспорт и права — e2e в Chromium с RustFS.
