# Design

## Context

Создать гостя может любой (`POST /api/guest` без входа), гость работает как обычный пользователь. Число досок
(`POST /api/boards`), размер документа (`collab` принимает любые правки, `PUT /internal/boards/{id}/document`
читает тело целиком) и размер версий (100 штук до 16 МБ каждая) ничем не ограничены. WebSocket-сервер `collab`
(`ws` внутри Hocuspocus 4) по умолчанию принимает сообщения до 100 МиБ. Перед `backend` стоит nginx с
`client_max_body_size 16m`; адрес клиента `backend` получает из `X-Forwarded-For` доверенных прокси
(`RemoteIpValve`).

## Goals / Non-Goals

**Goals:**

- Ограничить то, что растёт без предела и стоит дисков и памяти: гостей, доски, документы, версии.
- Пределы с запасом для обычной работы и с понятным сообщением, когда предел достигнут.

**Non-Goals:**

- Квоты по тарифам, суммарный объём данных пользователя, ограничение частоты всех запросов API.
- Пределы, общие для нескольких экземпляров `backend` (счётчик гостей живёт в памяти экземпляра).
- Ограничение числа соединений и участников одной доски.

## Decisions

### Настройки

`codraw.limits` в `backend`: `boards-per-user` (100), `guests-per-address-per-hour` (20), `document-size` (32MB),
`versions-size-per-board` (64MB). В `collab` — `DOCUMENT_SIZE_LIMIT_BYTES` (16 МиБ). Предел `backend` для документа
вдвое выше предела `collab` и служит страховкой: документ, который `collab` принял, всегда сохранится, даже если его
состояние после слияния правок вышло чуть больше суммы.

### Число досок

- `BoardService.create` в одной транзакции блокирует строку владельца (`SELECT … FOR UPDATE`) и считает его доски:
  два одновременных запроса не превысят предел. Сверх предела — исключение, которое контроллер переводит в 409 с
  `ProblemDetail`: `title` «Board limit reached», свойство `limit`.
- 409, а не 403 или 429: запрос верен и разрешён, ему мешает текущее состояние — число досок; после удаления доски
  тот же запрос пройдёт.
- Перенос досок гостя при входе предел не проверяет: вход не должен отказывать, а досок у пользователя станет больше
  предела только однажды — новые он создаст, удалив лишние.

### Новые гости с одного адреса

- В памяти `backend` — окно в час на адрес (`request.remoteAddr` после `RemoteIpValve`): счётчик и начало окна.
  Считаются только созданные гости: повторное «Продолжить без входа» с живым сеансом гостя не создаёт. Сверх
  предела — 429 с `Retry-After` в секундах до конца окна. Истёкшие окна удаляются при обращениях.
- Альтернатива — счётчик в базе по адресу. Отклонено: хранить адреса пользователей ради этого не нужно, а один
  экземпляр `backend` в MVP. Предел 20 в час оставляет запас для офиса за одним NAT.

### Размер документа и версий в `backend`

- `PUT /internal/boards/{id}/document` читает тело потоком не больше предела плюс байт: больше предела — 413, без
  чтения остального. `POST …/versions` — то же с прежним ответом 400 для неверного тела.
- `BoardVersions.prune` удаляет версии, которые не входят в 100 последних или за которыми, считая от новой, сумма
  размеров (`octet_length(state)`, без распаковки) превышает `versions-size-per-board`; новейшая версия остаётся
  всегда. Так обычная доска хранит все 100 версий, а доска в десятки мегабайт — несколько последних.
- nginx пропускает тела до 32 МБ, как `backend`.

### Размер документа в `collab`

- `collab` знает размер документа без кодирования на каждую правку: при загрузке — размер сохранённого состояния,
  при каждом сохранении — размер того, что сохранил, а между сохранениями прибавляет размер каждой принятой правки.
  Это оценка сверху: удаления и слияние её только уменьшают, и следующее сохранение приводит её к точному числу.
- Хук `beforeSync` получает тип sync-сообщения и его содержимое до применения. Для `step2` и `update` по
  соединению с правом правки: если оценка с этой правкой больше предела, а правка что-то добавляет, — ошибка с
  кодом 4413 и причиной `document-too-large`. Hocuspocus закрывает соединение с документом и правку не применяет.
- Удаление проходит всегда: правка без новых элементов (`Y.decodeUpdate(…).structs` пуст) только освобождает место.
  Разбираются только правки меньше 64 КиБ — большая правка удалением не бывает.
- `websocketOptions.maxPayload` — предел плюс 64 КиБ: сообщение, которое заведомо не поместится, `ws` отклоняет
  кодом 1009, не собирая его в памяти.

### Отказ на странице доски

- Закрытие с причиной `document-too-large` или кодом 1009 значит, что в локальном документе есть правка, которую
  сервер не примет: провайдер повторял бы её при каждом переподключении. Страница отбрасывает локальный документ и
  подключается заново с чистым, то есть возвращается к состоянию сервера, и показывает предупреждение: «Доска
  достигла предельного размера, последнее изменение не сохранено. Удалите лишнее, чтобы продолжить».
- `HttpError` получает разобранное тело ответа (`ProblemDetail`), чтобы показать предел числа досок; на главной —
  «Можно держать не больше 100 досок. Удалите ненужные, чтобы создать новую», на странице входа при 429 —
  «Слишком много новых гостей с вашего адреса. Попробуйте позже или войдите через GitHub или Google».

## Risks / Trade-offs

- [Несколько экземпляров `backend`] → у каждого свой счётчик гостей, предел умножается на их число; вынести
  счётчик в общее хранилище, когда экземпляров станет больше одного.
- [Пользователи за одним NAT] → 20 новых гостей в час на адрес; уже созданные гости работают дальше, а войти
  через провайдера можно всегда.
- [Доска у предела] → можно только удалять; правки, которые добавляют, отклоняются с понятным сообщением.
- [Оценка размера сверху] → у самого предела правка может быть отклонена, хотя после слияния поместилась бы;
  после сохранения (не позже 10 секунд) оценка снова точна.

## Migration Plan

Схема не меняется. Доски сверх предела у существующих пользователей остаются, новые не создаются, пока досок не
станет меньше. Версии сверх 64 МБ на доску удаляются при её следующей версии. Откат — предыдущие версии сервисов.
