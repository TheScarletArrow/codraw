# Design

## Context

Пользователь — строка `users`; на неё ссылаются внешние ключи двух десятков таблиц. Почти все уже объявлены с
`ON DELETE CASCADE` (участие, запросы, визиты, отметки прочтения, теги и папки, библиотеки, шаблоны, уведомления
получателя, каналы уведомлений, подключение GitHub, реакции, упоминания, предложения автора, участие в пространствах) или
`ON DELETE SET NULL` (автор комментария и решения, кто закрыл ветку, ответственный за ветку, кто решил предложение, кто
привязал задачу, автор уведомления). Так их удаляет уборка ушедших гостей (`GuestCleanup`): сначала доски гостя, потом
строку пользователя. Без каскада только `boards.owner_id`: доску нельзя потерять молча. Ещё два места хранят
идентификаторы пользователей без внешнего ключа: массивы `board_documents.editors` и `board_versions.authors`; авторов,
которых нет в `users`, версии сейчас пропускают. Сеансы Spring Session хранятся в `spring_session` с
`principal_name` = идентификатор пользователя.

Документы досок — двоичные состояния Yjs, `backend` их не разбирает. Выгрузка в `.drawio` уже есть во `frontend`
(`exportDrawio` с изображениями внутри через `embeddedImages`), как и сборка ZIP (`lib/zip.ts`).

`collab` проверяет доступ при подключении и раз в минуту по `GET /internal/boards/{id}/access`; правило доступа не
проверяет, существует ли пользователь, поэтому по ссылке с правкой удалённый пользователь остался бы на доске до
переподключения. Токен синхронизации живёт 5 минут.

## Goals / Non-Goals

**Goals:**

- Пользователь сам удаляет учётную запись, и после этого ни одна таблица не ссылается на него.
- Доски с другими участниками не пропадают без явного решения владельца.
- Вклад в общие доски не исчезает, а обезличивается.
- Удаление — сервис `backend`, который вызывает и пользователь, и администратор установки (#162).
- Пользователь скачивает все свои данные в открытых форматах; частота выгрузки ограничена.

**Non-Goals:**

- Отложенное удаление с периодом отмены («удалим через 30 дней»): удаление необратимо сразу, как и окончательное
  удаление доски из корзины.
- Переписывание документов Yjs чужих досок (имена в отметках «Изменено» и закреплениях) и текста чужих комментариев
  (`@Имя`): это содержимое досок других людей, `backend` документы не разбирает.
- Отзыв токена GitHub у GitHub.
- Интерфейс администратора — отдельный issue #162.

## Decisions

### Что удаляется, а что обезличивается

| Данные | Что происходит | Как |
|---|---|---|
| Профиль, сеансы | удаляются | `DELETE FROM users`, `DELETE FROM spring_session WHERE principal_name = :id` |
| Личные доски без других участников, корзина, их изображения в S3 | удаляются | `BoardService.delete` → `BoardDeleted` → `BoardImageService` |
| Личные доски с участниками или посетителями | по решению: передать участнику или удалить | `BoardService.transferOwnership` / `delete` |
| Доски пространств, за которые отвечал | переходят первому другому владельцу пространства | `WorkspaceService.removeMember` (уход) |
| Пространство, где он единственный участник | удаляется, доски — в его корзину и удаляются вместе с ней | `WorkspaceService.delete` |
| Участие в досках и пространствах, запросы доступа, визиты, отметки прочтения, теги, папки, библиотеки, шаблоны, уведомления пользователя, каналы уведомлений и очередь, подключение GitHub, `issue_creations` | удаляются | каскад |
| Реакции, строки упоминаний | удаляются | каскад: реакция без человека ничего не говорит, а число на комментарии уменьшается на одну |
| Предложения изменений пользователя | удаляются | каскад: черновик без автора никто не правит и не отзывает |
| Комментарии, решения, привязки задач, кто закрыл ветку, ответственный, кто решил предложение, автор уведомлений других | остаются без автора — «Удалённый пользователь» | `ON DELETE SET NULL`, интерфейс уже показывает «Удалённый пользователь» |
| Авторство версий и правки с прошлой версии | остаются как «Удалённый пользователь» | идентификатор в массивах заменяется на нулевой UUID, версии показывают его как «Удалённый пользователь» |
| Имена в отметках элементов и закреплениях в документах Yjs, `@Имя` в тексте чужих комментариев | остаются | содержимое чужих досок; названо в политике |

- Альтернатива для реакций и упоминаний — служебный пользователь «Удалённый пользователь» в `users`, на которого
  переписываются строки. Отклонена: он попал бы во все списки пользователей, проверки ролей и уборку, а обезличивание
  через `SET NULL` уже принято для комментариев и решений.
- Нулевой UUID в массивах, а не удаление элемента: версия, которую правили двое, должна показывать двух авторов, а не
  одного. Перенос досок гостя (`array_replace`) и чтение авторов с ним работают; нескольких удалённых авторов версия
  показывает одним «Удалённый пользователь» (повторы схлопываются, как и раньше).

### Доски с участниками

- «Другие участники» доски — участники `board_members` и те, кто открывал её по ссылке (`board_visits`). Передать можно
  только участнику: передача владения требует участника, как и в окне «Поделиться». Доску, которую только открывали по
  ссылке, можно лишь удалить; страница предлагает сначала добавить человека в участники.
- Решение передаётся в `DELETE /api/me` явно для каждой такой доски. Сервис проверяет полноту решений до любых
  изменений и отвечает 409 `decisions-required` — так доска не пропадает без предупреждения, даже если участник
  появился между просмотром и удалением.
- Порядок в одной транзакции: блокировка пользователя (`users.lock`, на ней же сериализуются создание досок) → проверки
  (пространства, решения, участники) → передачи досок (могут упасть на пределе получателя) → уход из пространств →
  удаления досок → обезличивание массивов → сеансы → строка пользователя. Изображения удаляются слушателем
  `BoardDeleted` сразу, как и при окончательном удалении из корзины, поэтому всё, что может отказать, идёт до удалений;
  если хранилище недоступно, изображения добирает `ImageCleanup`.

### Пространства

- Единственный владелец пространства, где есть другие участники, не удаляется: 409 `sole-workspace-owner`. Передать
  роль владельца он может на странице пространства — автоматическая передача отдала бы управление командой человеку без
  его согласия.
- В остальных пространствах пользователь уходит, как по кнопке «Покинуть»: доски, за которые он отвечал, переходят
  первому другому владельцу (`WorkspaceService.removeMember`). Пространство, где он один, удаляется: его доски
  уходят в корзину пользователя и удаляются вместе с ней.

### Сервис для администратора

- `AccountDeletionService.preview(userId)` и `delete(userId, decisions, undecided)` не зависят от сеанса и HTTP.
  `undecided = REFUSE` (пользователь) требует решения для каждой доски с участниками; `undecided = DELETE` (администратор
  может выбрать) удаляет доски без решения. Проверку единственного владельца пространства сервис делает всегда.
  Сеансы завершает сам сервис (строки `spring_session`), поэтому администратор, удаляя другого пользователя, тоже
  выбивает его из всех браузеров.

### Соединения синхронизации

- Раз в минуту, вместе с проверкой доступа открытых документов, `collab` собирает пользователей всех соединений и
  спрашивает `POST /internal/users/missing`; соединения тех, кого нет, закрываются с `4401 account-deleted`.
  Одного запроса на весь сервер достаточно, а правило доступа не меняется. Свои вкладки удалённый пользователь
  покидает сам: страница после удаления уходит на вход.
- Альтернатива — `backend` вызывает `collab` при удалении. Отклонена: `backend` к `collab` не обращается (тот же выбор,
  что при смене прав со страницы пространства), а это потребовало бы новый адрес и токен в настройках установки.
- Окно: токен синхронизации, выданный до удаления, живёт до 5 минут; новое подключение с ним закроет следующая
  проверка.

### Выгрузка

- Архив собирает `frontend`: только он умеет превращать документ Yjs в `.drawio` с изображениями внутри. `backend`
  отдаёт JSON со всеми табличными данными (`POST /api/me/export`) и состояние документа каждой своей доски
  (`GET /api/me/export/boards/{id}`), а `frontend` пишет `profile.json`, `boards.json`, `comments.json` и т. д. и
  `boards/<название>.drawio` в ZIP (`zipBytes`, без сжатия, без новой библиотеки).
- В JSON: профиль; свои доски (с корзиной и пространством); участие в чужих досках и пространствах; свои комментарии
  с доской и веткой; реакции; решения, где он автор; свои предложения (без двоичных черновиков); библиотеки с
  компонентами; личные шаблоны с `.drawio`; папки и теги; запросы доступа; каналы уведомлений (адрес почты и вебхука —
  данные самого пользователя) и подключение GitHub — без токена; уведомления.
- Доски в корзине выгружаются тоже: это ещё данные пользователя.
- Предел — `codraw.limits.exports-per-user-per-day` (5): выгрузка читает много строк и все документы досок.
  Считается `POST /api/me/export` в памяти экземпляра, как предел импортов схемы; документы досок пределом не
  ограничены — владелец и так открывает их.

### Токен GitHub

- Токен — персональный токен доступа, который пользователь создал сам и мог использовать ещё где-то. GitHub отзывает
  такие токены только через API отзыва утёкших учётных данных, что сломало бы чужие интеграции пользователя. Поэтому
  CoDraw удаляет токен у себя, а страница и политика напоминают отозвать его в настройках GitHub.

### Подтверждение

- Ввод слова «удалить», а не имени: имя гостя «Гость 12» и имена с GitHub неудобно набирать, а слово однозначно.

### Миграция

- `V28` добавляет индекс `comment_threads (resolved_by)`: это единственный внешний ключ на `users` без индекса, и
  `SET NULL` при удалении пользователя читал бы всю таблицу веток. `U28` его удаляет. Тест проверяет, что у каждого
  внешнего ключа на `users` есть индекс, начинающийся с этого столбца.

### Тест полноты

- `AccountDeletionApiTest` находит в `pg_constraint` все внешние ключи на `users` и сверяет их со списком, который
  тест заполняет данными пользователя; новый внешний ключ без строки в списке валит тест. После удаления каждый такой
  столбец не содержит идентификатора пользователя, массивы — тоже, `spring_session` — тоже.

## Risks / Trade-offs

- [Изображения удаляются из хранилища до фиксации транзакции] → всё, что может отказать, проверяется и выполняется до
  удалений досок; так же работает окончательное удаление из корзины.
- [Удаление большой учётной записи — одна длинная транзакция] → предел досок на пользователя (100) и пространства
  ограничивают объём; уборка гостей удаляет и больше.
- [Имена в документах чужих досок остаются] → названо в политике; это содержимое, которое видели участники.
- [Соединение удалённого пользователя живёт до минуты] → как при любой смене прав без сообщения участника.
- [Предел выгрузок в памяти экземпляра] → как остальные пределы частоты; перезапуск сбрасывает счётчики.

## Migration Plan

`V28` только добавляет индекс; откат — `U28`. Новых настроек, кроме необязательного предела, нет.
