# Proposal

## Why

Политика конфиденциальности обещает удалить учётную запись по просьбе, но инструмента для этого нет ни у пользователя,
ни у оператора: из API пользователя есть только `GET /api/me`, а из базы удаляются только ушедшие гости. Персональные
данные лежат во многих таблицах — комментарии и реакции, ответственные за ветки, решения, участие в досках и
пространствах, запросы доступа, предложения, токен GitHub, адрес почты и вебхук, библиотеки фигур, личные шаблоны, теги
и папки, — и удалять их вручную SQL-запросами рискованно. Право на удаление и на переносимость данных требуют 152-ФЗ и
GDPR (issue #155, готовность к MVP).

## What Changes

- **Страница «Учётная запись»** (`/settings/account`) открывается из шапки рядом с именем пользователя. На ней два
  раздела: «Мои данные» и «Удаление учётной записи».
- **Удаление учётной записи** с явным подтверждением (ввести слово «удалить»). Перед удалением страница показывает, что
  станет с досками и пространствами:
  - личные доски без других участников удаляются вместе с корзиной;
  - для каждой доски, у которой есть участники или те, кто открывал её по ссылке, пользователь выбирает: передать её
    участнику доски или удалить. Без выбора удаление не выполняется — доски с другими участниками не пропадают без
    предупреждения;
  - доски пространств, за которые пользователь отвечал, переходят первому другому владельцу пространства, а сам он
    покидает пространство; пространство, где он единственный участник, удаляется вместе с досками;
  - если пользователь — единственный владелец пространства, в котором есть другие участники, удаление отклоняется, пока
    он не передаст роль владельца.
- **Что удаляется и что обезличивается.** Удаляются профиль, участие в досках и пространствах, запросы доступа, визиты,
  отметки прочтения, теги и папки, библиотеки фигур, личные шаблоны, уведомления пользователя, каналы уведомлений
  (почта и вебхук) с очередью, токен GitHub, реакции, отметки об упоминаниях, предложения изменений пользователя.
  Комментарии, архитектурные решения, привязки задач, решения по чужим предложениям, ответственность за ветки и
  авторство версий остаются на общих досках без автора — «Удалённый пользователь». Изображения удалённых досок
  удаляются из хранилища.
- **Сеансы и соединения.** Все сеансы пользователя завершаются, а соединения синхронизации закрываются не позже чем
  через минуту. Следующий вход через того же провайдера создаёт новую пустую учётную запись.
- **«Скачать мои данные»** собирает ZIP-архив: профиль, доски пользователя в `.drawio` с изображениями, его комментарии,
  реакции, решения, предложения, библиотеки фигур, шаблоны, папки и теги, участие в досках и пространствах, каналы
  уведомлений и подключение GitHub (без токена) в JSON. Частота выгрузки ограничена: 5 в сутки на пользователя
  (`codraw.limits.exports-per-user-per-day`).
- **Сервис удаления в backend** переиспользуемый: им же будет удалять учётные записи администратор установки (#162).
- Политика конфиденциальности описывает удаление и выгрузку данных; README и `docs/deploy.md` — новую возможность и
  предел.

## Capabilities

### New Capabilities

- `account-deletion`: удаление учётной записи пользователем с решением о досках с участниками, обезличивание вклада в
  общие доски, завершение сеансов и соединений синхронизации, выгрузка своих данных с пределом частоты.

### Modified Capabilities

- `legal-pages`: политика конфиденциальности называет удаление учётной записи, что при нём удаляется и обезличивается,
  и выгрузку данных.

## Impact

- `backend`: пакет `account` — `AccountDeletionService` (переиспользуемый), `AccountExportService`,
  `AccountController` (`GET /api/me/deletion`, `DELETE /api/me`, `POST /api/me/export`,
  `GET /api/me/export/boards/{id}`); внутренний `POST /internal/users/missing` для collab; обезличивание авторов версий;
  предел `exports-per-user-per-day`; миграция V28 и откат U28 (индекс `comment_threads.resolved_by`).
- `collab`: проверка соединений раз в минуту закрывает соединения пользователей, которых больше нет.
- `frontend`: `api/account.ts`, страница `/settings/account`, ссылка в шапке, сборка архива выгрузки, сообщение на
  странице входа, «Что нового» и версия приложения.
- `e2e`: `account-deletion.spec.ts`.
- Документация: README, `docs/deploy.md`, политика конфиденциальности.
