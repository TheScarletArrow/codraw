# Proposal

## Why

Перед выпуском MVP оператор не может сказать, работает ли продукт: `CodrawMetrics` считает только созданные доски и
гостей, остальное — операционные метрики (подключения, сохранения, ошибки). README называет совместную работу главным
сценарием, но её никто не измеряет: неизвестно, сколько людей возвращается, переходят ли гости в учётные записи и правят
ли доски вдвоём. Нужен небольшой набор продуктовых метрик на самой установке — без сторонней аналитики и без слежки за
содержимым досок, кликами и функциями.

## What Changes

- `backend` запоминает дни активности пользователей: пара «пользователь, день» пишется не чаще раза в сутки на
  пользователя, когда его сеанс обращается к API (в том числе за токеном подключения к доске); повторы отсекаются в
  памяти, так что почти все запросы ничего не пишут.
- Дни правки досок: «доска, день» — когда `collab` сохранил правки пользователей (заголовок `X-Editors` уже идёт с
  сохранением), и признак совместной правки — когда в этот день хотя бы два разных пользователя одновременно были
  подключены к документу с правом правки. Совместную правку `collab` сообщает новым внутренним запросом
  `POST /internal/boards/{id}/co-edited` не чаще раза в сутки на доску; учёт редакторов — O(1) на подключение и
  отключение.
- Переходы гостей в учётные записи считаются по дням без идентификаторов.
- Записи удаляются через 42 дня — фиксированный срок в коде, не настройка: этого хватает на периоды до 28 дней и на
  четыре недельные когорты удержания. Удаление учётной записи, уборка гостей и окончательное удаление доски удаляют их
  записи сразу. «Скачать мои данные» добавляет файл `activity-days.json` с днями активности пользователя.
- Статистика: активные пользователи за 1, 7 и 28 дней (учётные записи и гости отдельно), новые учётные записи и
  переходы гостей за 7 и 28 дней, удержание первой недели четырёх недельных когорт новых учётных записей, изменённые и
  совместно изменённые доски за 7 и 28 дней с долей совместных.
- `GET /api/admin/stats` — только администраторам; вкладка «Статистика» в разделе «Администрирование».
- Метрики Prometheus `codraw_product_*` с теми же числами, которые фоновая задача обновляет раз в 5 минут, а не при
  каждом опросе.
- Миграция `V32`/`U32` (`user_activity_days`, `board_activity_days`, `product_daily_counts`), «Что нового» 0.44.0,
  справка, README (пункт 118 плана), `docs/deploy.md`, ADR-0014.

## Capabilities

### New Capabilities

- `product-metrics`: дни активности пользователей и правки досок, переходы гостей, определения статистики, срок
  хранения, API статистики для администраторов и метрики Prometheus.

### Modified Capabilities

- `admin-moderation`: вкладка «Статистика» в разделе администрирования.
- `account-deletion`: выгрузка своих данных содержит дни активности пользователя.

## Impact

- `backend`: миграция `V32`/`U32`, пакет `product` (запись активности, статистика, метрики, уборка, API для
  администраторов), перехватчик запросов к `/api/**`, запись правки в сохранении документа, внутренний API
  `POST /internal/boards/{id}/co-edited`, счётчик переходов во входе гостя через провайдера, выгрузка своих данных.
- `collab`: учёт одновременных редакторов документа и сообщение о совместной правке в `backend`.
- `frontend`: вкладка «Статистика», «Что нового» 0.44.0 и версия, справка.
- Новые данные о пользователях — дни активности: политику конфиденциальности обновляет отдельное изменение по описанию
  из `design.md`; настроек и полей `/api/legal` это изменение не добавляет.
- Правил оповещений на продуктовые метрики нет: их падение — не авария, а повод посмотреть на продукт.
