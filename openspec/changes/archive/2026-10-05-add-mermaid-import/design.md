# Design

## Context

Вставка текста в редакторе идёт через `readClipboardText`: XML draw.io становится ячейками, остальное — фигурой
«Текст». Автораскладка (`layoutShapes`) раскладывает фигуры слоями и держит фигуры внутри рамок, определяя рамку по
координатам. Импорт SQL строит таблицы и связи полей через `schemaCells` и вставляет их справа от схемы страницы.

## Goals / Non-Goals

**Goals:**

- Вставить блок-схему или ER-диаграмму Mermaid из README одной вставкой и получить редактируемую схему.
- Терпимость: незнакомые строки (стили, классы, щелчки) пропускаются, а не ломают импорт.

**Non-Goals:**

- Стили Mermaid (`style`, `classDef`), иконки и изображения в узлах, ссылки `click`.
- Диаграммы последовательностей, классов, состояний, Ганта, C4 Mermaid; экспорт блок-схем в Mermaid.
- Многострочные определения и HTML в подписях кроме `<br>`.

## Decisions

### Свой разборщик вместо пакета `mermaid`

- Пакет `mermaid` весит больше 2 МБ, требует DOM и отдаёт SVG, а не граф; его внутренний парсер не публичный.
  Нужное подмножество — строки узлов и связей, `subgraph … end`, сущности и отношения ER — разбирается построчно.
- Комментарии `%%`, front matter `--- … ---`, `;` как разделитель операторов. Строки `style`, `classDef`, `class`,
  `linkStyle`, `click`, `direction` и непонятые строки считаются пропущенными.

### Блок-схема → ячейки

- Узел — фигура палитры по форме: `[ ]`, `[[ ]]`, `{{ }}`, `>]`, трапеции → «Прямоугольник»; `( )`, `([ ])` →
  «Скруглённый прямоугольник»; `(( ))`, `((( )))` → «Эллипс»; `{ }` → «Ромб»; `[( )]` → «База данных». Размер — по
  палитре, шире для длинных строк (до 320), выше для `<br>`.
- Связь: `---` без стрелки, `<-->` со стрелками с обеих сторон, `-.->` пунктиром, `==>` толщиной 3, подпись связи.
  `A & B --> C` — связи от каждого слева к каждому справа; цепочка `A --> B --> C` — по парам.
- `subgraph id [Заголовок] … end` → рамка «Граница» с заголовком; узел относится к самому внутреннему `subgraph`, где
  он впервые упомянут внутри `subgraph`. Связь к самому `subgraph` не рисуется.
- Раскладка — `layoutShapes` в направлении схемы. Рамка подграфа задаётся явно (`parent` у фигуры раскладки), а не
  по координатам: до раскладки у фигур ещё нет мест.

### ER-диаграмма → таблицы

- Сущность → таблица, атрибут `тип имя PK, FK, UK` → поле (`_` в типе — пробел: так пишет выгрузка CoDraw).
- Отношение `A ||--o{ B : подпись`: ссылается сторона «много» (без неё — правая). Её поле — атрибут `FK`, названный по
  таблице, на которую он ссылается, иначе первый свободный `FK`; связь идёт от него к первичному ключу. Кратности дают
  маркеры через уникальность и обязательность столбца, как в импорте SQL. Без такого поля или при «много ко многим» —
  связь между таблицами (`TableLink` в `schemaCells`) с маркерами кратностей.

### Где вставляется

- `readClipboardText` распознаёт Mermaid по первой значимой строке (`flowchart`, `graph`, `erDiagram`) и отдаёт
  ячейки как новую схему: из меню она встаёт левым верхним углом в точку щелчка, по клавишам — серединой в середину
  видимой области. Другой вид Mermaid или ошибка разбора — вставка текста, как раньше.
- В меню кода — «Импорт Mermaid…» с полем текста, сводкой и добавлением справа от схемы, как импорт SQL.

## Risks / Trade-offs

- [Синтаксис Mermaid богаче разбора] → незнакомая строка пропускается и считается в сводке; при вставке текст,
  который выглядит как Mermaid, но не дал ни одного узла, вставляется как текст.
- [Обычный текст, начинающийся со слова `graph`] → распознаётся только строка-заголовок `graph`/`flowchart` с
  направлением или в одиночку и `erDiagram`; без узлов вставляется текст.
