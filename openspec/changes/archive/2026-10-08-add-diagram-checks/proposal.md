# Proposal

## Why

Схему архитектуры ревьюят глазами, и типовые недочёты повторяются: связь без подписи, контейнер без технологии, два
сервиса пишут в одну базу, один и тот же сервис нарисован на двух страницах разными элементами. Ревьюер тратит время
на то, что можно найти автоматически, а документация остаётся неполной. Это шаг эпика «проектирование архитектуры
систем» (#81), задача #95.

**До:** недочёты схемы находит только человек на ревью.

**После:** кнопка «Проверки» в шапке доски показывает число замечаний и открывает панель со списком замечаний по всем
страницам с переходом к ячейке. Это подсказки, а не запрет: замечание можно скрыть, правило — выключить для доски.

## What Changes

- Кнопка «Проверки» в шапке доски и предложения изменений: значок, число замечаний; открывает и закрывает панель
  «Проверки» справа на холсте.
- **Правила** по модели архитектуры, как её видит «Архитектура как код», по всем страницам; ячейки общего элемента —
  один элемент:
  - связь между элементами без подписи; без технологии;
  - контейнер или компонент без технологии; элемент с подписью C4 без описания; система или контейнер без владельца
    (выключено по умолчанию);
  - элемент без связей ни на одной странице;
  - Container C4 вне границы системы, Component C4 вне границы контейнера;
  - цикл зависимостей между сервисами (без баз, очередей и людей);
  - общая база данных: к одной базе связаны два и больше сервисов;
  - вероятные дубли: разные элементы с одним именем на разных страницах; имена фигур палитры не считаются.
- **Панель**: вкладка «Замечания» — замечания по правилам с объяснением правила, предметом замечания, уточнением и
  ссылками на страницы ячеек; вкладка «Правила» — флажки правил с объяснением. Последние три правила —
  предупреждения.
- **Скрытие и правила**: кнопка с глазом скрывает замечание для этого случая и показывает снова; «Показать скрытые»
  возвращает скрытые в список; флажок правила включает и выключает его для доски. Скрытые замечания и правила хранятся
  в документе доски (`checks`) и общие для всех участников; в режиме «Просмотр» их только видно.
- **«Объединить…»** у вероятных дублей: выбор, чьи свойства оставить, и объединение в один общий элемент одним шагом
  отмены текущей страницы; закреплённые фигуры не объединяются.
- Замечания пересчитываются у каждого участника по мере правок (не чаще раза в 300 мс); сервер ничего не считает.

## Capabilities

### New Capabilities

- `diagram-checks`: кнопка и панель «Проверки», правила, скрытие замечаний и выключение правил, объединение дублей.

### Modified Capabilities

Нет.

## Impact

- `frontend`: правила без холста — `checks/checks.ts` (модель доски по `architecture/model.ts`, замечания, настройки в
  документе); хранилище с пересчётом — `checks/useChecks.ts`; панель и кнопка — `checks/ChecksPanel.tsx`;
  `architecture/model.ts` — у элементов, рамок и связей идентификаторы ячеек; `diagram/editor.ts` —
  `mergeElementCells` для ячеек любых страниц; `BoardPage`, `ProposalPage`; «Что нового» 0.15.0, README.
- `backend` и `collab` не меняются: настройки — карта `checks` документа Yjs. Новых зависимостей нет.
- Вне рамок: свои правила пользователей, проверки в CI, замечания на холсте у фигур.
