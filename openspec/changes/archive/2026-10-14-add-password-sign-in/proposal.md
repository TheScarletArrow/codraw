## Why

Сейчас в CoDraw входят только через GitHub, Google, корпоративного провайдера OpenID Connect или гостем. Небольшой
установке, у которой нет корпоративного провайдера и которая не хочет заводить OAuth-приложения GitHub и Google, нужен
самый простой постоянный вход: логин и пароль, без почты и без внешних сервисов. Гость для этого не годится: его сеанс
живёт 30 дней, а вернуться с другого устройства он не может.

## What Changes

- Вход по логину и паролю включается настройкой `codraw.passwords.enabled` (`CODRAW_PASSWORDS_ENABLED`), по
  умолчанию выключен, чтобы закрытые установки не открылись сами после обновления. Регистрацию можно выключить
  отдельно (`codraw.passwords.sign-up`, `CODRAW_PASSWORDS_SIGN_UP`): тогда входят только уже зарегистрированные.
- Регистрация на странице входа: логин (3–32 символа: латинские буквы, цифры, `.`, `_`, `-`; без учёта регистра
  уникален), пароль (не короче 8 символов, не длиннее 72 байт, не совпадает с логином) и его повтор. Логин —
  имя пользователя в CoDraw. Почта не нужна, сброса пароля по почте нет.
- Вход: логин и пароль; неверный логин и неверный пароль неотличимы ни по ответу, ни по времени ответа. Неудачные
  попытки ограничены по сетевому адресу и по логину, регистрации — по сетевому адресу; сверх предела — 429 с
  `Retry-After`.
- Гость, который регистрируется или входит по паролю, переносит свои доски, как при входе через провайдера.
  Заблокированный администратором пользователь не входит.
- Смена пароля на странице «Учётная запись»: текущий пароль и новый; остальные сеансы пользователя завершаются.
- Пароль хранится только хешем (bcrypt, с префиксом алгоритма), в отдельной таблице; в выгрузку данных хеш не
  попадает, удаление учётной записи удаляет и его.
- Администратор установки по паролю — `password:<логин>` в `CODRAW_ADMINS`. Логин из этого списка зарегистрировать
  нельзя: его не займёт посторонний, пока администратор не зарегистрировался.
- `GET /api/auth/providers` сообщает, включены ли вход по паролю и регистрация; политика конфиденциальности называет
  логин и хеш пароля, когда вход по паролю включён.
- `docs/deploy.md`, README, `.env.prod.example`, `docker-compose.prod.yml`, справка, «Что нового», ADR-0015.

## Capabilities

### New Capabilities

- `password-sign-in`: регистрация и вход по логину и паролю, правила логина и пароля, пределы попыток, смена
  пароля, хранение пароля.

### Modified Capabilities

- `user-auth`: способы входа установки включают вход по паролю; страница входа без способов входа учитывает его.
- `admin-moderation`: администратором может быть пользователь, вошедший по паролю; блокировка закрывает и вход по
  паролю.
- `legal-pages`: политика конфиденциальности называет логин и хеш пароля, когда вход по паролю включён.

## Impact

- `backend`: миграция `password_credentials`, `PasswordProperties`, `PasswordController` (регистрация, вход,
  смена пароля), пределы попыток, `GET /api/auth/providers`, `/api/me`, `/api/legal`, `AdminProperties`, метрики
  пределов, тесты.
- `frontend`: форма входа и регистрации на странице входа, вход по паролю со страницы приглашения в пространство,
  смена пароля на странице «Учётная запись», политика конфиденциальности, справка, «Что нового», версия 0.48.0.
- e2e: регистрация, вход, неверный пароль, перенос досок гостя, смена пароля.
- `docker-compose.prod.yml`, `.env.prod.example`, `docs/deploy.md`, README, ADR-0015.
