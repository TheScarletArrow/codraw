## MODIFIED Requirements

### Requirement: Способы входа установки

Страница входа SHALL показывать только способы входа, включённые в установке: форму входа по логину и паролю — если
он включён, со ссылкой «Зарегистрироваться» — если включена и регистрация, GitHub и Google — если задано их
OAuth-приложение, корпоративных провайдеров — по их настройкам, «Продолжить без входа» — если гостевой вход включён.
Список SHALL отдавать `GET /api/auth/providers` без входа. Без единого способа входа страница SHALL сообщать, что вход
не настроен.

#### Scenario: Только корпоративный вход

- **WHEN** оператор задал только корпоративного провайдера и выключил гостевой вход
- **THEN** на странице входа одна кнопка «Войти через <название провайдера>», без формы входа по паролю, без GitHub,
  Google и «Продолжить без входа»

#### Scenario: Только логин и пароль

- **WHEN** оператор включил вход по паролю, не задал OAuth-приложений и провайдеров и выключил гостевой вход
- **THEN** на странице входа форма «Логин», «Пароль», кнопка «Войти» и ссылка «Зарегистрироваться», без кнопок
  провайдеров и «Продолжить без входа»

#### Scenario: Список способов входа

- **WHEN** клиент без сеанса запрашивает `GET /api/auth/providers`
- **THEN** ответ имеет статус 200 и содержит включённых провайдеров с идентификаторами и названиями, признак
  гостевого входа и, если вход по паролю включён, признак регистрации

#### Scenario: Вход не настроен

- **WHEN** в установке нет ни одного провайдера, вход по паролю и гостевой вход выключены
- **THEN** страница входа сообщает «Вход не настроен. Обратитесь к администратору»

### Requirement: Вход заблокированного пользователя

Пользователь, которого заблокировал администратор, SHALL NOT входить: вход через GitHub, Google или корпоративного
провайдера SHALL вести на страницу входа с `?blocked`, где сказано «Учётная запись заблокирована администратором
установки», вход по паролю с верным паролем — отвечать 403 с тем же сообщением на странице входа, а тестовый вход —
отвечать 403. Учётная запись при этом SHALL NOT меняться, кроме имени и аватара от провайдера.

#### Scenario: Вход через провайдера

- **WHEN** заблокированная Алиса входит через GitHub
- **THEN** сеанс не создаётся, и открывается страница входа с сообщением о блокировке

#### Scenario: Вход через корпоративного провайдера

- **WHEN** заблокированный пользователь входит через Keycloak компании
- **THEN** сеанс не создаётся, и открывается страница входа с сообщением о блокировке

#### Scenario: Вход по паролю

- **WHEN** заблокированный пользователь входит по логину и верному паролю
- **THEN** ответ имеет статус 403, сеанс не создаётся, а страница входа сообщает о блокировке

#### Scenario: Заблокированный с неверным паролем

- **WHEN** заблокированный пользователь входит по своему логину с неверным паролем
- **THEN** ответ тот же 401 «Неверный логин или пароль», что и для любого неверного пароля

#### Scenario: Вход после разблокировки

- **WHEN** администратор разблокировал Алису, и она входит через GitHub
- **THEN** она входит, как раньше, со своими досками
