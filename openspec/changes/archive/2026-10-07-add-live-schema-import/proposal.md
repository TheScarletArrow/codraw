# Proposal

## Why

«Импорт SQL» принимает DDL и миграции Flyway, но у существующей базы схема часто есть только в самой базе. Самый
короткий путь — дамп схемы, `pg_dump --schema-only` или `mysqldump --no-data`, а сейчас он разбирается плохо:
мета-команда `\restrict` новых `pg_dump` склеивается со следующим оператором, `DELIMITER` в `mysqldump` режет
процедуры на куски, сводка насчитывает десятки «пропущенных» служебных операторов (`SET`, `GRANT`, `COMMENT ON`,
`OWNER TO`), столбец `bigserial` превращается в `bigint`, а секции партиционированной таблицы рисуются отдельными
таблицами. Полный дамп с данными ломает разбор совсем: строки `COPY … FROM stdin` попадают в операторы. Второй путь —
взять схему прямо из базы без файла (issue #54): для этого CoDraw должен подключаться к базе, а это вопрос
безопасности установки — доступ `backend` к сетям, учётные данные, таймауты.

## What Changes

- Дампы: `pg_dump` (с `--schema-only` и без, с `--no-owner --no-privileges` и без), `mysqldump` и `mariadb-dump`
  с `--no-data --routines --triggers` дают правильные таблицы, поля, первичные и внешние ключи, уникальность и
  индексы. Мета-команды psql (`\restrict`, `\connect`) пропускаются, `DELIMITER` меняет разделитель операторов,
  данные `COPY … FROM stdin` до `\.` пропускаются; `ALTER TABLE … SET DEFAULT nextval(…)` делает столбец `serial`,
  `bigserial` или `smallserial`; секции (`ATTACH PARTITION`, `PARTITION OF`) не становятся таблицами; схема у типа
  отбрасывается (`public.order_status` → `order_status`); `CHARACTER SET` MySQL не входит в тип.
- Сводка считает пропущенными только объекты, которые CoDraw не рисует (представления, функции, процедуры, триггеры,
  типы), и непонятые операторы; служебные операторы (настройки сеанса, владельцы и права, комментарии,
  последовательности, схемы, расширения, транзакции) и данные (`INSERT`, `COPY`) не считаются.
- В окне «Импорт SQL» — подсказка, какими командами снять дамп.
- «Подключиться к базе…» в окне «Импорт SQL» — только PostgreSQL и только если администратор установки разрешил
  адреса баз (`codraw.schema-import.allowed-hosts`, по умолчанию пусто — функция выключена). Поля «Хост», «Порт»,
  «База», «Схема», «Пользователь», «Пароль», «SSL» или строка подключения `jdbc:postgresql://…`/`postgresql://…`,
  которую окно разбирает в поля. `backend` читает каталог одной схемы и отдаёт DDL как у `pg_dump`, который встаёт
  в поле DDL, — дальше тот же разбор, сводка, автораскладка и один шаг отмены.
- Безопасность подключения: `backend` не принимает строку JDBC и строит параметры драйвера из белого списка;
  разрешённые адреса задаёт администратор (имена и сети CIDR), имя проверяется по всем его адресам, а подключение
  идёт по проверенному адресу; loopback, link-local и адрес базы самого CoDraw запрещены без явного разрешения;
  таймауты, только чтение, одно соединение без пула; только для вошедших не гостями, не больше 30 импортов в час на
  пользователя; ошибки — общие категории без подробностей сети; учётные данные не хранятся и не попадают в журналы,
  метрики и ответы.
- Журнал и метрика `codraw_schema_imports_total{result}` без учётных данных и имени базы.
- Политика конфиденциальности при включённой функции говорит, что учётные данные базы проходят через сервер и не
  хранятся.
- ADR-0007 о подключении к живой базе: почему через `backend` и выключено по умолчанию, почему без MySQL и без
  CLI-утилиты.

## Capabilities

### New Capabilities

- `live-schema-import`: схема PostgreSQL из живой базы через `backend` по разрешённым администратором адресам.

### Modified Capabilities

- `sql-schema`: импорт дампов `pg_dump`, `mysqldump` и `mariadb-dump`, счёт пропущенных операторов без служебных,
  подсказка о дампах.
- `legal-pages`: политика называет подключение к базе данных, когда оно включено.

## Impact

- `frontend`: разбор дампов в `sql/parseSql.ts` и служебные операторы в `sql/statementKinds.ts`, фикстуры настоящих
  дампов `sql/fixtures/`; строка подключения `sql/connectionString.ts`; окно «Подключение к базе»
  `sql/DatabaseConnection.tsx` и `sql/SqlMenu.tsx`; клиент API `api/schemaImport.ts`; политика `legal/PrivacyPage.tsx`;
  «Что нового» 0.6.0.
- `backend`: пакет `schemaimport` (настройки, проверка адресов, сокет по проверенному адресу, чтение каталога,
  контроллер `GET`/`POST /api/schema-import`), предел `codraw.limits.schema-imports-per-user-per-hour`, метрика,
  поле `schemaImport` в `GET /api/legal`; драйвер PostgreSQL нужен при компиляции. Миграции базы нет: ничего не
  хранится.
- `docs/adr/0007-live-schema-import.md`, `docs/deploy.md`, `docs/running.md`, README, `.env.example`,
  `.env.prod.example`, `docker-compose.prod.yml`; e2e `live-schema-import.spec.ts` (профиль `e2e` разрешает
  `localhost`).
- `collab` не меняется.
