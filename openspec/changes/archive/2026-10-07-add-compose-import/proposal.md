# Proposal

## Why

Самое точное описание контейнеров проекта и их зависимостей часто уже лежит в репозитории — это `docker-compose.yml`
(у CoDraw их два: для разработки и для продакшена). Схему контейнеров по нему рисуют руками, как раньше рисовали
таблицы по DDL до «Импорт SQL…», и она расходится с файлом после первого же нового сервиса. CoDraw уже превращает в
схему DDL, Mermaid и спецификации API (issue #88, эпик #81), а файлы compose — нет.

## What Changes

- В меню «SQL и Mermaid» появляется «Импорт docker-compose…» (только у тех, кто правит доску): поле для текста,
  «Открыть файлы» (`.yaml`, `.yml`, несколько сразу — сливаются, как `docker compose -f a.yml -f b.yml`), галочки
  «Связи по переменным окружения» (включена) и «Фигуры C4» (выключена), сводка «Сервисов: N, связей: N, сетей: N»,
  ошибки со строкой и столбцом и «Добавить на страницу». Схема встаёт справа от фигур страницы, разложенная
  автораскладкой слева направо, одним шагом отмены у всех участников.
- Сервис становится фигурой палитры по образу: базы данных — «База данных», Redis и подобные — «Кэш», RabbitMQ и
  NATS — «Очередь», Kafka и Redpanda — «Топик событий», nginx, HAProxy, Traefik, Envoy — «Балансировщик нагрузки»,
  Kong и подобные — «API-шлюз», MinIO и RustFS — «Хранилище объектов», Elasticsearch и OpenSearch — «Поисковый
  индекс», ClickHouse — «Хранилище данных», остальные и собираемые из исходников — «Контейнер». Подпись — имя
  сервиса, образ (или каталог и Dockerfile сборки) и опубликованные порты. С «Фигуры C4» — Container и Database C4 с
  подписью `имя`, `[Container: образ]`.
- Связи: `depends_on`, `links` и `network_mode: service:…` — от зависимого сервиса к зависимости; с «Связи по
  переменным окружения» — ещё и адреса других сервисов в значениях переменных (`jdbc:postgresql://postgres:5432/…`,
  `http://backend:8080`, `redis:6379`), подписанные протоколом (`JDBC`, `HTTP`, `Redis`).
- Сети: если сервисы в двух сетях и больше, каждая сеть — рамка «Граница» с именем сети вокруг своих сервисов.
- Значения `${VAR:-по умолчанию}` берутся по умолчанию; переменные без значения по умолчанию остаются как написаны.

## Capabilities

### New Capabilities

- `infrastructure-import`: схема контейнеров, их связей и сетей доски из описаний инфраструктуры — начиная с
  docker-compose.

### Modified Capabilities

- `sql-schema`: меню «SQL и Mermaid» предлагает «Импорт docker-compose…», фигуры сервисов compose не считаются
  таблицами и не выгружаются в SQL и Mermaid.
- `diagram-editing`: элементы из импорта docker-compose отмечены участником, который их добавил.

## Impact

- `frontend`: новый модуль `infra/` (разбор compose, граф инфраструктуры, ячейки, окно импорта), пункт меню в
  `sql/SqlMenu.tsx`; разбор YAML и сообщения об ошибках — из `apiSpec/loadDocument.ts`, раскладка — `layoutShapes`.
- `backend`, `collab` и документ доски не меняются: файлы разбираются в браузере и никуда не отправляются.
- Вне объёма: подстановка переменных из `.env` и окружения, `extends` из других файлов, `include`, Docker Swarm
  (`deploy`), тома как фигуры, профили как метки (появятся со свойствами элементов, #82), Kubernetes (#97).
