# Design

## Context

Комментарии и архитектурные решения уже хранятся в `backend` с привязкой к ячейке (`page_id`, `cell_id`) или ветке, с
правами «читают все участники, пишут редакторы» и сообщениями `collab` для остальных участников. Уведомления вне
CoDraw (ADR-0008) уже ходят во внешние системы с секретами пользователя и списком разрешённых хостов. Подробное
обоснование выбора трекера, способа подключения и обновления статуса — в ADR-0009.

## Goals / Non-Goals

- Цели: подключение GitHub токеном пользователя; привязка доступной задачи к элементу или ветке; создание задачи со
  ссылкой обратно; номер, название и статус в CoDraw с переходом в GitHub; идемпотентность повторов; явная обработка
  потери доступа и удаления; права на раскрытие задач.
- Не цели: другие трекеры, двусторонняя синхронизация, pull request, автоматическая смена статуса элемента по задаче.

## Decisions

### Снимок задачи в `backend`

`issue_links` хранит то, что CoDraw последний раз узнал о задаче, — так статус видят участники без подключения и доска
не зависит от доступности GitHub. Цель — элемент или ветка (`CHECK`: ровно одно), идентичность задачи — её id в GitHub
(`external_id`), который переживает переименование репозитория и перенос задачи. `UNIQUE NULLS NOT DISTINCT` по цели
и `external_id` делает повторную привязку обновлением той же строки (`INSERT … ON CONFLICT DO UPDATE`).

### Чьим токеном

Найти, привязать и создать задачу можно только своим токеном. Обновляет привязку токен того, кто её привязал, — и только
когда её показывают (старше 5 минут, сервер — не чаще раза в минуту на привязку) или по кнопке. «Не обновляется»
вычисляется при чтении: у привязавшего нет подключения, GitHub отверг его токен или привязавшего удалили. «Обновлять
через моё подключение» делает привязку своей явным действием, так что чужой токен ничего не раскрывает сам.

### Создание без дублей

Клиент выбирает `requestId` на окно создания. `issue_creations (user_id, request_id)` резервируется до запроса к GitHub:
повтор получает готовую привязку (200), пока первый запрос идёт — 409 `creation-in-progress`; неудача снимает резерв, а
резерв без привязки старше 2 минут считается брошенным. Ссылка обратно — `{app}/boards/{id}?page=…&cell=…` или
`?thread=…`, адрес приложения — `codraw.notifications.app-url` или адрес запроса; подпись элемента и название доски
экранируются для Markdown, `@` и `#` разрываются невидимым пробелом.

### Вебхук

`POST /api/integrations/github/webhook` открыт без сеанса и CSRF и принимает только подпись HMAC-SHA256 секретом
установки. Событие `issues` меняет только привязки с тем же `external_id` и только если `updated_at` задачи не старше
известного; `deleted` помечает привязку удалённой, `transferred` переносит её на новую задачу. Без секрета — 404.

### Интерфейс

Панель «Задачи элемента» — в правой колонке панелей холста, открывается из меню и значка элемента. Значок — под левым
нижним углом, рядом со статусом: зелёный, пока есть открытые задачи. Задачи ветки показывает `ThreadCard` через контекст
задач доски, поэтому и в панели комментариев, и в обсуждении решения, а вне доски (черновик предложения) — ничего.
Сообщение `issues-changed` перечитывает привязки у остальных участников.

## Risks / Trade-offs

- [Токен хранится открытым текстом в базе] → как адреса вебхуков (ADR-0008); страница советует fine-grained токен с
  нужными репозиториями и сроком; отвергнутый GitHub токен больше не отправляется.
- [Статус без вебхука отстаёт до 5 минут] → обновление при показе и кнопка; вебхук — по желанию администратора.
- [Редкий дубль задачи, если `backend` упал между созданием и записью привязки] → GitHub не принимает ключ
  идемпотентности; окно — доли секунды.
- [Снимок закрытой задачи остаётся после потери доступа привязавшего] → он был показан доске намеренно; панель помечает
  его «нет доступа», и его можно отвязать.
