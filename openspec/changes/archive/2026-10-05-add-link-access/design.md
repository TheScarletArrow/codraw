# Design

## Context

Права на доску проверяет `backend` в двух местах: `GET /api/boards/{id}` отдаёт доску любому вошедшему, а
`POST /api/boards/{id}/collab-token` выдаёт RS256-токен на 5 минут с утверждениями `sub`, `board`, `name`, `avatar`.
`collab` (Hocuspocus) проверяет токен по JWKS один раз — при подключении — и дальше держит соединение сколько
угодно. Участники узнают о переименовании и удалении доски по служебному сообщению `board-changed`, которое
отправляет фронтенд владельца, а `collab` рассылает остальным. Фронтенд привязывает холст maxGraph к Yjs-документу:
любая правка модели уходит в документ и дальше в `collab`. Требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Право на правку проверяет сервер: участник с правом `view` не изменит документ даже собственным клиентом.
- Смена режима доходит до подключённых участников без перезагрузки, а права на сервере меняются вместе с ней.
- Режим просмотра не портит документ: клиент, который только смотрит, ничего не пишет в Yjs.

**Non-Goals:**

- Приглашения по имени или почте, роли для отдельных пользователей, роль комментатора.
- Отдельные ссылки с разными правами для одной доски и отзыв уже выданной ссылки сменой идентификатора.
- Передача владения доской.

## Decisions

### Режим доступа в данных

- Колонка `boards.link_access text NOT NULL DEFAULT 'EDIT' CHECK (link_access IN ('NONE', 'VIEW', 'EDIT'))`.
  Значения — имена enum `LinkAccess`, как Spring Data JDBC пишет enum без конвертеров; в API они в нижнем регистре
  через `@JsonValue`, как у `BoardRole`.
- Существующие доски получают `EDIT` значением по умолчанию: ссылки, которые уже разосланы, продолжают работать.
  Новые доски тоже создаются с `EDIT` — совместная правка по ссылке остаётся основным сценарием, а закрыть доску
  владелец может в окне «Поделиться». Альтернатива — `NONE` или `VIEW` для новых досок — безопаснее, но добавляет
  шаг к каждому совместному сеансу и меняет привычное поведение; значение по умолчанию меняется одной строкой,
  если продукт решит иначе.
- Отдельная таблица прав не нужна: пока нет приглашений, права — это владелец плюс один режим ссылки.

### API

- Режим меняется тем же `PATCH /api/boards/{id}`, что и название: тело содержит `title`, `linkAccess` или оба.
  Тело без обоих полей — 400, как и сейчас для `{}`. Это и было причиной выбрать `PATCH` при переименовании.
  Смена только режима не трогает `updated_at`: список досок отсортирован по изменениям содержимого и названия.
- Переименование и смена режима обновляют только свои колонки (`SET title, updated_at` и `SET link_access`), а не
  всю строку: иначе переименование, прочитавшее доску до смены режима, вернуло бы прежний режим — например, снова
  открыло бы закрытую доску.
- Роль считает одна функция `Board.roleOf(userId)`: владелец — `owner`, остальные — `editor` при `EDIT`, `viewer`
  при `VIEW` и `null` при `NONE`. Контроллер переводит `null` в 403 и для доски, и для токена. 403, а не 404:
  у участника есть ссылка, он знает, что доска существует, и должен увидеть, что доступ закрыт, а не что доску
  удалили.
- Посещение записывается только при успешном `GET`. Строки посещений при закрытии доступа не удаляются —
  `GET /api/boards/shared` отфильтровывает доски с `NONE`; когда владелец снова откроет доступ, доска вернётся
  в список участника без повторного открытия.
- Ответ о доске получает `linkAccess` для всех ролей: участник по ссылке видит в окне «Поделиться», что по ссылке
  можно только смотреть.

### Право при подключении и соединения только для чтения

- Токен удостоверяет пользователя и доску, но права в нём нет. В `onAuthenticate` `collab` после проверки токена
  запрашивает у `backend` `GET /internal/boards/{id}/access` → `{"ownerId", "linkAccess"}` и считает право тем же
  правилом, что и `Board.roleOf`: владельцу — `edit`, остальным — режим доски. При `none` подключение отклоняется
  с причиной `no-access` до загрузки документа: клиент не получает ни документа, ни awareness. При `view`
  `connectionConfig.readOnly = true`: Hocuspocus сам отвечает на правки такого соединения отказом и не применяет
  их, а awareness — курсоры и выделения — принимает, как от остальных. Право кладётся в контекст соединения.
- Альтернатива — право в утверждении токена. Отклонено: токен живёт 5 минут, и сохранённый токен, выданный до
  смены режима, давал бы прежние права новому подключению — в том числе правку после «Только я», пока кто-нибудь
  не пришлёт `board-changed`. Запрос прав на подключение стоит одного внутреннего запроса, а `collab` и так
  обращается к `backend` за документом.
- Альтернатива — проверять право в `beforeHandleMessage` по своим правилам. Отклонено: встроенный режим только для
  чтения уже различает синхронизацию и правки и сообщает клиенту `readonly` при аутентификации.
- Страница доски правит только по соединению, которое принимает изменения: режим просмотра включает и роль
  `viewer`, и ответ `readonly` при аутентификации. Если право соединения не совпало с ролью, которую страница
  получила перед подключением (режим сменили между ними), страница запрашивает доску заново.

### Смена режима у подключённых участников

- Право считается при подключении, поэтому после смены режима открытые соединения держат старые права.
  После успешного `PATCH` фронтенд владельца отправляет `board-changed`, как после переименования. `collab`,
  получив это сообщение, кроме рассылки снова запрашивает режим доски и закрывает каждое соединение, право которого
  не совпадает с текущим. Код закрытия 4403, причина `access-changed`.
- Владелец может сменить режим и без открытой доски (запросом к API), а `board-changed` может потеряться, например
  если вкладка владельца в этот момент без связи. Поэтому `collab` сверяет так же все открытые документы раз
  в минуту: это предел, за который смена режима доходит до подключённых в любом случае. Цена — один внутренний
  запрос в минуту на открытую доску.
- Клиент после такого закрытия переподключается сам и получает новое право. С правом `view` у него соединение
  только для чтения, при `none` — 403 на токен (или отказ `no-access`, если режим сменился уже после выдачи
  токена), после чего страница показывает «Нет доступа» и больше не переподключается. Одновременно
  `board-changed` заставляет страницу заново запросить доску и перейти в режим просмотра или обратно по новой роли.
- Участник, который в момент смены переподключался (например, после предыдущей смены провайдер ждёт секунду перед
  новой попыткой), не получит ни `board-changed`, ни закрытия. Права на сервере у него всё равно новые — они
  считаются при подключении, — а роль на странице догоняет их так: страница заново запрашивает доску при каждой
  повторной аутентификации в `collab`.
- Сообщение — только подсказка: права `collab` берёт у `backend`, поэтому лишний `board-changed` от любого клиента
  приводит лишь к лишнему запросу. Чтобы участник не засыпал `backend` такими запросами, на документ выполняется
  не больше одной проверки одновременно, а сообщения, пришедшие во время проверки, дают ровно одну следующую.
- `404` на запрос прав значит, что доску удалили: `collab` закрывает соединения с причиной `board-not-found`, как
  при отказе сохранения. Удаление со страницы доски теперь доходит до участников сразу и без правок.
- Альтернатива — сигнал от `backend` в `collab` при смене режима. Отклонено по той же причине, что и для
  переименования: `backend` не знает, какой экземпляр `collab` держит документ. Сверка по таймеру закрывает тот же
  случай без новой связи между сервисами.

### Режим просмотра во фронтенде

- `createDiagramEditor` получает `readOnly`. В этом режиме граф запрещает перемещение, изменение размера, правку
  подписей, соединение, удаление и клонирование (`setCellsLocked`, `setCellsEditable(false)`,
  `setConnectable(false)`, `setCellsDeletable(false)`, `setCellsCloneable(false)`), клавиатура знает только Ctrl+C
  и Ctrl+A, а команды редактора, которые меняют модель, ничего не делают. Выделение, прокрутка, масштаб и
  копирование в буфер вкладки остаются: участник может перенести фрагмент на свою доску.
- Страница доски при роли `viewer` не показывает панель фигур, стрелки быстрого соединения, инструменты правки
  на панели инструментов (остаётся масштаб), пункты меню правого щелчка, кроме «Копировать» и «Выделить всё»,
  добавление и меню страниц, импорт `.drawio`. Экспорт в `.drawio` остаётся. В шапке — отметка «Только просмотр».
- Клиент без права правки не инициализирует документ после синхронизации: `initializeDocument` пишет в Yjs,
  а такие записи сервер отклонил бы, и документ клиента разошёлся бы с документом остальных. Если у доски ещё нет
  ни одной страницы (владелец создал её и не открывал), участник видит «Доска пока пуста».
- Роль меняется на лету: при новой роли холст пересоздаётся с другим `readOnly`, как при смене страницы.
- Главная страница помечает доски с ролью `viewer` в разделе «Открытые по ссылке» словом «просмотр».

### Окно «Поделиться»

- Кнопка «Поделиться» в шапке доски открывает `Popover`: поле со ссылкой на доску с текущей страницей
  (`/boards/{id}?page=…`, как адрес доски) и кнопка «Копировать» (`navigator.clipboard.writeText`), которая на
  пару секунд меняется на «Скопировано». Без доступа к буферу (небезопасный контекст) кнопка выделяет текст поля,
  чтобы его скопировали вручную.
- Владелец выбирает режим из трёх вариантов с пояснениями: «Только я», «Просмотр», «Редактирование». Выбор сразу
  отправляет `PATCH`, кладёт ответ в кэш запроса доски и отправляет `board-changed`. Остальные видят текст о своём
  уровне доступа.

## Risks / Trade-offs

- [Правки, которые участник сделал перед сменой режима на `view` и которые дошли до сервера уже по соединению только
  для чтения, остаются только у него] → окно — доли секунды; после перезагрузки страницы участник видит документ
  сервера, права при этом соблюдены.
- [Владелец сменил режим запросом к API без страницы доски, или `board-changed` потерялся] → подключённые участники
  сохраняют прежние права до ближайшей сверки по таймеру, не дольше минуты; новые подключения сразу получают новые.
- [`backend` недоступен при подключении] → подключение отклоняется, как и сейчас при ошибке загрузки документа;
  `collab` не пускает участника с правами, которые не смог проверить.
- [Участник по ссылке может присылать `board-changed` часто] → каждое сообщение вызывает лишь повторный запрос доски
  у остальных и не больше одной проверки прав на документ одновременно.
- [Ссылка с режимом `edit` ушла не туда] → владелец закрывает доступ, и подключённые посторонние сразу его теряют;
  восстановление испорченного документа — задача истории версий.

## Migration Plan

1. Пара миграций V4/U4: колонка `link_access` со значением по умолчанию `EDIT`; U4 удаляет колонку.
2. Выкатить `backend`, затем `collab`, затем `frontend`. Старый `collab` не знает режимов и пускает всех на правку,
   как раньше; новый `collab` запрашивает режим у `backend`, где этот запрос уже есть. Старый фронтенд игнорирует
   новые поля.
3. Откат — U4 и предыдущие версии сервисов; все доски снова открываются по ссылке на правку.
