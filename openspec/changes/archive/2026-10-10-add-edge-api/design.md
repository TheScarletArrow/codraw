# Design

## Context

Ячейка доски в Yjs — поля модели и вложенная карта `style`; связка `DiagramBinding` переносит стиль по ключам, поэтому
ключ стиля сразу синхронизируется, отменяется одним шагом, отмечает, кто изменил элемент, сравнивается в версиях и
сливается в предложениях, копируется и дублируется вместе с ячейкой maxGraph. Так уже живут ссылка (`link`) и
закрепление. `drawio/style.ts` умеет не писать ключ в строку стиля и переносить его в атрибут обёртки ячейки
(`ATTRIBUTE_KEYS`), `serialize.ts` и `parse.ts` делают это для `link`. Панель стикеров — слой React над холстом,
который показывается по состоянию редактора у выделенного. Импорт OpenAPI (`apiSpec/`) уже читает операции в вид
«МЕТОД /путь».

## Goals / Non-Goals

**Goals:**

- Описание HTTP-вызова у связи, которое видно щелчком по связи, правится всеми, кто правит доску, и живёт вместе со
  связью во всех копиях, версиях и файлах.
- Структура данных, близкая к операции OpenAPI 3, чтобы будущий импорт и экспорт OpenAPI были переводом поле в поле.

**Non-Goals:**

- Схемы JSON Schema с проверкой: тело — свободный текст (пример или схема), подсвечивается как код.
- Другие протоколы (gRPC, Kafka, AMQP), несколько операций у одной связи, `$ref` между описаниями.
- Экспорт всей доски в один документ OpenAPI и создание связей из импорта OpenAPI — следующие изменения.
- Описание у фигур и таблиц; поиск по описаниям.

## Decisions

### Где хранится

- Ключ стиля `codrawApi` со строкой JSON `{"v":1,…}`; без описания ключа нет. Ключ стиля даёт синхронизацию, отмену,
  отметку «кто изменил», версии, предложения, копирование и офлайн без нового кода. `board/changes.ts` называет его
  изменение «описание API». Копирование стиля его не переносит: оно берёт только ключи оформления.
- Альтернатива — вложенная `Y.Map` ячейки рядом со стилем, чтобы одновременные правки разных полей описания сливались.
  Отклонена: модель maxGraph её не видит, команде пришлось бы писать в Yjs мимо модели, а копирование и дублирование
  теряли бы описание. Одновременная правка одного описания двумя людьми редка; последний «Сохранить» побеждает, как у
  подписи.
- Строка JSON, а не набор ключей стиля: списки параметров и ответов не ложатся в плоский стиль.

### Данные и проверка

- Чистый модуль `diagram/edgeApi.ts`: `EdgeApi { method, path, summary, description, parameters[], requestBody,
  responses[] }`, параметр `{ name, in: path|query|header|cookie, type, required, example, description }`, тело
  `{ contentType, body }`, ответ `{ status, description, contentType, body }` — имена полей OpenAPI 3.
- `parseEdgeApi(value)` читает недоверенное значение (документ может прийти от участника, который пишет в Yjs мимо
  интерфейса, или из файла): неверный JSON, чужая версия, неизвестный метод — `null`; лишние поля отбрасываются,
  строки обрезаются, списки ограничены (100 параметров, 50 ответов), текст тела — 20 000 символов. Значение больше
  64 КБ не читается. Панель показывает только разобранное значение и выводит его текстом React, без HTML.
- `apiLabel(api)` — «МЕТОД /путь»; `toOpenApi(api)` — `{ paths: { [path]: { [method]: operation } } }` с
  `parameters`, `requestBody.content[type].example` и `responses[status]`. Путь без `/` в начале получает его.

### Команда и состояние редактора

- `EditorState.edgeApi` — `{ cellId, api, canChange }` для единственной выделенной связи, иначе `null`; `api` — `null`,
  если описания нет или его не разобрать. `canChange` — правит доску и связь не закреплена.
- `setEdgeApi(api | null)` — одно изменение модели: ключ `codrawApi` и, если подпись связи пуста или равна
  `apiLabel` прежнего описания, подпись `apiLabel` нового. Удаление описания подпись не трогает. Закреплённая связь,
  не связь и режим просмотра (`CHANGING_COMMANDS`) не меняются.

### Интерфейс

- Пункт «Описание API…» в меню связи после «Ссылка…», неактивный у закреплённой, нет у читателя. Меню отдаёт запрос
  странице (`onEdgeApi`), страница передаёт панели связь, которую открыть в режиме правки.
- `edgeApi/EdgeApiPanel.tsx` — панель 400 пикселей у правого края холста высотой по содержимому, не выше холста, с прокруткой, как боковые
  панели Swagger UI. Она видна, пока выделена одна связь с описанием или связь, для которой попросили правку; смена
  выделения закрывает правку без сохранения. Просмотр: метод цветом Swagger UI (GET синий, POST зелёный, PUT
  оранжевый, PATCH бирюзовый, DELETE красный), путь моноширинным, описание, таблицы «Параметры» и «Заголовки», «Тело
  запроса» и «Ответы» с кодом цветом по классу (2xx, 3xx, 4xx, 5xx). Правка — форма с теми же разделами, строки
  добавляются и удаляются; «Сохранить» (и `Ctrl+Enter`) вызывает `setEdgeApi`, «Отмена» и `Escape` возвращают
  просмотр. Параметры пути из `{…}` в пути, которых нет в списке, форма добавляет кнопкой «Из пути».
- «Копировать как OpenAPI» пишет YAML `toOpenApi` в буфер обмена; библиотека `yaml` грузится при первом копировании.

### `.drawio` и буфер обмена

- `codrawApi` в `ATTRIBUTE_KEYS`: строка стиля его не несёт (в JSON есть `;` и `=`), экспорт пишет его атрибутом
  обёртки `<object>`, если описание разбирается, импорт и вставка читают атрибут `codrawApi` `<object>` и
  `<UserObject>` обратно в стиль, неразборчивое значение отбрасывается. В draw.io описание видно в «Edit Data».

## Risks / Trade-offs

- [Одновременное сохранение одного описания двумя участниками — побеждает последнее] → как у подписи; версия и отмена
  возвращают прежнее.
- [Панель закрывает правую часть холста] → она есть, только пока выделена связь с описанием, и закрывается кнопкой;
  щелчок по пустому холсту снимает выделение.
- [Подпись «МЕТОД /путь» на длинных путях широкая] → подпись можно переписать, тогда она больше не следует за
  описанием.
