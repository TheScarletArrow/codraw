# Proposal

## Why

Страницы CoDraw грузятся частями: редактор доски, предложение изменений, администрирование, справка, публичный
просмотр, автораскладка (ELK) и разбор YAML — отдельные файлы сборки с хешем в имени. nginx отдаёт их как
`immutable`, а новый образ содержит только файлы своей сборки. Вкладка, открытая до выкатки, при переходе на доску
запрашивает файл, которого больше нет, и показывает «Что-то пошло не так». О новой версии вкладка не узнаёт вовсе:
«Что нового» показывается только после перезагрузки, а старый код продолжает править общий документ Yjs. Это
пункт P0 списка готовности к MVP: открытые вкладки должны переживать выкатку.

## What Changes

- `frontend`: сборка публикует `version.json` — версию из `package.json` и идентификатор сборки; nginx отдаёт его с
  `no-cache`.
- `frontend`: открытая вкладка сверяет `version.json` со своей сборкой раз в пять минут, при возвращении на вкладку,
  при появлении связи и после неудачной загрузки части приложения. Если сборка другая — внизу экрана ненавязчивая
  плашка «Вышла новая версия CoDraw» с кнопками «Обновить» и «Позже», на всех страницах: список досок, редактор,
  `/view/:boardId` (и во встраивании), `/help`.
- `frontend`: страница, часть которой не загрузилась (ленивый маршрут), перезагружается сама один раз с тем же
  адресом; защита от цикла — отметка в `sessionStorage`. Если не помогло, нет связи или хранилище недоступно —
  экран «CoDraw обновился» с кнопкой «Обновить страницу» вместо общего «Что-то пошло не так».
- `frontend`: перед обновлением страницы по кнопке плашки редактор применяет незавершённую правку подписи и ждёт,
  пока правки уйдут на сервер или в локальную копию; если правки сохранить негде — плашка предупреждает и предлагает
  «Обновить всё равно».
- `frontend`: доска, документ которой записан более новой схемой, чем знает вкладка (`meta.schemaVersion`),
  открывается только для чтения с плашкой «обновите страницу» — защита на будущее несовместимое изменение формата.

## Capabilities

### New Capabilities

- `client-updates`: публикация версии сборки, плашка о новой версии, восстановление после неудачной загрузки части
  приложения, сохранность правок при обновлении и защита документа от старого клиента.

### Modified Capabilities

- `deployment`: файл версии сборки отдаётся без кеширования.

## Impact

- `frontend`: модуль `update/` (версия, проверка, перезагрузка с защитой от цикла, плашка, экран), плагин Vite
  `vite/versionFile.ts`, обёртка ленивых маршрутов в `routes.tsx`, `AppError` различает неудачную загрузку, редактор
  доски и предложения регистрирует несохранённые правки, `location = /version.json` в nginx, новинка «Что нового»,
  тема справки, версия 0.41.0.
- `collab` и `backend` не меняются: минимальная версия клиента на сервере для MVP не нужна (см. `design.md`).
- E2E: подмена `version.json` и 404 на файл сборки через `page.route`; стековая проверка заголовков `version.json`.
- Документация: раздел README, пункт 112 «Плана работ».
