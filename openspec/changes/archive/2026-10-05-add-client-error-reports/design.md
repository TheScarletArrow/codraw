# Design

## Context

`backend` пишет в продакшене журнал ECS средствами Spring Boot (`LOGGING_STRUCTURED_FORMAT_CONSOLE: ecs`), метрики
— через `CodrawMetrics` с именами `codraw.*`, пределы — в `LimitProperties` (`codraw.limits.*`), предел новых гостей
с адреса — окно в памяти (`NewGuestLimiter`) и ответ 429 с `Retry-After` и `ProblemDetail`. Адрес клиента —
`request.remoteAddr`: `X-Forwarded-For` доверенных прокси применяет Tomcat (`forward-headers-strategy: native`).
Всё под `/api` требует входа, кроме входа гостя; CSRF — cookie `XSRF-TOKEN` и заголовок `X-XSRF-TOKEN`, который
`frontend` отправляет из `api/http.ts`. Приложение — React 19 с `createBrowserRouter`, без `errorElement` и без
обработчиков ошибок. Требования — в `specs/`.

## Goals / Non-Goals

**Goals:**

- Видеть ошибки браузеров в том же журнале и в тех же метриках, что ошибки сервера, без стороннего сервиса.
- Отчёты не должны засорять журнал и не должны нести содержимое досок.

**Non-Goals:**

- Source maps и восстановление исходных строк стека: стек — из собранных файлов; версия образа видна в журнале
  по времени развёртывания.
- Хранение отчётов в базе, группировка и интерфейс просмотра — это работа сборщика журналов.
- Сбор действий пользователя перед ошибкой.

## Decisions

### Отчёт

- Поля: `kind` (`error`, `unhandledrejection` или `render`), `message` (до 1000 символов), `stack` (до 8000),
  `path` (путь страницы без query и hash, до 500). `frontend` обрезает поля до этих длин, `backend` отвергает длиннее
  ответом 400. Браузер — из заголовка `User-Agent`, пользователь — из сеанса, если он есть; в отчёте их нет.
- Содержимое досок не отправляется: только сообщение и стек ошибки. Путь страницы содержит идентификатор доски — он
  нужен, чтобы воспроизвести ошибку, и так же есть в журнале запросов.

### `backend`

- `ClientErrorController` — `POST /api/client-errors`, `permitAll` в цепочке приложения: ошибка бывает и на странице
  входа. CSRF не отключается: страница приложения всегда получает cookie, а чужой сайт не сможет слать отчёты от
  имени браузера пользователя.
- Предел — `AddressRateLimiter`: то же окно в памяти, что у предела гостей, но общее (окно и число заданы при
  создании); `ClientErrorLimiter` — его экземпляр на минуту с `codraw.limits.client-errors-per-address-per-minute`
  (по умолчанию 30). Ответ сверх предела — 429 с `Retry-After`, как у гостей. `NewGuestLimiter` не переносится на
  общий класс в этом изменении, чтобы не трогать работающий предел.
- Журнал — SLF4J с парами ключ-значение (`atWarn().addKeyValue(...)`), которые структурированный журнал Spring Boot
  кладёт в поля строки JSON: `client.error.kind`, `error.message`, `error.stack_trace`, `url.path`,
  `user_agent.original`, `user.id`. Уровень `WARN`: ошибка у одного участника не поломка сервера.
- Метрика — `codraw.client.errors` с тегом `kind`, все три зарегистрированы заранее; предел — новый `Limit.CLIENT_ERRORS`
  (`client-errors`) в `codraw.limits.reached`.

### `frontend`

- `errors/reporting.ts`: `reportError(kind, error)` нормализует `Error`, строку или что угодно в сообщение и стек,
  отбрасывает повтор (по виду, сообщению и первой строке стека) и всё сверх 10 за загрузку страницы и отправляет
  `fetch` с `keepalive` через общий клиент API, глотая его ошибки: отчёт об ошибке не должен порождать новых.
- Источники: `window` `error` (кроме ошибок с `filename` чужого источника — так падают расширения) и
  `unhandledrejection`; ошибки отрисовки — `onCaughtError` и `onUncaughtError` корня React 19, через которые проходят
  и ошибки, пойманные `errorElement` маршрутизатора.
- `errorElement` корневых маршрутов — `AppError`: «Что-то пошло не так» и «Обновить страницу». Без него
  маршрутизатор показывает свою отладочную страницу на английском.

### Оповещение

- `CodrawClientErrors`: `sum(increase(codraw_client_errors_total[10m])) > 20`, `severity: warning`. Порог — выше
  шума единичных сбоев у отдельных участников, ниже массовой поломки после выкладки.

## Risks / Trade-offs

- [Злоумышленник засоряет журнал отчётами] → предел 30 в минуту с адреса, поля ограничены по длине, CSRF.
- [Без входа отчёты анонимны] → так и задумано: ошибки страницы входа тоже нужны; пользователь пишется, если он вошёл.
- [Стек из собранных файлов неудобно читать] → имена функций в собранном коде частично сохраняются; source maps —
  отдельное изменение.
