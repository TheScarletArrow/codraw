## Context

Документ доски — состояние Yjs, которое collab сохраняет через внутренний API backend в `board_documents.state` (`Y.encodeStateAsUpdate`, формат обновления Yjs v1) с задержкой 2 с после последней правки (не позже 10 с). Backend считает состояние непрозрачным: хранит и отдаёт его как есть. Рядом лежит `search_text` — текст доски для поиска.

Изображения (ADR-0006, пакет `image`): строка `board_images` (id, board_id, sha256, тип, размер, ширина, высота) и объект хранилища S3 `boards/{board_id}/{id}`. Фигура хранит адрес `/api/boards/{boardId}/images/{imageId}` в `style.image` (значение `Y.Map`). Изображение отдаётся только тем, у кого есть роль на доске из адреса, и живёт, пока жива доска: окончательное удаление публикует `BoardDeleted`, `BoardImageService` удаляет строки и объекты, `ImageCleanup` добирает остальное.

Личные шаблоны переносят схему через `.drawio` с изображениями внутри и заново загружают их в новую доску из браузера. Этот путь теряет то, чего нет в `.drawio` (общие элементы с моделью, легенда, проверки, отметки статуса), и работает только в браузере.

Корзина: `BoardService.find` не видит доски в корзине, восстановление и создание сериализуются блокировкой владельца или пространства и проверяют предел досок.

## Goals / Non-Goals

**Goals:**
- Копия целиком на сервере, одним запросом API, без участия браузера: тот же документ байт в байт, кроме адресов изображений.
- Изображения копии принадлежат копии и переживают окончательное удаление оригинала.
- Права и пределы — те же, что у создания доски.

**Non-Goals:**
- Копирование комментариев, версий, предложений, решений, задач трекера, участников, живой картинки (см. «Что не копируется»).
- Копия с выбором страниц или копия «в чужое пространство» — для этого есть личные шаблоны и перенос доски.
- Снятие с копии отметок о том, кто менял элементы.

## Decisions

### 1. Копия собирается на сервере из сохранённого состояния, а не из `.drawio` в браузере

`POST /api/boards/{id}/copy` в одной транзакции создаёт доску, строки изображений и строку `board_documents` с состоянием оригинала; после транзакции копирует объекты изображений в хранилище. Ответ — 201 с доской копии, как у `POST /api/boards`.

Почему не путь шаблонов (выгрузка `.drawio` и `setPendingImport`): он теряет часть документа, перекладывает загрузку изображений на браузер (копия большой доски — десятки запросов), оставляет пустую доску, если вкладку закрыли до импорта, и не даёт копировать через API, о чём прямо просит issue.

### 2. Адреса изображений переписываются в байтах состояния подстановкой той же длины

В копии фигуры должны ссылаться на `/api/boards/{copyId}/images/{newImageId}`, иначе после удаления оригинала картинки пропадут. Backend не умеет разбирать Yjs, поэтому состояние переписывается как байты: каждое вхождение `/api/boards/{originalId}/images/{imageId}` известного изображения оригинала заменяется на `/api/boards/{copyId}/images/{newImageId}`. Оба адреса — ASCII одинаковой длины (UUID по 36 символов), поэтому:

- Yjs v1 хранит строки как длину в байтах UTF-8 (varuint) и сами байты; длины и все смещения после подстановки те же, контрольных сумм нет;
- `style.image` — атомарное значение `Y.Map` (`ContentAny`), адрес лежит в нём целиком и не делится между элементами;
- полный адрес с хостом (`https://…/api/boards/…`) тоже переписывается: подставляется только путь.

Подстановка идёт по регулярному выражению над строкой ISO-8859-1 (байт = символ), так что прочие байты не меняются. Адреса других досок и адреса, которых нет среди изображений оригинала, остаются как есть. Тест backend сверяет результат с состоянием, которое сам Yjs закодировал с новым адресом (одинаковый `clientID`), — байт в байт.

Рассмотренные альтернативы:
- переписать адреса в collab при первой загрузке копии (по таблице соответствий): публичный просмотр и живая картинка читают документ мимо collab, а копия, которую никто не открыл, жила бы со ссылками на оригинал;
- переписать адреса в браузере после копирования: снова нет копии через API и есть окно, когда копия ссылается на оригинал;
- порт Yjs для JVM (`y-crdt`/`yrs` через JNI): новая нативная зависимость в стеке ради одной операции, отдельный ADR и сборка под платформы — несоразмерно.

### 3. Изображения копируются строками с новыми id и объектами через S3 CopyObject

Для каждого изображения оригинала вставляется строка копии с тем же sha256, типом, размером и размерами в пикселях; id новый (`uuidv7()`), ключ объекта — `boards/{copyId}/{newId}`. Объекты копируются на стороне хранилища (`CopyObject`, без скачивания в backend), по одному, после транзакции — как `BoardImageService.store` кладёт объект после короткой транзакции со строкой. Пока объект копируется, запрос картинки получает 404 и не кэшируется.

- Хранилище не отвечает → копия удаляется (`BoardService.delete`, событие `BoardDeleted` убирает её строки и объекты), ответ 503.
- Объекта оригинала нет (хранилище его потеряло) → строка копии удаляется: и в оригинале, и в копии на месте картинки заглушка, копирование не падает из-за уже потерянного файла.
- Квота: сумма размеров изображений оригинала сравнивается с квотой доски внутри транзакции; при превышении (квоту уменьшили после загрузки) — 409 «Image quota reached», как при загрузке.

Миграция БД не нужна: схема `board_images` уже позволяет одинаковые sha256 на разных досках.

### 4. Копируется сохранённое состояние

Копия берёт то состояние, которое collab сохранил последним; правки последних 2–10 секунд в ней могут не оказаться. Попросить collab сохранить документ немедленно backend не может (collab ходит в backend, а не наоборот), а гонять состояние через браузер ради нескольких секунд — значит потерять решение 1. В интерфейсе это незаметно: копию делают не в ту же секунду, что правку; в README это упомянуто.

### 5. Копировать может любой с ролью на доске

Как в Google Docs: читатель и так может выгрузить `.drawio` или PNG и загрузить их новой доской, запрет только мешал бы. Проверка — `BoardService.participated`, как у открытия доски: 404 для неизвестной или удалённой доски, 403 при закрытом доступе. Гостям копирование тоже доступно: у гостя есть свои доски.

### 6. Место копии

- Доска пространства: копия в том же пространстве и проекте, если роль копирующего в пространстве позволяет создавать доски (`WorkspaceRole.createsBoards`); предел — досок пространства, доступ по ссылке `none`, доступ пространства по умолчанию, как у `WorkspaceBoardService.create`. Иначе копия — личная доска копирующего.
- Личная копия: доступ по ссылке как у новой доски, предел личных досок.
- Личная папка и теги, которые копирующий дал оригиналу, переносятся на копию (это его собственная организация, пределы тегов не растут: те же теги).
- Сериализация — блокировка пользователя или пространства, как при создании и восстановлении.

### 7. Что не копируется и почему

Участники, приглашения, запросы доступа, доступ по ссылке — принадлежат оригиналу и его владельцу. Комментарии, реакции, версии, предложения изменений — история обсуждения оригинала с авторами; копия — новая работа. Живая картинка — публичная ссылка, которую владелец включает сам. Задачи GitHub — копия, связанная с теми же задачами, путала бы трекер. Архитектурные решения не копируются: это записи о решениях, принятых по оригиналу, со статусом, автором и обсуждением; их связи с элементами копии были бы чужими. Кому нужно продолжить с решениями — продолжает в оригинале. Текст для поиска копируется, чтобы копия сразу находилась поиском.

### 8. Отметки «кто менял» остаются в документе

Документ хранит, кто менял элемент, кто написал стикер и кто поставил статус. Backend не меняет документ (решение 2), и копия «как есть» их сохраняет. Участники копии видят эти имена — новые получатели, поэтому политика конфиденциальности дополняется абзацем о копиях.

### 9. Название

«<название> (копия)»; если не помещается в 200 символов, укорачивается название оригинала, а не суффикс.

## Risks / Trade-offs

- [Будущий формат состояния (Yjs v2 или сжатие) сломает подстановку] → тест на настоящем состоянии Yjs; при смене формата хранения в collab тест и копирование придётся менять вместе, это упомянуто в комментарии к коду.
- [Строка, совпадающая с адресом изображения, но не являющаяся им (например, подпись с этим адресом)] → она тоже переписывается на адрес копии того же изображения; это безвредно и даже верно.
- [Копирование доски с сотней изображений — сотня запросов CopyObject] → копирование идёт на стороне хранилища без передачи байтов; квота доски ограничивает объём.
- [Ошибка хранилища посреди копирования] → копия удаляется целиком, пользователь получает 503 и повторяет.
- [Последние секунды правок не попадают в копию] → решение 4.

## Migration Plan

Миграции нет. Откат — откат кода; созданные копии остаются обычными досками.
