# Proposal

## Why

В многомодульном проекте на Kotlin или Java карта компонентов уже записана в сборке: `settings.gradle(.kts)`
перечисляет модули, а `dependencies { implementation(project(":core")) }` — связи между ними. Схему модулей рисуют руками
и обновляют реже, чем меняется сборка, поэтому она быстро врёт. CoDraw уже строит схемы по DDL, спецификациям API,
docker-compose и манифестам Kubernetes, но не по сборке Gradle (issue #89, эпик #81).

## What Changes

- В меню «SQL и Mermaid» появляется «Импорт Gradle…» (только у тех, кто правит доску) с двумя источниками:
  - **граф из скрипта** — точный: окно даёт скачать `codraw.gradle`, команда
    `./gradlew -q -I codraw.gradle codrawGraph > modules.json` печатает модули, их плагины и зависимости между ними так,
    как их видит сам Gradle; файл открывают или вставляют в поле;
  - **папка проекта** — быстрый, без запуска Gradle: «Открыть папку проекта…» читает `settings.gradle(.kts)` и
    `build.gradle(.kts)` модулей и разбирает типовые записи `include`, `project(":x")`, `projects.x` и `plugins`;
    чего не разобрать без Gradle, сводка называет пропущенным.
- Модуль становится «Компонентом» UML с подписью из пути модуля и технологий по плагинам (Kotlin, Spring Boot,
  Android, …); зависимость — связью от модуля к модулю, подписанной конфигурацией (`api`, `implementation`). Модули
  одной папки (`:services:billing`, `:services:orders`) — в рамке «Граница» с её путём. Схема раскладывается сверху вниз.
- Галочки «Тестовые зависимости» (выключена: `testImplementation` и подобные не рисуются) и «Фигуры C4» (Component C4
  с `[Component: технологии]`). Сводка «Модулей: N, связей: N, групп: N, пропущено: N».

## Capabilities

### New Capabilities

- `gradle-import`: схема модулей и зависимостей между ними доски из сборки Gradle.

### Modified Capabilities

- `sql-schema`: меню «SQL и Mermaid» предлагает «Импорт Gradle…», его фигуры не считаются таблицами.
- `diagram-editing`: элементы из импорта Gradle отмечены участником, который их добавил.

## Impact

- `frontend`: модуль `infra/` — скрипт `codraw.gradle`, разбор его графа и файлов сборки, граф модулей, окно импорта;
  направление раскладки в `infra/infraCells.ts`; пункт меню в `sql/SqlMenu.tsx`.
- `backend`, `collab` и документ доски не меняются: файлы разбираются в браузере и никуда не отправляются; скрипт
  только читает сборку.
- Вне объёма: внешние зависимости (Maven Central), Maven (`pom.xml`), включённые сборки (`includeBuild`) и `buildSrc`,
  каталоги версий, кроме имён плагинов в `alias(libs.plugins…)`.
