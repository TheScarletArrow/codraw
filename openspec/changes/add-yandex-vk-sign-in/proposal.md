## Why

Сейчас в CoDraw входят через GitHub, Google, корпоративный провайдер OpenID Connect или гостем. У российских
пользователей основные учётные записи — Яндекс ID и VK ID, а GitHub и Google у многих нет или вход через них работает
ненадёжно. Установке для российской аудитории нужен вход через эти сервисы, и подключать его оператор должен
настройками, как GitHub и Google, без кода.

## What Changes

- Вход через **Яндекс ID** (`yandex`): OAuth 2.0 приложения Яндекса, права `login:info` и `login:avatar` без почты,
  профиль `login.yandex.ru/info` с заголовком `Authorization: OAuth`. Имя — `real_name`, иначе `display_name` или логин,
  аватар — `avatars.yandex.net/get-yapic/<default_avatar_id>/islands-200`, если он есть. Включается переменными
  `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`.
- Вход через **VK ID** (`vk`): OAuth 2.1 на `id.vk.ru` с обязательным PKCE (S256) и без секрета приложения, право
  `vkid.personal_info`. Особенности VK ID: `state` только из букв, цифр, `_` и `-`; `device_id` из обратного вызова и
  `state` уходят в обмен кода; профиль — `POST /oauth2/user_info` с `client_id` и токеном, внутри `user`. Имя — имя и
  фамилия, аватар — `avatar`. Включается переменной `VK_CLIENT_ID`.
- Учётная запись связана с id пользователя у провайдера (`users.provider` = `yandex` или `vk`, миграции нет), гость при
  входе переносит доски, блокировка и удаление учётной записи работают, как для GitHub. Администраторов из этих
  провайдеров задают записи `yandex:<id>` и `vk:<user_id>` в `CODRAW_ADMINS`.
- Страница входа показывает «Войти через Яндекс ID» и «Войти через VK ID» по списку `GET /api/auth/providers`, только
  если задано приложение провайдера; в английском интерфейсе — «Yandex ID». id `yandex` и `vk` нельзя занять
  корпоративным провайдером.
- Подсказки гостю («… доступны после входа через GitHub или Google») и условия использования больше не называют
  конкретных провайдеров: в установке их может не быть.
- Политика конфиденциальности называет Яндекс ID и VK ID среди провайдеров входа и говорит, что вместе с профилем они
  присылают и другие сведения (пол, у VK ID и дату рождения), которые CoDraw не хранит; `/api/legal` отдаёт id
  провайдеров. Дата политики и условий — 13 октября 2026 г.
- README и `docs/deploy.md`: как зарегистрировать приложения в Яндекс OAuth и в кабинете VK ID и какие переменные
  задать; `docker-compose.prod.yml`, `.env.prod.example`; ADR-0015; справка, «Что нового» 0.48.0, «План работ».

## Capabilities

### New Capabilities

- `yandex-vk-sign-in`: вход через Яндекс ID и VK ID — включение приложением провайдера, обмен кода с особенностями VK
  ID, профиль и связь учётной записи, администраторы из этих провайдеров.

### Modified Capabilities

- `user-auth`: вход и способы входа установки включают Яндекс ID и VK ID; подсказки гостю не называют провайдеров.
- `legal-pages`: политика называет Яндекс ID и VK ID и что от них приходит, условия не называют конкретных провайдеров.
- `admin-moderation`: администраторы установки — и учётные записи `yandex:<id>` и `vk:<user_id>`.

## Impact

- `backend`: регистрации `yandex` и `vk` в `application.yaml`, свой `state` и параметры VK ID в обмене кода
  (`SecurityConfiguration`), загрузка профиля Яндекс ID и VK ID, `ProviderProfile`, список провайдеров,
  `AdminProperties`, зарезервированные id в `OidcProperties`, `id` провайдеров в `/api/legal`; тесты с поддельными
  серверами провайдеров. Новых библиотек и миграций нет.
- `frontend`: названия провайдеров по языку интерфейса, политика конфиденциальности и условия на двух языках,
  подсказки гостю, справка, «Что нового», тесты.
- e2e: страница входа и политика с Яндекс ID и VK ID.
- `docker-compose.prod.yml`, `.env.prod.example`, `docs/deploy.md`, `docs/running.md`, README, ADR-0015.
