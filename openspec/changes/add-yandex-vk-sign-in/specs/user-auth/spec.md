## ADDED Requirements

### Requirement: Подсказки гостю без названий провайдеров

Подсказки гостю о том, что функция доступна только вошедшему (подключение к базе, командные пространства, приглашение
в пространство, подключения, задачи GitHub, уведомления вне CoDraw), SHALL говорить «после входа» и MUST NOT называть
конкретных провайдеров входа: в установке может не быть ни GitHub, ни Google.

#### Scenario: Подсказка пространств

- **WHEN** гость открывает командные пространства
- **THEN** подсказка говорит, что они доступны после входа, и не называет GitHub или Google

## MODIFIED Requirements

### Requirement: Вход через внешнего провайдера

Система SHALL позволять войти через GitHub, Google, Яндекс ID, VK ID или корпоративного провайдера OpenID Connect,
включённых в установке, и после успешного входа возвращать пользователя в приложение уже аутентифицированным.

#### Scenario: Успешный вход через GitHub

- **WHEN** пользователь нажимает «Войти через GitHub» и подтверждает доступ у провайдера
- **THEN** он возвращается в приложение, и в шапке отображаются его имя и аватар

#### Scenario: Успешный вход через Яндекс ID

- **WHEN** пользователь нажимает «Войти через Яндекс ID» и подтверждает доступ у Яндекса
- **THEN** он возвращается в приложение, и в шапке отображаются его имя и аватар

#### Scenario: Отказ у провайдера

- **WHEN** пользователь отменяет вход на стороне провайдера
- **THEN** он возвращается на страницу входа с сообщением, что вход не выполнен

### Requirement: Способы входа установки

Страница входа SHALL показывать только способы входа, включённые в установке: GitHub, Google, Яндекс ID и VK ID —
если задано их приложение, корпоративных провайдеров — по их настройкам, «Продолжить без входа» — если гостевой вход
включён. Список SHALL отдавать `GET /api/auth/providers` без входа в порядке GitHub, Google, Яндекс ID, VK ID, затем
корпоративные провайдеры. Названия встроенных провайдеров SHALL показываться на языке интерфейса («Яндекс ID» и
«Yandex ID»). Без единого способа входа страница SHALL сообщать, что вход не настроен.

#### Scenario: Только корпоративный вход

- **WHEN** оператор задал только корпоративного провайдера и выключил гостевой вход
- **THEN** на странице входа одна кнопка «Войти через <название провайдера>», без GitHub, Google, Яндекс ID, VK ID и
  «Продолжить без входа»

#### Scenario: Только российские провайдеры

- **WHEN** оператор задал только приложения Яндекс ID и VK ID
- **THEN** на странице входа кнопки «Войти через Яндекс ID» (основная) и «Войти через VK ID», без GitHub и Google

#### Scenario: Английский интерфейс

- **WHEN** в установке включён Яндекс ID, а интерфейс на английском
- **THEN** кнопка называется «Sign in with Yandex ID»

#### Scenario: Список способов входа

- **WHEN** клиент без сеанса запрашивает `GET /api/auth/providers`
- **THEN** ответ имеет статус 200 и содержит включённых провайдеров с идентификаторами и названиями и признак
  гостевого входа

#### Scenario: Вход не настроен

- **WHEN** в установке нет ни одного провайдера, а гостевой вход выключен
- **THEN** страница входа сообщает «Вход не настроен. Обратитесь к администратору»
